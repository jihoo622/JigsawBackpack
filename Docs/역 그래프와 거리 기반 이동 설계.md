# 역 그래프와 거리 기반 이동 설계

## 현재 적용 범위

- 목적지 ID 기반의 직결 역 이동과 지도 노드 클릭 UI를 적용한다. 기존 출발→도착 노선 인덱스를 재사용하고 도시 정렬 순서에 따른 순환 이동을 제거한다.
- 농업마을(`city.b`)↔어촌마을(`city.f`) 양방향 철도를 추가한다. 기본 비용은 각 6이며 기존 적재 칸 요금을 더한다. 기존 `city.a`↔`city.c` 연결도 유지한다.
- 사용자 지시에 따라 모든 연결 이동 시간은 1턴이다. 원본은 `PuzzleRouteTableData.travelTurns: 1`이며 거리·속도·별도 경과 시간 계산은 도입하지 않는다.
- 화물 가치 변화와 시장 재설정은 기존 이동당 처리를 유지하고, 비활성 상태인 빚 차감은 복구하지 않는다.
- 아래 내용은 초기 분석과 후속 확장 제안이다. 거리 기반 비용·시간 및 시간 기반 경제는 현재 구현 사항이 아니다.

## 결론

- 역은 정점, 이동 가능한 선로는 간선인 가중 그래프가 적합하다. `TableManager`의 출발 역 → 도착 역 Dictionary를 재사용한다. 외부 그래프 패키지나 인접 행렬은 필요하지 않다.
- 첫 적용은 목적지 ID 기반의 인접 역 한 구간 이동으로 제한한다. 이 범위에서는 경로 탐색 알고리즘이 필요하지 않다.
- 거리로 요금과 게임 내 경과 시간을 계산한다. 실제 대기 시간과 이동 연출은 별도 선택이다.
- 그래프와 비용·시간 도입은 비교적 국소적인 변경이다. 화물 가치·빚·시장 재고까지 시간 기준으로 전환하면 경제 규칙 변경이 추가되므로 별도 단계로 나눈다.

## 그래프와 거리 원본

### 최소 변경안

기존 방향별 `routes` 행에 거리 필드를 추가하고, 현재 `(fromCityId, toCityId)` 키를 유지한다. 현재 역 ID는 배열 인덱스 대신 직접 보유하고, 노출 목록의 ID 정렬은 그대로 유지한다. 목록 정렬을 선로 연결로 해석하지 않는다.

이는 가장 적은 변경으로 분기 이동을 지원한다. 다만 같은 선로의 양방향 거리를 두 행에 저장하면 한쪽만 수정할 위험이 있다.

### 거리 단일 원본을 우선하는 안

같은 물리 선로를 양방향으로 이용한다면 `PuzzleRouteTableData` 안에 다음 두 종류의 행을 둔다.

- 구간: `id`, 양 끝 역 ID, `distanceUnits`. 물리 거리는 여기에서만 정의한다.
- 방향별 이동: `fromCityId`, `toCityId`, `segmentId`, 방향별 기본 요금. 기존 방향별 비용 차이를 보존할 수 있다.

구간 참조를 해석해 기존 출발→도착 인덱스를 만든다. 별도 로더나 새 전역 이동 상태를 만들지 않는다. 이동 견적 계산은 규칙 계층의 순수 계산 경로로 모으고 서비스가 현재 화물량·자금을 제공한다.

추천은 거리 편집의 단일 원본을 갖는 두 번째 안이다. 단, 양방향이 서로 다른 선로를 쓰는 설정까지 무조건 같은 거리로 강제하지 않는다. 노선의 방향성과 물리 거리 공유 여부는 서로 다른 결정이다. 같은 두 역 사이의 복수 선로는 현재 인덱스가 지원하지 않으므로 첫 범위에서 제외한다.

## 비용과 시간 계산 제안

거리는 화면 노드 좌표와 분리한 정수 단위로 저장한다. 거리 단위, 단가, 속도 또는 거리당 시간은 모두 테이블에 명시하고 누락을 유효한 0으로 취급하지 않는다.

비용 후보는 다음과 같다. `d`는 거리, `n`은 출발 직전 기차 점유 칸 수다.

| 안 | 식 | 의미 |
|---|---|---|
| 기존 구조 확장 | `기본 요금 + d × 거리 단가 + n × 적재 단가` | 현재 적재 요금을 유지하고 거리 요금 추가 |
| 거리·적재 연동 | `기본 요금 + d × (공차 단가 + n × 적재 거리 단가)` | 같은 화물도 멀리 운송하면 운송료 증가 |

거리 운송의 의미를 강조하려면 두 번째 식을 추천한다. 기존 `cost`의 비대칭 샘플값을 거리로 해석하거나 새 단가와 조용히 중복 적용하지 않는다. 기본 요금으로 남길지 교체할지 명시적으로 정한다.

시간은 `거리 × 거리당 시간` 또는 `거리 / 속도`로 계산한다. 속도 업그레이드가 필요하지 않으면 거리당 시간 계수가 단순하다. 적재량에 의한 감속은 사용자 요구에 포함되지 않았으므로 첫 적용에 추가하지 않는다.

- 게임 내 시간은 정수 분 또는 더 작은 정수 단위로 누적한다. 화면 표시만 시간·일 단위로 변환한다.
- 나눗셈이 필요하면 올림·내림과 적용 시점을 명시한다. 구간마다 올림하면 경유가 직행보다 오래 걸릴 수 있으며 이것이 의도인지 구분한다.
- 비용과 시간의 곱셈·합산은 오버플로를 검사한다. `long` 금액을 `float`나 `Mathf.CeilToInt`로 변환하지 않는다.
- 화물의 `decimal` 값도 정밀도와 범위에 한계가 있으므로 무손실·무한 누적을 보장한다고 표현하지 않는다.
- 견적과 출발 확정은 같은 계산 경로를 사용하고 확정 직전에 화물량·자금을 다시 확인한다.

## 시간과 경제 효과의 범위

### 1차 적용: 이동 비용과 경과 시간

지도에서 연결 역을 선택하고 비용·거리·시간을 확인한 뒤 한 구간을 즉시 이동한다. 게임 내 경과 시간은 증가하되, 화물 가치의 이동당 한 번 누적과 출발 시장 재설정은 우선 기존 규칙을 유지할 수 있다. 이 경우 시간은 아직 경제 정산의 공통 기준이 아니라는 점을 문서와 화면에서 명확히 한다. 비활성화된 빚을 이 작업에서 자동으로 복구하지 않는다.

### 2차 적용: 시간 기반 경제

- **화물 가치:** 기존 한 턴 변화량을 기준 시간당 변화율로 해석하려면 기준 시간을 테이블로 정의한다. 배치와 변화율이 같은 동안에는 `변화율 × 경과 시간 / 기준 시간`을 누적하고 매 구간마다 금액을 정수화하지 않는다. 중간 역에서 거래·재배치한 경우는 조건 자체가 달라지므로 같은 결과를 보장할 대상이 아니다.
- **빚:** 이동 횟수 일정과 시간 기한은 다른 규칙이다. 시간 기준으로 바꾼다면 `기한 <= 도착 시간`인 미처리 항목을 기한 순서대로 정산한다. 한 이동에서 여러 기한을 넘을 수 있으므로 한 번의 동일값 비교로 처리하지 않는다. 부족하면 출발 차단인지, 도착 후 패배인지, 이동 중 정차인지 별도 결정한다.
- **재고:** 현재 출발 시 재추첨을 유지하면 짧은 왕복으로 자주 재추첨할 수 있다. 시간 기반 재입고를 택한다면 도시별 재고와 다음 갱신 시점을 씬 로컬 상태로 유지하고, 기한 전 재방문에서는 구매·판매 후의 재고를 그대로 보여주는 안이 단순하다. 시간 전환만으로 모든 왕복 수익 문제가 사라지는 것은 아니다.

같은 시간의 처리를 나눠도 가치 정산이 일관돼야 한다는 요구는 모든 노선에 삼각부등식이나 직행 거리=경유 거리 합을 강제하라는 의미가 아니다. 실제 선로는 우회할 수 있다. 경로 탐색이 필요해질 때도 비음수 가중치와 결정적인 동점 처리로 설계할 수 있다.

`TelemetryLog.GameTime`은 기존 분석 세션 시계로 유지한다. 이동으로 증가하는 세계 시간은 씬 로컬 도메인 상태로 별도 소유하며 `Time.time`을 기준으로 만들지 않는다. 이벤트에는 기존 분석 타임스탬프와 별도의 경과 시간 필드를 구분해 전달한다.

## 실행과 UI 연결

- 지도 노드 선택 → 거리·비용·시간 견적 → 출발로 연결한다. 미방문 인접 역도 탐험 대상으로 허용하는 안을 추천한다. 교역 정보 공개 여부는 이동 가능 여부와 분리한다.
- 현재 역·알 수 없는 역·직접 연결 없는 역·자금 부족·산술 오류는 확정 전에 차단한다. 실패 시 비용·시간·화물·시장·방문 기록을 바꾸지 않는다.
- 현재 성공 경로는 순차 변경이며 예외까지 포함하는 완전한 트랜잭션은 아니다. 변경을 강화한다면 견적·화물 변화량·새 시장을 먼저 준비하고 성공 후 상태를 반영한다. 새 시장 준비가 난수·ID를 소비한다면 그 보존 범위도 정해야 한다.
- 도착 이벤트는 모든 상태 정산이 끝난 뒤 발행한다. 빚을 다시 활성화할 경우에도 최종 자금·게임 상태를 구독자가 보게 한다.
- 인벤토리 Presenter도 도착 이벤트를 대칭 구독해 지도 이동 시 보드·자금·가치를 갱신한다. 자체 이동 성공 후 직접 갱신과 이벤트 갱신을 중복 실행하지 않도록 경로를 정리한다.
- 견적은 선택 당시 수치일 뿐이다. 거래로 적재량이 바뀌면 견적을 갱신하고, 출발 시 다시 평가한다. 드래그와 Ctrl+클릭도 동일한 모델 변경 경로를 사용한다.
- 지도 열림 시 드래그 취소에 더해 배경 보드 입력 차단도 유지한다. 새 입력은 Input System 자산에 정의하고 노드·견적·출발 버튼은 프리팹에 미리 배치한다.
- 노드와 선에는 도시·구간 ID를 연결해 테이블과 프리팹의 누락·중복·불일치를 검증한다. 기존 이전·다음 버튼은 임의 분기를 표현할 수 없으므로 첫 적용에서는 지도 이동으로 통합하는 안을 추천한다.

## 적용 순서와 남은 결정

1. 이동 시간의 의미를 결정한다. 추천은 실제 대기 없이 게임 내 시간이 경과하는 방식이다. 실제 대기를 택하면 이동 중 상태·입력·일시정지·취소 정책이 추가된다.
2. 인접 역 이동 범위와 `city.a ↔ city.c` 존치 여부를 정한다. 다중 구간 자동 이동은 경유 거래·정차 규칙이 정해진 뒤 추가한다.
3. 거리 원본·단위·비용식·시간 계수를 확정하고 기존 JSON·DTO·인덱스·검증을 함께 변경한다. 거리와 단가의 실제 밸런스 값은 아직 정하지 않았다.
4. 목적지 ID 평가·확정 경로와 씬 로컬 경과 시간을 구현하고, 지도·인벤토리 Presenter·프리팹을 연결한다.
5. 이동 이벤트를 기록하려면 `TelemetryEvents`·`TelemetryPayload`·`TelemetryRecorder`·`PLAY_LOG.md`를 함께 갱신한다. 이동 이벤트 기록을 필수 구현으로 확정한 상태는 아니다.
6. 화물·빚·재고의 시간 전환은 별도 경제 변경으로 결정한다. 관련 문서의 빚 활성 여부와 시장 고정 배치 설명도 실제 구현에 맞춰 정리한다.

전체 역 도달 가능성을 필수로 할지, 잠긴 구간·고립된 역을 허용할지에 따라 연결성 검증을 정한다. 그래프의 순환은 정상이며 금지할 이유가 없다. 일방통행과 복수 선로는 명시적으로 필요한 경우에만 확장한다.

## 분석 자료

`.orca/reports`의 그래프·경제·UI 개별 보고서를 검토해 통합했다. 개별 보고서에 있는 수식, 무향 그래프 채택, 빚 재활성화, 시간 기반 재고 변경은 확정 사항이 아니다. 원본 보고서의 완전 원자성·무손실 decimal·거리 삼각부등식에 관한 과도한 표현은 위 통합안의 설명을 따른다.
