# 화물 태그 인접 효과 구현 계획

## 목표와 적용 기준

- `Cargo`(화물) 태그가 있는 품목이 같은 보드에서 상하좌우로 인접한 다른 `Cargo` 품목에게 가치 시너지 +20%를 준다. 두 품목 모두 화물이라면 서로에게 적용한다.
- 기존 시너지 계약을 따른다. 맞닿은 면마다 합산하고 대상의 **기본 가치**를 기준으로 정산 주기마다 실제 가치에 변화량을 누적한다. 다른 시너지·역시너지와 합산하며 숙련 보강도 기존 규칙과 동일하게 적용한다. 예: 숙련 보강이 없고 기본 가치가 100인 대상은 한 면 접촉 시 정산마다 20, 두 면이면 40이 증가한다.
- 서로 다른 품목 사이에만 적용한다. 대각선, 떨어진 품목, 다른 객차는 인접하지 않는다. 기존 폐기물 대상 면역을 유지한다. 시장은 기존 시너지와 같이 계산·표시 범위에 포함하되 시간 정산은 기차에서만 한다.
- 위 해석은 기존 인접 시너지의 면별·정산·숙련 규칙을 따른 계획이다. 요청한 +20%를 접촉 품목당 한 번의 고정 보너스 또는 즉시 판매가 배율로 의도했다면 구현 전에 이 기준을 바꿔야 한다.

## 현재 구조와 주의점

- `Assets/Resources/Tables/PuzzleSynergyTableData.json`의 `sample.cargoNearFood`는 **Food 발생원 → Cargo 대상** 규칙이다. 새 화물 간 규칙과 별개이므로 덮어쓰거나 재사용하지 않는다.
- 태그가 일치하는 것만으로는 효과가 적용되지 않는다. `PuzzlePieceEffects`는 각 품목의 `synergyEffects`에서 해당 규칙의 대상과 발생원 역할도 확인한다.
- `PuzzleInventoryValuation.Recalculate`는 현재 인접 규칙을 수집하고 `PuzzleInventoryPresenter`도 드래그 미리보기를 호출한다. 반면 루트 README와 `Docs/인접 가치 시너지 비활성화 계획.md`는 인접 가치 효과가 꺼져 있다고 설명한다. 구현 시 실제 동작과 문서의 차이를 확인해 현재 상태에 맞게 관련 설명을 정리한다. 새 규칙을 위해 다른 기존 규칙을 일괄 활성화하거나 비활성화하지 않는다.

## 구현 순서

1. `PuzzleSynergyTableData.json`에 고유 ID `cargoNearCargo`인 규칙을 추가한다. `targetTag`와 `neighborTag`는 모두 `Cargo`, `spatialRange`는 `Adjacent`, `scope`는 기존 화물 인접 규칙과 같은 `Both`, `multiplierPercent`는 `120`으로 둔다. 대상·발생원 설명도 화물 간 +20%로 작성하고 수치를 코드에 중복하지 않는다.
2. `Assets/Resources/Tables/PuzzleTableData.json`의 모든 `Cargo` 태그 품목에 `synergyEffects` 항목 `{ "ruleId": "cargoNearCargo", "target": true, "source": true }`를 추가한다. 다른 태그 품목과 기존 역할은 바꾸지 않는다. 이후 새 화물 품목에도 양쪽 역할을 선택해야 한다는 점을 품목 편집 흐름에서 확인한다.
3. 기존 `PuzzleInventoryValuation`의 양방향·면별 계산과 `PuzzleInventory`의 시간 정산을 그대로 사용한다. `PuzzlePieceEffects`, 테이블 검증 및 아이템 편집기(`Assets/Scripts/Editor/Tables/`)가 같은 태그의 대상·발생원 규칙을 정상 처리하는지 살피고, 필요한 경우에만 기존 공통 경로를 수정한다. 누적된 과거 가치를 다시 계산하지 않는다.
4. 기존 `Presentation`, 품목 툴팁, `PuzzleSynergyChart` 및 `Assets/Art/PuzzleSynergyChart.prefab`의 행·열 용량, 배치 화살표와 드래그 미리보기가 새 규칙을 일관되게 표시하도록 연결한다. 품목별 역할과 실제 계산을 기준으로 하고 UI 문구·색은 기존 단일 출처를 사용한다. 용량이 부족할 때만 프리팹에 사전 배치 칸을 추가한다.
5. `Docs/게임 기획서.md`의 관련 태그 규칙과 루트 `README.md`의 현재 구현 설명을 짧게 갱신한다. 기존 인접 효과가 꺼져 있다는 기록과 실제 구현이 다르면 확인한 상태를 명시한다.

## 완료 기준

- Cargo 품목 두 개가 한 면 인접하면 양쪽이 각각 기본 가치의 20%를 정산마다 얻고, 여러 면·여러 이웃은 기존 합연산 규칙을 따른다.
- Cargo가 아닌 품목, 대각선, 서로 다른 객차, 자기 자신의 칸에는 이 새 규칙이 적용되지 않는다. 폐기물 면역과 다른 시너지·숙련·신선도 규칙은 유지된다.
- 품목 설명과 상성표, 접촉 표시와 드래그 미리보기는 실제 규칙과 일치한다. 시장에서는 시간 정산으로 가치가 누적되지 않는다.
- 테이블의 ID 참조와 품목별 양쪽 역할이 빠짐없이 연결된다. 테스트·플레이 실행 및 검증 실험은 프로젝트 지침에 따라 사용자가 요청한 경우에만 수행한다.
