# 아이템 가격과 도시별 태그 배율 분리 작업 계획

## 목표와 현재 구조

아이템 가격은 전용 테이블에서 아이템 ID별로 관리한다. 도시는 자신에게 적용되는 태그별 구매·판매 배율을 설정한다. 거래 가격은 아이템의 가격과 현재 도시에서 일치하는 태그 배율을 조합해 계산한다. 이 문서는 구현 계획이며 완료 기록이 아니다.

현재 기본 가치는 `PuzzleTableData.json`의 각 아이템 `baseValue`에 있고, 도시별 기본·태그 배율과 거래 허용 여부는 `PuzzleTradeTableData.json`의 `cityPrices`에 있다. `PuzzleInventoryService.EvaluateDrop`은 구매·판매 가격을 계산하고 `Drop`은 놓는 순간 다시 판정한다. 이 구조를 별도의 아이템 가격 테이블과 도시 데이터의 태그 배율로 분리한다.

## 공통 계약

- 아이템 종류·모양·태그는 `PuzzleTableData.pieces`의 ID로 식별하고, 가격은 `PuzzleItemPriceTableData.json`에서 같은 아이템 ID로 조회한다. 가격은 한 곳에서만 보관하고 아이템 정의·UI·씬에 사본을 두지 않는다.
- 도시별 태그 배율과 기본 배율은 `PuzzleTableData.cities`의 해당 도시에 둔다. 현재 도시 ID와 아이템의 태그를 사용해 배율을 선택하며 도시·태그 배열 순서는 의미가 없다. 시작 자금은 기존 거래 테이블을 원본으로 유지한다.
- 현재 동작을 기준으로, 태그 규칙에는 구매·판매 배율과 `priority`를 각각 둔다. 여러 태그가 일치하면 가장 높은 `priority`의 한 규칙을 사용하고, 일치하는 규칙이 없으면 도시 테이블의 명시적인 기본 배율을 사용한다. 기본값과 샘플 배율은 데이터에 명시하며 코드에 폴백을 두지 않는다.
- 구매는 아이템 가격 테이블의 기본 가치, 판매는 기존 기차 내 시너지 반영 최종 가치를 기준으로 한다. 최종 가치 계산도 같은 가격 테이블의 기본 가치를 사용한다. 턴별 실제 가치와 거래가의 연동 여부는 기존 계획의 후속 결정으로 둔다.
- `AGENTS.md`의 JSON → 직렬화 DTO → `TableManager` → `GameTableRules` 경로를 따른다. 게임 상태는 씬 로컬 모델이 소유하고, 표기 문구·색은 `Presentation`에서 관리한다.
- 각 단계의 완료 기준은 구현 요구사항이다. 테스트·플레이·검증용 입력이나 캡처·원인 조사 실험은 사용자가 별도로 요청할 때만 수행한다.

## 1단계. 아이템 가격 테이블 분리

**대상** `Assets/Resources/Tables/PuzzleItemPriceTableData.json`, `PuzzleTableData.json`, `GameTables.cs`, `GameTableRecords.cs`, `TableManager.cs`, `GameTableRules.cs`.

1. `PuzzleItemPriceTableData.json`에 `status`, `note`와 아이템 가격 목록을 정의한다. 각 항목은 `pieceId`와 기존 `baseValue`를 가진다. 누락된 금액이 유효한 0으로 위장되지 않도록 DTO에 검증용 누락 표시를 둔다.
2. 기존 아이템별 `baseValue`를 동일한 ID와 값으로 새 테이블에 이전한다. `PuzzleTableData.pieces`의 중복 가격 필드는 제거한다. 상품 종류나 기존 샘플 가격을 임의로 변경하지 않는다.
3. `TableManager`의 공통 `Load<T>(ref loaded)` 경로에 새 테이블을 연결하고 아이템 ID 인덱스를 만든다. 알 수 없는 ID에 코드 기본값을 반환하지 않는다.
4. 가격 ID의 누락·중복·빈 값·미등록 아이템 참조와 금액 범위를 항목별로 보고한다. 모든 아이템에 가격이 정확히 하나씩 있어야 하며 가격만 있고 정의가 없는 항목도 오류다. `IsValid`와 `RequireValid()`를 사용한다.
5. `PuzzleItemDefinition`, 시작 화물 가치와 `PuzzleInventoryValuation`이 새 테이블에서 조회한 기본 가치를 사용하게 연결한다. 각 인스턴스의 실제 가치, 시너지 변화량 및 기존 아이템 ID를 보존한다.

**완료 기준** 아이템 기본 가격의 유일한 원본이 별도 가격 테이블이고, 기존 샘플은 ID별로 이전과 같은 값을 사용한다. 가격 누락이나 중복은 초기화를 차단한다.

## 2단계. 도시의 태그 배율 설정

**대상** `PuzzleTableData.json`, `PuzzleTradeTableData.json`, `PuzzleCityData`, 도시·태그 가격 DTO, `TableManager.cs`, `GameTableRules.cs`.

1. 각 도시 항목에 구매·판매 허용 여부, 명시적 기본 구매·판매 배율, 태그별 배율 목록을 둔다. 각 태그 규칙은 `tag`, `priority`, `buyPercent`, `sellPercent`를 가진다.
2. 기존 `PuzzleTradeTableData.cityPrices`의 도시별 허용 여부·기본 배율·모든 태그 규칙을 같은 도시 ID의 설정으로 이전한다. 기존 태그·우선순위·비율을 바꾸지 않아 이전 전후 가격이 같도록 한다. `startingFunds`는 거래 테이블에 남긴다.
3. 도시 ID 및 필수 설정의 누락, 태그 공백·미등록·도시 내 중복, 우선순위 누락·중복, 기본·태그 배율 누락과 범위를 검증한다. 태그 비교는 현재 아이템 정의와 같은 대소문자 규칙을 따른다.
4. `TableManager.CityPrice`와 `TryGetCityTagPrice`의 기존 사용처를 새 도시 설정과 그 인덱스로 연결한다. 중복된 도시 가격 목록과 사용하지 않는 DTO·인덱스는 사용처를 확인하고 정리한다.

**완료 기준** 도시마다 자체 태그 배율을 설정하고 조회할 수 있으며, 거래 테이블과 도시 데이터가 같은 배율을 중복 저장하지 않는다.

## 3단계. 거래 가격과 UI 연결

**대상** `PuzzleInventoryService.cs`, `PuzzleItemDefinition.cs`, `PuzzleInventoryValuation.cs`, 관련 View·Presenter 및 `Presentation.cs`.

1. 구매·판매에 사용할 아이템 가치와 도시의 선택된 배율을 결합하는 기존 단일 가격 계산 경로를 새 데이터 원본에 연결한다. 일치 태그, 복수 태그의 우선순위, 기본 배율과 거래 허용 여부는 공통 계약대로 처리한다.
2. 기존 반올림, 오버플로·자금 부족·허용 여부 판정을 유지한다. 미리보기와 실제 `Drop`은 같은 `EvaluateDrop` 경로를 사용하고, 확정 시 현재 도시·원본 인스턴스·대상 점유·가격·자금을 다시 확인한다. 실패 시 아이템과 자금은 함께 보존한다.
3. 아이템 상세, 거래 미리보기와 확정 결과가 새 가격 테이블의 아이템 가치 및 도시에서 선택한 태그·배율을 표시하도록 연결한다. 같은 인스턴스의 이동, 회전, 도시 전환과 누적 실제 가치를 보존한다.
4. 거래 이벤트와 분석에 기록되는 도시·아이템·가격이 실제 확정 결과와 일치하도록 기존 `GameEvents`·`TelemetryPayload` 경로를 사용한다. 필드 변경이 필요하면 서버 측 이름과 `Docs/PLAY_LOG.md`, `Docs/TELEMETRY.md`를 함께 갱신한다.

**완료 기준** 아이템 가격은 별도 테이블에서, 배율은 현재 도시 설정에서 읽는다. 기존 데이터로 계산한 구매·판매 가격과 미리보기·확정 결과가 같은 규칙을 따른다.

## 4단계. 문서 정리와 사용자 확인

1. `README.md`, `Docs/TABLES.md`, `Docs/기차-인벤토리-관리-게임-기획서.md` 및 `Docs/도시 이동 턴과 승패 흐름 구현 계획.md`의 가격 원본·도시 배율·거래가 설명을 실제 구현에 맞게 갱신한다.
2. 기존 두 테이블의 이전 전 항목과 이전 후 ID별 가격·도시별 태그 설정이 대응하도록 한다. 실제 항목이 누락되거나 값이 충돌하는 경우 임의의 기본값을 주지 않고 오류로 보고한다.
3. 사용자가 확인을 요청하면 아이템 가격 변경, 한 태그가 여러 도시에 적용되는 경우, 복수 태그 우선순위, 규칙 없는 태그, 자금 부족·이동 실패 및 도시 전환 뒤 거래를 확인한다. 수행하지 않은 확인은 완료로 기록하지 않는다.

**완료 기준** 아이템 가격과 도시별 배율의 데이터 소유권, 거래 경로 및 문서가 일치한다.
