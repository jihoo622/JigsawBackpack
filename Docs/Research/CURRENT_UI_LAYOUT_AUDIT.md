# 현 UI 레이아웃 감사 — R0

> 조사일: 2026-11-18 · 기준 커밋: `fe7c6d5`  
> 범위: 저장소 정적 조사, PC 1920×1080 배치 계약  
> **Unity 실행·컴파일·플레이·입력 실험·스크린샷 촬영은 하지 않았다.** 아래 ‘확인’은 소스/직렬화 값 확인이며 실제 화면·사용성 검증 완료를 뜻하지 않는다.

## 1. 요약과 근거 수준

현재 화면은 왼쪽 기차 5×5, 오른쪽 시장 7×6와 시장 정보 열, 상단 HUD/상태 안내, 하단 화차 선택 바다. 두 보드의 셀 크기와 세로 중심을 맞춘 구조는 유지 가치가 있다. 반면 거래를 결정하는 아이템 상세는 호버 툴팁에 집중되어 **화물을 잡으면 사라지고**, 시장 정보 열은 선택 아이템의 거래·배치 결과가 아니라 도시의 일반 교역 규칙을 표시한다.

가장 큰 격차는 ‘보드가 두 개라서’가 아니라 **드롭 직전의 공간 적합성·지금 가격·시너지 증감·알고 있는 타 도시 기회·운임을 같은 문맥에서 보지 못하는 것**이다. 다만 이것이 실제 오판·시간 증가로 이어지는지는 플레이 검증 전 가설이다. 이 문서는 레이아웃 권고안을 확정하지 않고 R4/R5의 입력을 제공한다.

### 근거 표기

- **S**: 소스·프리팹·테이블에서 확인한 사실.
- **D**: 문서에만 있는 설명/좌표 계약. 실제 렌더링 측정치가 아니다.
- **H**: 사용성 마찰 가설. 플레이로 검증해야 한다.
- **U**: 실행 없이는 확인할 수 없는 사항.

### 조사 입력과 우선순위

[조사 계획](GRID_INVENTORY_LAYOUT_RESEARCH_PLAN.md) §2·5·7 → [UI_LAYOUT](../Management/UI_LAYOUT.md) → [UI_DESIGN_HANDOFF](../Management/UI_DESIGN_HANDOFF.md) → [README](../../README.md)를 읽고 해당 프리팹/스크립트/테이블과 대조했다. 문서 간 충돌이 있어 [CURRENT_STATE](../Management/CURRENT_STATE.md)의 최신 피벗 설명도 보조 확인했다. **현행 동작 판단은 실제 소스·테이블·중첩 프리팹 값을 우선**하며, 과거 문서를 그대로 현행이라고 쓰지 않는다.

## 4. 입력·드래그·툴팁·Z-order

### 정적 코드에서 확인한 흐름

1. 호버: 아이템 placement에서 실제 가치/도시 배율/서비스 견적을 읽어 툴팁 표시. 기차 문맥은 판매, 시장은 구매 금액이다(`Presenter:1208`, `TooltipView:209`).
2. 좌클릭 누름: 즉시 `PuzzleInventoryDrag` 생성, 원자리 외곽선, 포인터 캡처, 툴팁 닫기. 드래그 임계값을 사용하지 않는다(`Presenter:590`, `Input.OnInitializePotentialDrag`). 클릭 고정 선택/핀 상세와는 다르다.
3. 드래그/회전: `EvaluateDrop`으로 공간+경제 유효성을 얻고 후보 보드 한 곳에 고스트와 유효/무효 표시, 원자리→후보 광선, 조건부 이웃 시너지 칩, 상단 상태 줄 견적을 갱신한다(`Presenter:881`). 보드 밖이면 커서 고스트를 쓰며 상태 줄은 비운다.
4. 놓기: 보드 또는 화차 슬롯 대상에서 즉시 확정. 별도 구매 확인 모달/스테이징 단계는 이 경로에 없다. 성공하면 보드·가치·자금·화차 바 갱신, 실패/취소는 원본 보존 후 드래그 표시 제거(`Presenter:691`, `Service.ApplyDrop`).
5. Ctrl+좌클릭: 시장/열린 작업대↔현재 화차로 즉시 빠른 이동. 현재 회전부터 4방향·위에서 아래/왼쪽부터 가능한 첫 위치를 찾는다(`Service:2043`). 최적 시너지 위치를 고르는 알고리즘이 아니다.
6. 다른 화차: 슬롯 드롭은 자동 배치, 드래그 중 화차 호버 전환은 `wagonDragHoverDelay=0.5` 기본값을 갖는다. 다른 화차 공간을 동시에 펼쳐 보여주는 방식이 아니다.

### 표시 수준과 한계

- 드래그 중 툴팁은 숨긴다. 거래 견적은 상단 상태 줄로 옮겨가지만 상세 가치·효과·기한을 그대로 유지하는 별도 가시 패널은 위 조사 범위에서 확인되지 않았다(S).
- `CalculateAdjacentSynergyDeltas`는 **후보 보드 이웃이 받는 인접 배율 변화**를 계산한다. 같은 보드 이동이면 원자리 이웃도 비교하지만 보드 간 이동에서는 출발 보드 칩을 숨긴다. ‘화물 자신+출발 이웃+도착 이웃의 정산 후 총가치 변화’ 계약은 아니다(S).
- `ShowAdjacentSynergyPreview`는 `+n%`/`−n%` 텍스트와 색을 병용한다. 칩 풀 용량 이후는 그리지 않는다. 초과 개수나 모든 영향 대상이 전달되는지는 U.
- 거래 보드간 이동의 잔액 부족/영업 종료/막힌 칸/겹침 사유는 `Presentation.PuzzleTradeStatus`에 있다. **같은 화차 재배치 등 Direction=None이면 대부분 빈 문자열을 반환**하므로 잘못 놓기 사유가 항상 문장으로 나온다고 볼 수 없다(S).
- Ctrl 이동은 미리보기 없이 확정된다. 빠르지만 의도와 다른 시너지 배치를 만드는지 검증 필요(H).
- 구매 취소(`PurchaseCancel`, 같은 방문 구매 화물 반납)는 서비스에 존재한다. 일반적인 모든 거래·배치·시간 진행을 되돌리는 Undo와는 구분해야 한다.

### 레이어 및 입력 회귀 경계

문서 계약은 본문 0 → 지도 100 → 이동 확인/연출 200 → 수첩 210 → 상성표 220 → 지도 미리보기 230 → 고정 HUD 250 → 고스트 260 → 화차 고스트 265 → 화물 툴팁 270 → 링크 미리보기 272 → 메뉴 280 → 일시정지 300이다. 툴팁 원본 270은 직렬화 확인했고 나머지 전체 캔버스의 실효 레이어/레이캐스트는 실행 검증하지 않았다.

- 표시 전용 툴팁/고스트가 입력을 가로채지 않는 계약을 유지해야 한다.
- Esc/우클릭은 단일 Presenter가 모두 처리하는 것이 아니라 지도·수첩·일시정지 등과 우선순위를 공유한다. 개편 시 검색 포커스 → 이동 확인 → 드래그 취소 → 상성표/지도/수첩 → 역 복귀 → 일시정지 순서를 회귀 대상으로 삼는다.
- 우클릭은 잡은 화물이 있으면 회전, 아니면 한 단계 닫기다. 입력 모드 추가 시 회전과 팝업 닫기 동시 실행을 막아야 한다.
- 지도 열림 중 기차 조작은 가능하지만 시장 조작/빠른 거래는 차단한다(`MarketOperationsBlocked`). 이동 연출/확인 상태는 기차까지 차단한다.

## 5. 핵심 과제 5개 격차 지도

‘필요 조작’은 코드 경로의 최소 질적 설명이며 사용자 관찰로 잰 클릭 수가 아니다. 의뢰 실패·성장/번식·냉장 같은 부수 규칙은 판단 정보로만 포함한다.

| 조사 계획 §7 과제 | 현재 가능한 경로/노출 | 마찰 가설 및 부족 정보 | 검증할 관찰 |
|---|---|---|---|
| **구매**: 2×3 선택→공간/시너지 확인→구매 | 시장 호버로 구매가·기본/실제가치 → 기차로 드래그 → 셀 유효성/상단 견적 → 놓으면 확정 | 잡는 순간 가격 상세가 사라짐; 배치 후 전체 정산 손익/구매 후 잔액을 한 문맥에 고정하지 않음(H) | 호버 재방문 수, 자금 시선 왕복, 무효 드롭, 가격 오독 |
| **재배치**: 같은/다른 화차로 이동 | 원자리/후보 고스트/광선·이웃 ±% 칩; 하단 슬롯 드롭/호버 전환 | 다른 화차를 미리 비교하지 못함; 칩은 전체 가치 차이/출발 보드 손실 요약 아님; 자동 배치는 공간 우선(H) | 전환 횟수, 놓기 후 원복, 효과 설명 정확도 |
| **판매**: 지금 가격 vs 기본/매입가 vs 미래 도시 | 기차 호버로 현재 판매가·기본/실제가치; 시장 드롭 견적; 소문은 요약/수첩 | 정확한 매입 원가와 도시별 알려진 기회가 하나의 선택 문맥에 정리되지 않음; 현재 거래와 소문을 기억으로 연결(H) | 판매 결정 전 화면 전환/호버 수, 지금/나중 가격 혼동 |
| **여정**: 시간·운임·화물/의뢰 기한 | 지도/도시 호버·이동 확인에 운임/도착·자금; 기차 툴팁에 신선도/선택 목적지 미래 가치; 수첩에 의뢰 | 지도는 시장 영역을 대체하므로 시장 구매와 목적지 탐색이 분리. 미래 가치는 선택 직결 목적지 1턴 후 **가치**이지 알려진 모든 도시의 순판매이익 비교가 아님(S/H) | 시장↔지도 왕복, 비용/기한 누락, 미확인 시세를 확정값으로 오해하는지 |
| **오류 복구**: 잘못된 드롭/공간·잔액·영업 문제 | 서비스가 사전 평가; 거래 불가 사유 상태 줄; Esc/포커스 상실 취소; 실패 시 원본 유지 | 공간 무효와 경제 무효가 같은 유효/무효 색에 합쳐질 수 있음; 내부 재배치 사유는 공백 가능; 확정 후 범용 Undo 없음(S/H) | 원인 설명 가능 여부, 잘못 확정 횟수, 상태 줄 발견 시간, 복구 성공 |

### 여정/가격 데이터에 관한 주의

- `TryQuoteTrade`를 툴팁과 드롭 평가가 공유하므로 새 UI에서 별도의 가격식을 복제하지 않는다.
- 목적지 미래 가치는 `PreviewValueAfter`/시간 진행 사본을 사용한다. 이것을 목적지의 판매가나 운임 공제 후 순익으로 이름만 바꿔 표시하면 안 된다.
- 소문·방문에 따른 정보 공개는 제품 조건이다. `정확한 값 / 범위 / 등급·추세 / 미확인`을 데이터 계약에 분리한 뒤 UI에 넣어야 한다. 테이블 전체를 읽을 수 있다고 미방문 가격을 모두 공개하는 것은 금지한다.
- 매입가/구매취소 정보가 내부에 존재한다는 사실과, 현재 플레이어가 비교 UI에서 볼 수 있다는 사실을 구분한다.

## 6. 개편 후보의 구현 접점과 제약

아래는 확정 디자인이나 구현 요청이 아니라 R4/R5에서 비용을 비교할 기준이다. **현재 코드·씬·프리팹은 수정하지 않았다.**

| 개선 후보 | 필요한 데이터/책임 | 영향 파일/선행 결정 |
|---|---|---|
| 드래그 중 고정 거래 요약 | 선택 화물, 매입/매도 방향·견적, 잔액 전후, 실패 원인 | GameplayLayout의 시장 정보 열 또는 새 사전 배치 부품; Presenter의 선택/드래그 상태 계약; Presentation 문구 |
| 배치 전후 영향 요약 | 원본/후보 사본에서 자신·출발·도착 이웃·화차 총가치/보존 차이 | Service/Valuation에서 순수 미리보기 DTO 제공, Presenter 수작업 인접 계산과 중복 방지; View는 표시만 |
| 알려진 목적지 비교 | 지식 수준·출처/신선도, 현재/도착 견적, 홉/운임/기한 | Service/Rumors/Routes와 지도/수첩 연계. 정보 공개 수준을 먼저 결정 |
| 거래 중 보드 근접/대칭 배치 | 같은 셀 크기·고스트 좌표·기차 상시성 유지 여부 | GameplayLayout과 PuzzleInventoryUI 인스턴스 배치. 원본 700×600이 아닌 인스턴스 override 기준으로 변경 |
| 복구/즉시 확정 정책 | 취소와 구매취소/범용 Undo의 의미, 시간/퀘스트 부작용 | Service 트랜잭션 범위 결정이 선행. 확인 버튼 추가만으로 Undo가 생기지 않음 |
| 여러 화차 가시화 | 동시 View 수·선택 대상·입력 캡처 대상 | 사전 배치 풀/참조 재설계, TrainBar/Presenter/Drag의 단일 trainView 가정 검토 |

### 반드시 보존할 프로젝트 제약

1. UI 오브젝트와 LayoutGroup은 런타임 생성하지 않는다. 기존 사전 배치 풀과 on/off를 사용한다. 동적 텍스트/크기 계산은 이 금지와 별개다.
2. 배치 원본은 프리팹이고 씬/상위 인스턴스에서 우발적인 override를 만들지 않는다. 다만 **현재 기차/시장 보드 배치는 GameplayLayout의 공용 보드 인스턴스 override에 실제로 존재**하므로 문서 규약만 믿고 다른 파일을 고치지 않는다.
3. 공용 PuzzleInventoryUI 수정은 시장·기차·작업대 계열에 파급될 수 있다. 하나의 파일 담당자를 정하고 Item Editor 아이콘 재저장과 동시 수정하지 않는다.
4. CanvasScaler 1920×1080 Expand, 분리 Canvas/정렬 순서, TMP와 6단계 글자, 8pt 간격·테마/문구 단일 출처를 유지한다.
5. 회전/잡은 칸 기준, 화면 밖/포커스 상실 취소, Ctrl 빠른 이동, 하단 화차 드롭, 지도 상태 제한을 모두 회귀 대상으로 남긴다.
6. 개편을 이유로 시너지·가격·시간·소문 공개 규칙을 임의 변경하지 않는다. 사용자 선택 게이트 G1 전 구현하지 않는다.

## 7. 후속 검증·남은 질문

### 실행 확인이 필요한 항목(U)

- 시장 진입 후 원본/중첩 override가 의도한 5×5/7×6 크기로 실제 나타나는가; 다른 비율에서도 클릭 칸과 아이콘이 일치하는가.
- 원자리 테두리/광선/고스트가 아이템·레이어·수첩에 가려지거나 레이캐스트를 차단하는가.
- 툴팁 폭 300·효과 최대 슬롯·하단 회피 144가 긴 한글/효과 많은 화물에서 잘림·HUD 가림을 만드는가.
- 드래그 직전/중/직후 상단 상태 줄을 플레이어가 실제 읽는가; 여러 피드백이 덮어써 중요한 거래 결과가 사라지는가.
- Ctrl 자동 배치 실패/잔액 부족/야간/잘못된 대상/화차 간 이동·드래그 취소에서 상태와 돈이 보존되는가.
- 상성표·지도·수첩 전환, 검색 IME 포커스, Esc/우클릭·회전 우선순위가 유지되는가.

### 이후 단계가 결정해야 할 질문

1. 거래 중 고정 정보 열은 도시 규칙과 선택 화물 중 무엇을 우선할 것인가?
2. 드롭 전 비교의 기준은 즉시 판매액, 다음 정산 가치, 선택 목적지 순익 중 무엇인가? 서로 다른 수치를 한 ‘이득’으로 합치지 말 것.
3. 공개 가능한 타 도시 정보 수준/출처/유효 기간은 무엇인가?
4. 빠른 이동은 즉시 거래를 유지할 것인가, 위험 거래만 확인할 것인가? 구매취소 외 되돌리기는 범위에 들어가는가?
5. 다른 화차 동시 노출의 효익이 보드 축소/입력 복잡도보다 큰가?

### R4/R5 인수 조건

보수안·중간안·재구성안을 위 5개 과제로 같은 기준에서 비교한다. **호버 → 집기 → 유효/무효 후보 → 확정 → 목적지 선택** 각 상태에 가격·공간·시너지·여정 정보의 위치와 숨김 여부를 명시한다. 실제 사용성 검증 전에는 이 문서의 H를 결함 확정·개선 효과 수치로 재인용하지 않는다.
