4. 레이아웃 5안 예상 와이어프레임

각 안은 같은 시나리오(시장의 2×3 화물을 기차로 구매·배치)의 평상시 / 드래그 중 두 상태를 그린다. 아래 탭으로 안을 전환하고, 각 안 안의 버튼으로 상태를 전환한다. 조사 계획 §8의 A/B/C 원안에 D 다중 객차 윈도우안과 L 행선지 가격·시너지·배치 후보 렌즈안을 더한 총 5안이다.

D안(윈도우 재구성안)에 대하여
  • 참조 교정: Escape from Tarkov의 인벤토리는 사실 고정 분할 UI다(좌 장비·우 컨테이너 내용 — 레지스터 G07). 자유 윈도우 배치의 계보는 Project Zomboid(이동 가능 패널·컨테이너별 무게경감), Barotrauma(속성 윈도우), DayZ(Vicinity 주변 패널)다 — 인디 조사 문서 그룹 2·5와 레지스터 G09에 기록.
  • 정면 이득: 감사서 §7 질문 5("다른 화차 동시 노출의 효익")의 가장 직접적인 답. 객차 전체를 동시에 펼쳐 재배치·분산 적재를 비교할 수 있고, 배치 자유도는 사용자 손에 넘어간다.
  • 비용(이 코드 기준): ① 현재 Presenter는 단일 trainView 가정 — 다중 보드 View·입력 캡처 대상 재설계(감사서 §6 "여러 화차 가시화" 항목). ② UI 런타임 동적 생성 금지 아래 윈도우 관리자(생성·포커스·z-order·위치 저장)를 사전 배치 풀로 만들어야 함. ③ 윈도우 겹침·가림 관리가 플레이어 부담으로 이동(과부하 5). ④ "열린 윈도우 = 시설 진입 상태" 정의 필요(시장 밤 규칙·MarketEntered 수명).
  • 절충 경로(D-lite): B안을 먼저 구현하고 → ① 재배치 시 "다른 객차 비교 윈도우" 1장을 임시로 띄우는 것에서 시작해 → ② 작업대·수첩 윈도우화 → ③ 전면 윈도우화로 단계 이행. B안의 "거래 중 근접 배치"는 게임이 대신 해 주는 자동 윈도우 배치이므로 D로 가는 자연스러운 중간점이다.
L안(행선지 렌즈)에 대하여
  • 핵심: 시장 아이템을 잡으면 기차 보드 위에 상위 3개 배치 후보를 겹쳐 표시하고, 오른쪽 렌즈에서 현재 도시·확인 도시·소문 도시의 가격 근거를 전환한다.
  • 정보 공개 규칙: 현재 도시는 확정 견적, 방문 도시는 지도에 이미 공개된 등급·지역 물가로 계산한 공식 견적(현재 가치 기준, 도착 시 가치 변동 별도 표기), 소문 도시는 소문이 말한 등급만 표시한다. 미방문·무소문 도시는 미확인이며 숨은 테이블 가격을 순위에도 쓰지 않는다.
  • 배치 후보 수치: 후보 ①②③은 다음 정산 가치 Δ만으로 순위를 매긴다(ROUTE_LENS §6). 행선지 가격·운임은 자리와 무관하므로 후보 수치에 더하지 않고 렌즈의 별도 줄에 둔다.
  • 단계 적용(ROUTE_LENS §10과 동일): L0 드래그 중 고정 문맥 → L1 가리킨 자리 하나의 정산 Δ·영향 이웃 → L2 상위 3개 후보 → L3 방문/소문 도시 렌즈 → L4 B 근접 배치 결합 실험. 구체 순서는 구현 계획.
