## 1. 제안 요약

기존 안들은 주로 **두 그리드와 정보 패널을 어디에 놓을지**를 바꾼다. L안은 한 단계 더 들어가, 플레이어가 실제로 고민하는 질문을 기차 보드 위에 직접 투영한다.

> “이 화물을 어느 도시에 가져갈 것인가?”를 먼저 고르고, “그 목적에서 어느 자리에 놓는 것이 가장 좋은가?”를 기차 보드에서 바로 비교한다.

선택한 화물과 행선지 지식 수준을 기준으로 기차 보드의 유효 후보를 평가하되, 25칸 전체를 숫자로 덮지 않는다. 현재 회전에서 좋은 후보 **상위 3곳만** `① +42`, `② +31`, `③ +18`처럼 표시하고, 나머지는 `배치 가능/불가`만 보여 준다. 후보에 마우스를 올리면 고정 렌즈 패널에서 거래액·배치 가치·영향 이웃·운임·정보 신뢰도를 분리해 설명한다.

이 안의 핵심은 자동 배치가 아니다. 플레이어가 공간 퍼즐을 직접 풀되, 반복 배치와 툴팁 왕복 대신 **현재 목적에 맞는 비교 근거**를 보드 안에서 얻도록 하는 것이다.

## 2. 기존 안과 다른 점

| 안 | 중심 변화 | L안과의 차이 |
|---|---|---|
| A | 기존 좌우 배치 + 고정 정보 열 | L은 정보 열의 결과를 보드 후보 위치에 다시 연결한다 |
| B | 거래 중 두 보드를 근접 배치 | L은 보드 이동 없이도 시너지 판단 거리를 줄이며, B와 결합 가능하다 |
| C | 시장·기차·여정 선반을 하나의 작업 공간으로 재구성 | L은 지도/역 구조를 바꾸지 않고 선택 목적만 보드에 투영한다 |
| 윈도우형 후속안 | 여러 화차·컨테이너를 자유 배치 | L은 창 관리 대신 현재 화차 한 장의 배치 품질에 집중한다 |

L안은 레이아웃 재배치보다 **판단 방식의 개편**이다. 따라서 공통 DTO와 고정 비교 도크를 먼저 구현한 뒤 A 또는 B 위에 얹을 수 있다.

## 4. 렌즈 문맥

### 현재 도시

- 구매/판매 견적과 자금 전후를 정확히 표시한다.
- 기차 보드 후보 점수는 **현재 배치 가치 변화**만 사용한다.
- 즉시 현금과 다음 정산 가치를 합산하지 않는다.

### 정확히 관측한 도시

- `관측 매도가`, 관측 시각, 이동 시간, 운임, 도착 시 기한을 표시한다.
- 후보 배치는 공간·시너지 기준으로 순위화한다.
- 목적지 예상 판매 결과는 별도 줄에 두며 배치 Δ와 하나의 숫자로 섞지 않는다.
- 오래된 관측값은 확정가가 아니라 추정값으로 표시한다.

### 소문으로만 아는 도시

- `비쌈`, `귀함`, 범위처럼 실제로 공개된 수준만 표시한다.
- 정확한 이익액과 숫자 순위를 만들지 않는다.
- 보드 후보는 시너지 Δ까지만 숫자로 표시하고, 행선지 기회는 정성 배지로 분리한다.

### 미확인 도시

- 시세를 `0`이나 최하위로 취급하지 않는다.
- 경로가 알려졌다면 시간·운임만 표시할 수 있다.
- 숨은 테이블 가격을 후보 순위 계산에도 사용하지 않는다.

## 6. 후보 순위 규칙

순위는 플레이어에게 숨은 종합 점수 하나를 보여 주는 방식이 아니다. 다음 단계로 제한한다.

1. 현재 화차와 현재 회전에서 공간상 가능한 앵커를 찾는다.
2. 각 후보를 원본을 바꾸지 않는 사본에서 평가한다.
3. 자신·출발 이웃·도착 이웃·화차 가치의 같은 시점 전후를 비교한다.
4. **배치 가치 Δ**로만 순위를 정한다.
5. 동률이면 위→아래, 왼쪽→오른쪽의 안정적인 순서를 쓴다.
6. 상위 3개만 숫자와 순위를 표시한다.

목적지 가격과 운임은 후보 자리를 바꾼다고 달라지지 않으므로 배치 순위에 중복 반영하지 않는다. 냉장·기한처럼 배치로 실제 결과가 달라지는 규칙만 같은 평가 시점에서 포함할 수 있다. 무엇을 포함했는지는 렌즈 상세에 표시한다.

`① +42`는 `42원 확정 수익`이 아니라 반드시 `다음 정산 가치 +42`처럼 단위를 붙인다. 정확한 평가 계약이 준비되지 않은 초기 단계에서는 기존 인접 `±%`만 보여 주고 순위를 숨긴다.

## 7. 장점

- 공간 퍼즐과 경제 판단을 같은 보드에 연결한다.
- 좋은 자리를 찾기 위한 반복 드롭·원복을 줄일 가능성이 있다.
- 드래그 중 툴팁이 사라져도 선택·가격·목적 문맥이 유지된다.
- 보드 위치와 기존 근육 기억을 유지하므로 B/C보다 레이아웃 회귀 위험이 작다.
- 정확한 도시 정보와 소문 수준을 같은 UI에서 다르게 표현할 수 있다.
- A에서 시작해 B에 결합하는 단계적 구현이 가능하다.

## 8. 위험과 제한

- 후보 계산이 느리면 포인터 이동과 회전이 끊긴다.
- 숫자 표식이 많으면 아이템 모양과 빈칸 판독을 가린다.
- 불완전한 시너지 평가를 `최적 배치`로 보이면 플레이어를 오도한다.
- 추천 위치가 공간 퍼즐을 자동 풀이처럼 느끼게 할 수 있다.
- 다른 화차까지 동시에 평가하면 계산량과 정보량이 급증한다.
- 목적지의 과거 가격을 현재 확정가처럼 쓰면 소문·탐색 루프가 무너진다.

완화 원칙:

- 현재 화차·현재 회전만 계산한다.
- 상위 3개만 표시하고 나머지는 가능/불가만 표현한다.
- `후보`라고 부르고 `최적`이라고 부르지 않는다.
- 추천 표시는 사용자가 끌 수 있게 하되, 유효/무효 피드백은 항상 유지한다.
- 16ms 안에 안정적으로 계산되지 않으면 드래그 연속 계산 대신 집기/회전 때만 갱신한다.
- 데이터가 불완전하면 정확한 금액 대신 기존 인접 배율·정성 설명으로 강등한다.

## 9. 구현 영향

### 데이터 계약

- `LensContext`: 현재 도시/관측 도시/소문 도시, 정보 수준, 출처, 관측 시각, 경로·운임·기한.
- `PlacementCandidatePreview`: 앵커, 회전, 유효성, 실패 사유, 가치 전후/Δ, 영향 대상 ID, 평가 시점.
- `PlacementCandidateBatch`: 원본 스냅샷 ID, 현재 화차, 현재 회전, 후보 목록, 상위 3개.
- `PinnedSelectionSnapshot`: 판매/처분 후에도 영수증을 설명할 표시용 스냅샷.

### View/프리팹

- `PuzzleInventoryUI.prefab`에 입력 없는 후보 표식 슬롯 최대 25개를 사전 배치한다.
- 실제 숫자 배지는 상위 3개만 켜고 나머지는 유효성 배경만 사용한다.
- 기존 Ghost Canvas 260과 충돌하지 않도록 후보는 본문 또는 별도 표시 전용 Canvas에서 고스트 아래에 둔다.
- 기존 시장 정보 열을 렌즈로 전환하므로 A의 고정 비교 View와 공유할 수 있다.

### Presenter/서비스

- `PuzzleInventoryService`/`PuzzleInventoryValuation`에 원본을 바꾸지 않는 배치 후보 일괄 평가 경로가 필요하다.
- 미리보기에서 `ApplyDrop` 후 원복하는 방식은 금지한다.
- 캐시는 화물·화차·회전뿐 아니라 자금, 시간, 도시, 숙련, 구매취소 자격, 화차 구성, 가치 상태가 바뀌면 무효화한다.
- `PuzzleInventoryPresenter`는 호버/드래그/영수증 상태와 렌즈 문맥을 분리해 관리한다.
- 목적지 가격은 숨은 테이블을 직접 조회하지 않고 공개정보 어댑터를 거친다.

## 10. 단계적 적용

1. **L0 — 고정 문맥:** 드래그 중 현재 거래액·자금 전후·선택 화물을 고정한다.
2. **L1 — 현재 후보 상세:** 포인터가 가리키는 한 자리의 배치 Δ와 영향 이웃만 계산한다.
3. **L2 — 상위 3개 후보:** 현재 화차·현재 회전의 후보를 일괄 평가하고 보드에 표시한다.
4. **L3 — 행선지 렌즈:** 정확/범위/등급/미확인과 시간·운임·기한을 결합한다.
5. **L4 — B 결합 실험:** 두 보드 근접 배치와 렌즈를 함께 쓸 때 과부하와 실제 과제 시간을 비교한다.

L1까지는 A/B 공통 데이터 계약의 자연스러운 확장이다. L2부터 성능·자동풀이 인식 위험이 생기므로 별도 프로토타입 게이트로 둔다.

## 11. 동일 기준의 잠정 평가

| 기준 | 가중치 | L안 | 판단 |
|---|---:|---:|---|
| 핵심 루프 적합성 | 25 | 24 | 공간·시너지·행선지를 한 선택 문맥으로 연결 |
| 두 그리드 이동 명료성 | 20 | 17 | 위치는 유지하지만 후보와 실패 원인을 보드에서 직접 표시 |
| 가격 판단력 | 20 | 19 | 정보 수준과 여정 비용을 선택 문맥에 유지 |
| 시너지 판단력 | 15 | 15 | 후보 위치와 영향 결과를 직접 연결 |
| 정보 과부하 억제 | 10 | 8 | 상위 3개 제한이 전제 |
| 현 프로젝트 구현 적합성 | 10 | 5 | 순수 후보 일괄 평가와 표식 풀이 신규 작업 |
| **합계** | **100** | **88** | 실측 점수가 아닌 프로토타입 우선순위 가설 |

점수 88은 B의 87보다 우수하다는 검증 결과가 아니다. L은 레이아웃 회귀 대신 계산·설명 복잡도를 부담한다. 따라서 **B를 곧바로 구현하기보다 L0/L1을 공통 기반으로 먼저 만들고, B 배치 변경과 L2 후보 표시를 각각 켜고 끌 수 있는 프로토타입으로 비교**하는 것이 가장 안전하다.

## 12. 권고

최종 후보를 `B 단독`에서 다음 비교로 바꾼다.

- **기준안:** A + L0/L1 — 현재 좌표, 고정 렌즈, 현재 후보 한 곳의 정확한 설명
- **실험안 1:** B + L0/L1 — 두 보드 근접 + 고정 렌즈
- **실험안 2:** A + L2/L3 — 현재 좌표 + 상위 3개 후보 + 행선지 문맥

세 안에서 같은 구매·재배치·판매·여정·오류 복구 과제를 측정한다. B의 좌표 변경과 L의 후보 추천 효과를 한 번에 넣으면 무엇이 개선에 기여했는지 분리할 수 없으므로, 처음부터 합친 단일 시안만 만들지 않는다.
