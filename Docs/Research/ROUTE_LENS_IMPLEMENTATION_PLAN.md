## 1. 결론

1. **L0–L2 코어는 그대로 유효하다.** 잡는 순간 견적 고정, 자리 하나의 정산 Δ, 상위 3 후보는 develop의 API로 구현할 수 있다. Δ 기준을 HUD 정산 게이지와 맞추면 오히려 기존 화면과 잘 이어진다.
2. **렌즈 패널 위치는 처음부터 다시 정해야 한다.** 예정했던 오른쪽 정보 열이 develop에서 76px 높이의 가로 띠로 바뀌었다(E1).
3. **S1(휴식·대기 통합)은 작아진다.** 휴식은 이미 턴 선택형이고 대기 버튼도 휴식을 부른다. 남은 일은 끊긴 버튼 정리와 휴식 화면의 "아침까지" 선택지다.
4. **D2(방문 도시 견적 숫자)는 유지할 수 있다.** 안개 규칙에서도 방문 도시의 등급·물가는 공개 정보다. 미방문 도시는 계속 숫자·등급을 숨긴다.
5. **문서·목업은 develop 기준으로 다시 그려야 한다.** 보드 크기, HUD(결산 목표·D-n), 6시간 턴, 소문 무료, 작업대 비용, 등급 이름이 모두 바뀌었다.

## 5. 검증 (실행은 사용자 요청 시)

- 빌드: 런타임·에디터 `dotnet build` 오류 0. 새 `.cs`는 Unity가 csproj를 다시 만들기 전까지 수동 등록 필요.
- 기초데이터 계약(`BasicDataContract.cs`)을 생성기로 다시 만든 뒤 테이블 검증 통과.
- 순수성: 후보 평가 전후 원본 화차의 배치·가치·알림 불변.
- Δ 일치: 후보 자리에 실제로 놓은 뒤 HUD 정산 예상치(`TrainSynergyDelta`) 변화 = 표시 Δ. 구역·구멍·가공 화차·숙련 보강 포함 사례.
- 공개 규칙: 지나치기만 한 역, 소문만 있는 역, 미방문 역에서 가격·등급이 나오지 않음.
- 회귀: R5 §7 공통 항목(입력·복구·화차·지도·레이어).
