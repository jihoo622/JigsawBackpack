# 가격·목적지 판단 레이아웃 증거 — R3

> 확인일: 2026-11-18 · PC 마우스·키보드 비교 · 문서 조사만 수행  
> 상태: **4개 사례의 정적 화면·공식 매뉴얼 조사 완료 / 동적 거래·정보 공개 조건 검증 미완료**  
> 대상: Merchant of the Skies, Patrician IV 기본판, X4: Foundations, Port Royale 4. 비그리드 D군 비교군이며 A/B/C군 또는 검증된 그리드 게임 수에 산입하지 않는다.

## 1. 목적·방법·증거 경계

[조사 계획](GRID_INVENTORY_LAYOUT_RESEARCH_PLAN.md) §2·5·10과 [후보 레지스터](GRID_INVENTORY_CANDIDATE_REGISTER.md) D01–D03를 기준으로, 현재 거래가와 다른 목적지의 기회를 공간 배치 화면 옆에 어떻게 두어야 하는지 조사했다. 네 번째는 기존 [무역 조사](TRADE_GAME_UI_RESEARCH.md)의 Port Royale 4를 추가했다. [기차 조사](TRAIN_GAME_UI_RESEARCH.md)는 수요/목적지 표현의 발견 자료로 읽었지만, 그 문서의 평가·조작·화면 주장을 재검증 없이 인용하지 않았다.

실제 수행:

1. Steam 상품 API `https://store.steampowered.com/api/appdetails?appids=<ID>&l=english`에서 제목·발매일·상품 스크린샷 목록을 읽었다.
2. 네 게임의 상품 이미지 총 66장(18/13/19/16)을 내려받아 컨택트 시트로 선별하고, 아래 증거표의 주요 원본을 직접 열어 관찰했다. 파일명에 `1920x1080`이 있어도 실제 픽셀을 별도로 확인했다.
3. Steam의 공식 매뉴얼 링크가 리다이렉트하는 Patrician IV 영문 PDF(56쪽), Port Royale 4 영문 PDF(18개 PDF 페이지, 양면 편집)를 내려받아 관련 본문을 추출했다. Patrician IV p.14·15·40·41은 렌더링한 도판도 직접 확인했다.
4. 게임 실행·클릭·드래그·가격 갱신·연속 영상 관찰은 하지 않았다. 따라서 정적 화면 한 장을 거래 전후의 연속 증거나 현재 배포 빌드의 조작 증거로 부르지 않는다.

증거 구분:

- **S — 화면 관찰**: 이 문서에서 실제 연 이미지/매뉴얼 도판에 보이는 것.
- **M — 공식 문서**: 읽은 매뉴얼 본문이 명시하는 기능. 실측 조작 검증과 다르다.
- **U — 미확인**: 이번 자료로 판단 불가. 화면에 없다는 것이 게임 전체에 없다는 뜻은 아니다.
- **P — 제안**: Trainventory에 적용할 설계 가설. 외부 게임의 사실로 역수입하지 않는다.

모든 출처의 확인일은 위 날짜다. 상품 이미지는 촬영일·실행 OS·입력 장치·패치·DLC·모드 여부가 공시되지 않았다. PC 상품에 실린 화면이라는 것과 **PC 현행 기본판에서 재현했다는 것**을 구분한다. 정확한 빌드 미확인은 아래에 그대로 남겼다. 화면 내 화폐 숫자는 해당 정적 상태의 예시이지 현행 밸런스나 단가의 보증이 아니다.

## 3. 사례별 관찰

### 3.1 Merchant of the Skies — 소유·거래 대기·상대 재고의 분리

**S / M1:** 좌측 `Your Ship`, 중앙 `Buying`, 우측 `Merchant` 세 영역이 각각 테두리와 제목을 가진다. 중앙 아래에 별도 빈 슬롯 영역과 확인/취소 아이콘 및 `-38`이 있고, 선택 팝업에는 `Wood (2)`와 동전 `38`이 보인다. 좌상단에는 `13840`, 상대 영역 아래에는 동전 `462`가 있다. 좌하단에 `15% Income Tax`, `V x10`, `Z x100` 안내가 있으며 우하단 Trade Post 게시판은 품목별 동전 기호 및 일부 `(?)`를 보인다.

- 가격 위치: 선택 상세와 중앙 거래 대기 결과가 공간적으로 가깝다. **38이 단가인지 두 개 합계인지**는 정지 화면만으로 확정하지 않는다.
- 배치: 두 소유 영역은 대략 x=390–700 / x=1270–1590이며, 중앙 대기 영역을 사이에 둔다. 같은 크기의 스택 슬롯이지 Trainventory의 비정형 패킹 증거가 아니다.
- 정보 계층: 소유 재고와 거래 대기는 제목으로 구분되지만 중앙 팝업이 슬롯 일부를 가린다. 숫자 색만이 아니라 `Buying`, 부호, 위치를 함께 사용한다.
- 현재 거래와 미래 기회: M1에 다른 도시의 비교 가격은 관찰되지 않는다. M2는 섬과 이름을 보여 주지만 선택한 Wood의 가격·운임·ETA 표를 동시에 보여 주는 증거가 아니다. `(?)`의 정확한 의미·해금 조건도 U다.
- 입력·확정: 확인/취소 아이콘과 수량 배수 안내의 존재만 S다. 드래그 시점의 소유권 변경, 버튼 클릭 직후 정산, 취소 복원, Max·슬라이더 지원은 U다.

**P / 가져올 것:** `내 화물 / 구매 대기 / 시장`이라는 의미 분리와 **총 자금 변화에 부호를 붙이는 패턴**. 별도 대기 격자를 그대로 추가하기보다 기차 위 고스트와 고정 거래 요약으로 대체하는 편이 기존 두 보드를 보존한다.

**피할 것:** 슬롯을 가리는 가격 팝업, 동전 그림만 있고 단위/단가/합계가 모호한 수치. 기존 무역 문서의 “전 품목 매수·매도가 리스트 + 슬라이더/Max”는 M1과 일치한다고 확인되지 않았으므로 설계 근거로 사용하지 않는다.

### 3.2 Patrician IV — 정확 가격·원가·공급 등급의 역할 분담

**S+M / P2:** 거래 창은 왼쪽 도시 공급, 오른쪽 창고/선단이고 거래 방향을 바꾸는 제어가 있다. p.15는 공급 지표를 **네 다이아 슬롯의 다섯 채움 상태**로 설명한다. 전부 채움은 비싸고 긴급 수요, 전부 비움은 과잉 공급·생산가 미만이다. 이를 “다이아 4개 = 네 가격 단계”로 단순화하면 틀린다. 생산품은 톱니 표시로 별도 구분한다.

**M / P2:** 상품을 클릭하고 수량 슬라이더를 움직인다. **수량 변화에 따라 가격도 변한다**고 명시되어 있다. 오른쪽 열은 평균 매입가이며 자가 생산품은 생산가다. 공급 등급은 정확 시세의 대체가 아니라 수요·평판 결과를 설명하는 보조 정보다. 매뉴얼 p.10은 거래 창에서도 경쟁자가 활동한다고 경고한다.

**S+M / P1·P3:** P1에는 큰 항로 지도와 연결선, `Route / Handel` 탭, 우측 선단 요약이 동시에 보인다. P3의 거래 탭은 도시 순서 목록, 상품 분류, 상세 조건 열로 나뉜다. p.40–41은 `거래 안 함 / 자동 거래 / 명세대로 거래`, 최대 수량, 판매 최소 가격, 적재·하역 전환을 명시한다. `100%`는 정상 생산가를 채우는 기준 버튼이다. p.42는 한 순회 후 항로 손익을 확인할 수 있다고 설명한다.

- 현재가/원가: 같은 거래 작업에서 평균 매입가를 참조하므로 “얼마에 샀는지” 기억 부담을 줄인다.
- 타 도시 기회: 도시별 규칙을 선택해 편집하지만, **현재 거래 창에서 전 도시의 실제 시세를 한 번에 비교하는 화면**은 확보하지 못했다.
- 시간/위험: 항로 연결은 S, 선장 능력이 정박 시간/이동 속도에 영향을 준다는 것은 매뉴얼 p.34의 M다. 현재 선택 상품에 대해 운임·ETA·해적 위험을 함께 합산하는 화면은 U다.
- 취소/확정: 슬라이더가 있다는 것만으로 “움직이면 즉시 확정”이라고 결론 내리지 않는다. 확정·복구 동작은 별도 실행 검증이 필요하다.

**P / 가져올 것:** 선택 화물 옆에 `현재 매도가 / 매입원가 / 기본 가치`를 구별하고, 보조 수급/가격 등급에는 텍스트 범례를 붙인다. 도시 순서 선택과 상세 거래 조건의 2단계 구조는 목적지 비교 패널과 전체 지도 분리의 근거가 된다.

**피할 것:** 생산지라는 이유만으로 항상 싸다고 표시하기, 공급 등급을 정확 이익률로 환산하기, 과거 한 순회 손익을 다음 여정의 확정 이익으로 표시하기.

### 3.3 X4: Foundations — 지도 맥락을 유지하는 고정 선택 정보

**S / X1·X2:** 왼쪽 약 31% 폭의 긴 자산/객체 목록, 나머지 큰 지도, 하단 중앙의 `Selected Object` 요약으로 구성된다. 우상단에 `Trade / Mining / Other` 필터와 검색이 있다. X1에는 선택된 선박과 명령, `Remaining cargo after orders` 및 용량·품목 수치가 하단에 함께 보인다. 이는 **현재 재고와 명령 후 결과를 구별한 요약**의 시각적 근거다. X2도 같은 구조를 보여 주지만 거래 가격 창은 아니다.

- 가격: 두 이미지에 선택 상품의 매수·매도 호가 표는 확보되지 않았다. 초록 글씨는 소유 객체 목록에도 쓰이므로 **초록 = 무조건 수익성 높은 가격**으로 해석할 수 없다.
- 목적지: 지도상의 장소·연결과 선택 객체의 상태를 유지할 수 있다. 다만 하단 명령 텍스트가 잘리므로 긴 목적지는 별도 전체 이름 표시가 필요해 보인다.
- 정보 공개/신선도: Trade 필터의 존재는 S지만 호가 만료, 위성/에이전트/라이선스 갱신 조건, 미탐사 시 가격 공개 범위는 U다.
- 운임/시간/위험: 지도상의 상대 위치가 보인다는 것과 수치 비용을 비교한다는 것은 다르다. X1·X2에서 ETA·운임·위험 점수는 관찰하지 못했다.
- 빌드 주의: 기본 상품의 이미지라고 DLC 미사용을 뜻하지 않는다. X4를 “2018~EA”로 부르지 않는다; 2018-11-30 정식 발매와 이미지 촬영 버전은 별개다.

**P / 가져올 것:** 지도/보드를 갈아엎지 않고 **선택 결과만 고정된 얕은 요약에 표시**하기. Trainventory 드래그 중에도 현재 거래 결과·목적지 후보가 고정되어 커서 주변 팝업을 쫓지 않게 한다.

**피할 것:** X4의 자산 트리 밀도와 전체 지도 오버레이를 작은 두 보드 거래 화면에 그대로 축소하기. 이 자료로 기존 무역 문서의 평균가 색상·예약 물량 색·거래 정보 갱신 규칙을 검증했다고 주장하지 않는다.

### 3.4 Port Royale 4 — 경로 비용을 별도 축으로 다뤄야 하는 비교군

**S / R1:** 넓은 섬 지도에 도시 이름과 국기, 여러 칸의 색 막대, 우하단 축약 지도가 보인다. 이 막대가 상품 희소성을 의미하는지는 화면만으로 판별할 수 없다. 특정 상품 선택/매수·매도가 표가 없는 지도이므로 **“도시 밑 막대 = 4-pip 희소성”의 증거로 사용하지 않는다**. 화면의 0.1.0 버전 표기를 기록했고 현행판 UI로 일반화하지 않는다.

**M / R2:** 선박 데이터에 다음이 명시된다.

- `Daily Costs`: 선박 유지비에 추가 선원 임금이 더해진다.
- `Draft`: 연안/얕은 수역 이동에 영향을 주며 혼합 선단은 가장 깊은 흘수의 제약을 받는다.
- `Speed`: 순풍·해류 조건과 선단 중 가장 느린 선박의 제약을 받는다.
- `Stability`: 시간에 따른 마모가 있으며 긴급 수리는 시간을 소모한다.

따라서 거리만으로 실제 여정 손익을 대신하면 안 된다는 **규칙 근거**는 있다. 하지만 이 데이터들이 거래/목적지 선택 화면의 같은 패널에 표시되는지, 실제 ETA·순이익을 UI가 계산하는지는 U다. 전투 위험도·정확 운임을 지도 위에서 비교하는 화면도 확보하지 못했다.

**P / 가져올 것:** 현재 판매가와 목적지 가격 사이에 반드시 `이동 시간 / 비용 / 화물 기한`을 별도 축으로 두기. 가격 차이에 운임을 암묵적으로 숨기지 않는다.

**피할 것:** 이 게임의 바람·흘수·선박 마모 같은 새 규칙을 Trainventory에 추가하기. 이 사례는 비용 모델 비교군이며 검증된 가격 비교 화면 사례로 세지 않는다. 기존 문서의 Standard 자동 거래 버튼·4-pip 수급 주장은 후속 검증 큐다.

## 6. Trainventory 적용안 — 정확값·범위·등급·미확인의 분리

아래는 **P**, 외부 게임에서 네 수준 모두를 관찰했다는 뜻이 아니다. 프로젝트의 방문·소문·의뢰 루프를 보존하기 위한 데이터/표현 계약 제안이다.

| 정보 수준 | 목적지 비교 행 표현 예시 | 허용하는 계산·정렬 | 금지 |
|---|---|---|---|
| 정확값 | `도시 A · 매도가 140 · 방문 확인 · 2일 전` | 알려진 가격 기준의 추정 차액. 과거 관측이면 현재 확정가처럼 부르지 않음 | 오래된 값의 무표식 사용, 도착 시 가격 보장 |
| 범위 | `도시 B · 120–160 · 소문 · 1일 전` | 경계가 실제 정보에 포함될 때만 순수익 범위 계산 | 임의 중앙값 140을 정확값처럼 사용 |
| 등급/추세 | `도시 C · 비쌈 ↑ · 소문` | 등급 비교와 정성적 기회 안내 | 등급에서 숫자 가격·정확 이익률 역산 |
| 미확인 | `도시 D · 시세 미확인` | 경로가 알려져 있으면 시간/운임은 독립 표시 | `0`, 무료, 적자, 최하위 등급으로 처리 |

상시·선택·드래그·지도 정보 배치:

- **상시:** 보유 자금, 현재 도시/거래 가능 상태, 기차·시장 두 보드, 현재 화차. 전체 도시 가격표는 상시 펼치지 않는다.
- **선택 시 고정 열:** 화물 이름, `구매가/현재 매도가`, `매입원가`, 현재 가격의 단위, 현재 거래 후 자금. 아래에는 **알려진 목적지 상위 2–3개**와 정보 수준·출처·경과일을 표시한다. 후보가 적으면 미확인으로 채우지 말고 그대로 둔다.
- **드래그 중 고정 요약:** `구매 -100 / 배치 시너지 +20 / 정산 예상 가치 120`처럼 서로 다른 종류의 값을 분리한다. 시너지 증가를 즉시 현금 수익처럼 합산하지 않는다. 실제 규칙에 없는 수치는 새로 만들지 않는다.
- **목적지 비교:** 같은 선택 화물을 유지한 채 `알려진 판매 기회 / 이동 시간 / 운임 / 도착 시 기한 상태`를 행으로 비교한다. 전체 지도는 펼침으로 열고, 닫아도 선택·화차·보드 스크롤을 유지한다.
- **확정 직전:** 실제 드롭 위치·가격·자금 차액·시너지 영향이 거래 입력 처리와 같은 데이터 기준이어야 한다. 잔액/공간/거래 가능 상태가 바뀌면 미리보기를 갱신하고 사유를 텍스트로 표시한다.

순이익이라는 이름은 계산 의미를 먼저 정해야 한다. `목적지 예상 매도가 - 현재 구매가 - 이번 여정 운임`은 신규 구매의 **추정 여정 차익**이고, `다른 도시 예상 매도가 - 지금 매도가 - 추가 운임`은 **지금 팔기 대비 보유 기회 차이**다. 두 식을 혼합하지 않는다. 여러 화물에 공동 운임을 각각 전액 차감한 뒤 합산하는 이중 계상도 피한다. 정보가 등급/미확인이거나 도착 시세를 보장할 수 없으면 숫자 순위에 확정 수익 배지를 붙이지 않는다.

## 7. 권고·보류·후속 검증

**현재 권고:** 거래 화면은 두 보드의 공간 판독을 주작업으로 두고, 선택 화물의 가격·배치 결과·알려진 목적지 기회를 **고정된 얕은 비교 영역**에 합친다. 전체 도시/노선 설정은 확장 지도에 남긴다. 가격 등급·현재 숫자·매입원가·시간 비용은 서로 다른 의미를 유지한다. 세부 픽셀 배치와 보수/중간/재구성 3안의 최종 선택은 R4에서 현 UI 감사 및 A/B/C 증거와 함께 결정한다.

**아직 권고 근거로 사용할 수 없는 것:** 미탐사 가격 자동 공개, X4식 호가 갱신 조건, Port Royale의 Standard 버튼/희소성 pip, Merchant의 전 품목 가격표/Max, 즉시 체결·되돌리기. 기존 요약 문서에 있다는 이유로 확정하지 않는다.

후속 증거 큐:

1. **Merchant:** 촬영 빌드를 특정한 PC 영상에서 물품 선택→구매 대기→확정→취소를 연속 관찰. 38의 단가/합계 관계, 게시판 `(?)`, 섬 지도 가격 공개 조건 확인.
2. **Patrician IV:** 기본판 빌드를 명시한 PC 거래 연속 화면에서 수량/가격 변화와 최종 확정, 도시별 비교 동선을 검증. Special Edition/확장을 섞지 않음.
3. **X4:** 패치·DLC·모드를 명시한 Trade 필터/상품 오퍼 화면 및 정보 만료·갱신 출처 확보. 평균가·호가·재고·명령 후 화물을 구분해 캡처.
4. **Port Royale 4:** 0.1.0 홍보 화면 대신 현행 PC의 시장/상품 선택/항로 계획 화면 확보. 막대 의미·수급 단계·ETA·운영비 표시 위치를 공식 설명 또는 영상과 대조. 실패하면 다른 D 사례로 교체하되 이 문서의 규칙 비교 기록은 보존.
5. **공통:** 동일 빌드의 평상시/선택/미리보기/거래 직후/목적지 선택을 연결하고, 정확값·범위·등급·미확인을 실제로 어떻게 노출하는지 확인. 기한·위험이 해당 게임에 없으면 N/A와 기능 부재 근거를 기록하고, 자료가 없으면 U로 남긴다.

문서 산출은 완료했지만, **네 게임 모두의 동적 거래 검증 또는 계획 §10의 조사 완료 게이트 통과를 선언하지 않는다.** 후속 결정자는 이 문서의 S/M 증거만 확정 근거로, P는 검증할 설계 가설로 사용해야 한다.
