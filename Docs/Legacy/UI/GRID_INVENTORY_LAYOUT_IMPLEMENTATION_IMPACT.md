### 가격·가치 구현상 함정

1. 현재 TryQuoteTrade는 숙련/구매취소까지 적용한다. TryQuoteTradeAt은 다른 도시 공식 조회이며 같은 보정/정보 공개 계약을 자동 보장하지 않는다. 목적지 표시는 서비스의 공개정보 어댑터를 통하게 한다.
2. 판매액은 음수일 수 있다(처분 비용). ‘판매=자금 증가’라는 전제 금지. 음수 판매와 잔액 부족/오버플로를 포함해 기존 평가를 사용한다.
3. Move는 새 placement를 만들고 실제 가치/배율을 재계산한다. 오래된 원본 참조를 확정 후 선택으로 유지하지 않는다. InstanceId와 실제 도착 Owner/Pose를 다시 찾고, 기록은 삭제 전에 캡처한다.
4. ApplyDrop은 자금뿐 아니라 원산 기록·동물 상태·숙련·의뢰 실패/이벤트를 갱신한다. 미리보기에서 실제 ApplyDrop 후 원복하는 방식은 금지한다.
5. CopyForTimeAdvance는 출발점이지 완성된 순수 드롭 미리보기 API가 아니다. 사본의 원본 placement 매핑·두 보드 이동·전체 화차/시간 상태·식별자/이벤트 부작용을 검토해야 한다. 실제 모델 변경 없이 반복 평가해 원본 해시가 불변임을 테스트한다.
6. 캐시는 보드/칸/회전만으로는 부족하다. 자금·시간·도시·숙련·구매취소 자격·화차 구성·화물 정의/가치 변경 시 무효화한다. 기존 인접 칩 캐시를 그대로 견적 캐시로 확장하지 않는다.
7. 목적지 미래 가치와 목적지 판매가, 현재 현금과 다음 정산Δ를 합치지 않는다. 복수 화물의 공통 운임을 중복 차감하지 않는다. 공개 데이터 없으면 계산 불가/미확인으로 남긴다.

## 5. 입력·레이어 계약과 변경 범위

### 입력/상태

- 최소 변경은 기존 호버→집기 즉시 캡처→회전→놓기 즉시 확정을 보존한다. Ctrl 자동 빈자리 탐색도 유지하고 결과 도크는 실제 도착 좌표를 표시한다. 수동 후보를 자동 배치 결과로 재사용하지 않는다.
- 새 표시 상태는 `Idle / Hover / Drag / Receipt`, 배치 상태는 `NonTrade / Trade / Map`처럼 분리할 것을 제안한다. 후보/가격 갱신이 선택을 바꾸지 않고, 영수증을 일시 호버가 언제 교체할지는 승인 때 정한다.
- 3안의 ‘드래그 중 지도/수첩 열기 금지’는 **현행 보존이 아니라 동작 변경**이다. MapToggleRequested/MapRequested/링크/요약 띠/단축키 등 요청 진입점에 공통 게이트를 둬야 한다. 버튼만 비활성화하면 부족하다.
- Esc 우선순위는 PauseMenu의 검색→메뉴→이동 확인/자동이동→드래그→상성표→지도→수첩→역 복귀→일시정지를 보존한다. 화차 상품/순서 드래그 취소 경로도 함께 확인한다. 우클릭은 잡는 중 회전만 수행한다.
- 지도에서는 시장 거래 차단·기차 정리 허용, 이동 확인/연출은 기차까지 차단한다. 비활성화/포커스 상실은 취소이며 무효 놓기는 원본과 자금 보존이다.
- 화면 밖으로 이동했을 때 현재 RefreshDrag는 표시를 숨기고 상태 줄을 비우는 경로다. 이것을 포인터 이탈 즉시 전체 취소가 이미 구현됐다고 쓰지 않는다. 화면 밖 놓기/포커스 상실은 별도 검증한다.

## 9. 최종 판단·남은 결정

- **B 조건부 권고 유지:** 현재 단일 View와 서비스 경로를 보존할 수 있으나 시장 모드/복원과 공개정보 계약은 신규 작업이다. ‘프리팹 위치만 변경하면 끝’이라는 판단은 부적절하다.
- **A로 축소 가능:** 공통 DTO+고정 정보 열을 먼저 검증한다. B 배치 회귀가 크거나 A만으로 판단력이 충분하면 근접 배치를 생략한다.
- **C 보류:** 선반 최대3개/지도 좁힘/역 모드 전환의 효과와 가독성이 확인되기 전에는 높은 비용을 정당화하지 못한다.
- 사용자 결정 필요: 최종안, B의 기차 위치 변화 허용, 호버/영수증 교체·핀 여부, 원가 기록 범위, 목적지 정보 수준/관측 수명, 드래그 중 지도·수첩 열기 차단 승인.
- 기술 미결: 순수 사본 평가 범위/시점, 과거 관측값 저장 계약, B 부모 클리핑/참조, C 지도 축소, 실제 Raycast/화면비/긴 텍스트. 이 문서는 이를 검증 완료로 닫지 않는다.

## 11. R5 이후 추가안의 영향

[행선지 렌즈 + 배치 후보 히트맵](ROUTE_LENS_UI_PROPOSAL.md)은 공통 DTO와 고정 정보 열을 재사용하지만, 현재 화차·현재 회전의 유효 앵커를 원본 변경 없이 일괄 평가하는 `PlacementCandidateBatch`가 추가로 필요하다. 후보 표식은 최대 25개를 사전 배치하고 상위 3개만 숫자를 켠다. L0/L1은 A/B 공통 단계로, 상위 후보를 계산하는 L2부터는 성능·정보 과부하·자동풀이 인식 때문에 별도 프로토타입 게이트로 취급한다.
