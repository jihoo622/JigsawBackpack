# 그리드 인벤토리 거래 UI 개편 조사 계획

> 상태: 조사 실행 전 계획  
> 작성일: 2026-11-18  
> 조사 운영: Orca orchestration  
> 기준 화면: PC 마우스·키보드, 1920×1080

## 1. 이번 조사로 내릴 결정

현재의 `왼쪽 5×5 기차 보드 + 오른쪽 7×6 시장 보드/역 화면` 구성을 그대로 다듬을지, 두 그리드와 가격·시너지·목적지 정보를 더 직접 비교할 수 있는 새 레이아웃으로 바꿀지를 결정한다.

조사가 답해야 할 중심 질문은 다음 한 문장이다.

> 플레이어가 비정형 화물을 시장 그리드와 기차 그리드 사이에서 옮기는 바로 그 순간에, 공간 적합성·인접 시너지·현재 거래가·알고 있는 타 도시 기회·이동 비용을 어떻게 한 화면에서 비교하게 할 것인가?

최종 산출물은 사례 모음이 아니라, 현 프로젝트에 적용할 **권고 레이아웃 1안과 구현 변경 명세**다.

## 2. 조사 목표

### 2.1 1차 목표 — 직접 비교할 수 있는 레이아웃 찾기

다음 조건에 가까운 게임을 우선 찾는다.

1. 크기나 모양이 다른 아이템을 칸 단위로 배치·회전한다.
2. 한 그리드에서 다른 그리드로 아이템을 자주 옮긴다.
3. 옮기는 행위가 구매·판매·보관·장비·제작 중 하나의 경제적 결정을 동반한다.
4. 아이템의 위치·인접·방향이 가치나 성능에 영향을 준다.
5. 플레이어가 현재 장소와 다른 장소의 가치 차이를 판단한다.

다섯 조건을 모두 만족하는 사례가 드물 수 있으므로, 한 게임에서 억지로 답을 찾지 않는다. `공간 배치`, `그리드 간 이동`, `가격 비교`, `목적지 선택`을 잘 푼 서로 다른 사례를 조합한다.

### 2.2 2차 목표 — 현 UI의 정보 우선순위 재정의

구매·판매 순간에 필요한 정보를 아래 네 층으로 나누고, 무엇을 상시 노출하고 무엇을 선택·호버·드래그 중에만 보여 줄지 정한다.

- **즉시 판단**: 살 가격/팔 가격, 보유 자금, 들어갈 자리, 거래 가능 여부
- **배치 결과**: 적용·해제되는 시너지, 정산 후 가치 변화, 영향을 받는 이웃
- **여정 판단**: 알려진 도시의 가격/등급, 이동 시간·운임, 유통기한·의뢰 기한
- **상세 설명**: 태그 규칙, 성장·번식·보존·가공 규칙, 과거 기록

정확한 타 도시 시세를 무조건 노출하면 소문·탐색 루프를 무너뜨릴 수 있다. 조사에서는 `정확한 값`, `범위`, `등급/추세`, `미확인`의 네 정보 수준을 별도로 비교한다.

### 2.3 3차 목표 — 배치 조작의 마찰 줄이기

다음 조작을 사례별로 비교한다.

- 드래그 중 원래 자리, 잡은 모양, 회전 방향, 놓을 수 있는 칸의 표시
- 유효/무효 드롭과 실패 이유
- 구매 전 배치 미리보기와 구매 후 확정의 순서
- Ctrl+클릭 같은 빠른 이동, 자동 빈자리 탐색, 되돌리기
- 보드 간 셀 크기·정렬·거리와 커서 이동량
- 시너지 변화의 화살표·외곽선·수치 표시
- 판매 시 사라지는 아이템과 시장에 남는 아이템의 구분

### 2.4 최종 목표 — 조사 결과를 실제 UI 개편으로 연결

권고안은 다음 구현 단위를 특정해야 한다.

- 바꿀 프리팹과 유지할 프리팹
- View/Presenter/Input의 책임 변화
- 필요한 거래·시너지 미리보기 데이터
- 새 아이콘·색·상태 표현
- 입력 우선순위와 툴팁/Z-order 영향
- 플레이 검증 시나리오와 로그 항목

## 3. 고정 조건과 재검토 가능한 조건

### 유지해야 하는 제품 조건

- 핵심 루프는 `도시에서 구매 → 기차에 배치 → 이동·정산 → 다른 도시에서 판매`다.
- 기차와 시장 모두 비정형 아이템을 담는 그리드다.
- 아이템의 위치와 인접 관계가 가치에 영향을 준다.
- 가격 정보의 일부는 방문·소문·의뢰를 통해 알게 된다.
- 여러 화차를 선택·관리한다.
- PC 마우스·키보드와 드래그 중심 조작을 쓴다.
- UI 원본은 `Assets/Art/UI/`의 프리팹이며 런타임 UI 동적 생성은 하지 않는다.

### 조사로 바꿀 수 있는 조건

- 좌측 기차/우측 시장이라는 고정 분할
- 시장과 기차 보드의 상대 크기와 위치
- 정보 열, 툴팁, 하단 화차 바의 역할
- 가격·시너지·여정 정보의 상시 노출 범위
- 구매·판매의 확정 단계와 빠른 이동 조작
- 지도·수첩·상성표를 여는 방식
- 한 화면에서 다루는 화차 수와 전환 방식

|---|---|

## 5. 게임별 관찰 프레임

각 게임은 설명문만 읽지 않고 아래 화면 상태를 증거로 남긴다.

1. **평상시**: 아무 아이템도 잡지 않은 거래/정리 화면
2. **아이템 선택**: 가격·설명·시너지·목적지 정보가 나타난 상태
3. **드래그 중**: 원자리, 고스트, 유효/무효 칸, 회전, 영향 대상 표시
4. **드롭 직전/거래 미리보기**: 비용과 배치 결과를 확정하기 전 상태
5. **거래 직후**: 돈·재고·가치·되돌리기 피드백
6. **목적지 선택**: 가격 차이와 시간·운임·위험을 비교하는 화면

각 상태에서 다음을 기록한다.

- 그리드의 위치·크기·셀 수·화면 점유율
- 두 그리드 사이 거리와 셀 크기 일치 여부
- 상시 보이는 핵심 수치 수
- 가격/시너지/경로 정보를 보기까지 필요한 클릭·호버 수
- 툴팁·고정 정보 열·오버레이의 역할
- 드래그 중 가려지는 정보와 커서 이동 거리
- 색만으로 전달하는 상태와 텍스트/모양으로 중복 전달하는 상태
- 취소·되돌리기·빠른 이동의 방식
- 잘된 점, 실패 가능성, Trainventory에 옮길 때의 조건

화면 주장은 스크린샷이나 영상 타임스탬프를 근거로 하고, 버전·플랫폼·해상도·출처 URL·확인일을 함께 적는다. 오래된 버전과 현재 버전을 섞지 않는다.

## 6. 비교 평가 기준

심층 조사 사례와 이후 레이아웃 안을 같은 기준으로 평가한다.

| 기준 | 가중치 | 성공 조건 |
|---|---:|---|
| 핵심 루프 적합성 | 25 | 구매·배치·이동·판매의 연결을 끊지 않는다 |
| 두 그리드 이동 명료성 | 20 | 출발·도착·유효성·확정 결과를 오해하지 않는다 |
| 가격 판단력 | 20 | 현재 거래와 알려진 미래 기회를 빠르게 비교한다 |
| 시너지 판단력 | 15 | 배치 전후의 영향 대상과 가치 변화를 읽는다 |
| 정보 과부하 억제 | 10 | 공간 퍼즐이 숫자표에 묻히지 않는다 |
| 현 프로젝트 구현 적합성 | 10 | 프리팹·입력·데이터 계약 안에서 단계적으로 적용 가능하다 |

점수는 결론을 자동으로 정하는 숫자가 아니라, 서로 다른 장점을 같은 언어로 비교하기 위한 장치로 쓴다.

## 7. 핵심 사용성 시나리오

권고안과 프로토타입은 최소 다음 과제를 통과해야 한다.

1. **구매**: 시장의 2×3 화물을 고르고, 현재 화차에 들어가는지와 구매 후 시너지 변화를 확인한 뒤 산다.
2. **재배치**: 다른 화차 또는 같은 화차의 위치로 옮기며 손익이 좋아지는 이유를 확인한다.
3. **판매**: 현재 판매가, 매입 당시/기본 가치, 알려진 다른 도시 기회를 비교해 지금 팔지 결정한다.
4. **여정**: 유통기한·의뢰 기한·운임·이동 시간을 함께 보고 다음 도시를 고른다.
5. **오류 복구**: 잘못된 드롭·공간 부족·잔액 부족·거래 불가 시간에서 이유를 알고 원상태로 돌아온다.

평가 지표는 과제 완료 시간, 필요한 클릭/호버 수, 무효 드롭 수, 가격·시너지 오판, 화면 전환 수, 사후 설명 가능 여부다.

| 구현 영향도 | 파일·데이터·입력·아트·테스트 변경 목록 | 작업 단위와 선행조건을 제시함 |
| 검증 결과 | 프로토타입/구현의 시나리오별 결과 | 치명적 막힘과 회귀가 없음 |

레이아웃 3안은 반드시 다음 범위를 갖는다.

- **보수안**: 현재 좌우 구조를 유지하며 정보 계층과 드래그 피드백만 개선
- **중간안**: 거래 중에만 시장과 기차를 대칭/근접 배치하고, 평상시 역 화면은 유지
- **재구성안**: 구매·배치·가격·목적지 판단을 하나의 거래 작업 공간으로 재설계

## 9. Orca orchestration 실행 계획

프로젝트 프로필은 `.orca/orchestration-profile.json`을 사용한다. 현재 `max_parallel=2`이므로 아래 DAG도 동시 작업 두 개를 기준으로 한다. 모든 작업이 최종 결정의 선행 경로에 있으므로 장기 실행 워커는 쓰지 않는다.

| ID | 작업 | 티어 | 의존성 | 기대 결과 |
|---|---|---|---|---|
| R0 | 현 프로젝트 UI·핵심 과제 감사 | medium | 없음 | 현재 레이아웃, 프리팹, 입력, 데이터와 마찰 가설 |
| R1 | MobyGames 후보 30개 1차 선별 | low | 없음 | 점수·근거·심층 후보 12~16개 |
| R2 | A/B/C군 화면 상태 심층 조사 | high | R1 | 공간 시너지와 두 그리드 이동 패턴 |
| R3 | D군 및 가격·목적지 정보 심층 조사 | medium | R1 | 시세·운임·시간·미확인 정보 패턴 |
| R4 | 패턴 통합과 레이아웃 3안 | high | R0, R2, R3 | 3안 와이어프레임, 평가표, 권고 초안 |
| R5 | 구현 가능성·영향도 검토 | medium | R4 | 프리팹/스크립트/데이터 변경 지도와 단계별 비용 |
| G1 | 사용자 결정 게이트 | 이 세션 | R4, R5 | 구현할 안과 허용 범위 확정 |
| I1 | 선택안 프로토타입/구현 | high | G1 | 실제 프로젝트 반영 |
| V1 | 사용성 시나리오·회귀 검증 | medium | I1 | 결과 기록, 남은 문제, 보정안 |
| V2 | 최종 독립 리뷰 | high | V1 | 목표 대비 누락·과잉 정보·조작 회귀 확인 |

실행 순서는 `R0+R1 → R2+R3 → R4 → R5 → G1 → I1 → V1 → V2`다. 조사 워커는 문서와 캡처만 수정하고, `G1` 전에는 프리팹·씬·런타임 코드를 바꾸지 않는다.

### 워커 공통 브리프

모든 워커 지시에는 다음을 포함한다.

- **목표**: 어떤 결정을 지원하는 조사/구현인지
- **입력과 범위**: 볼 문서, 게임, 버전, 파일과 보지 않을 범위
- **방법**: 캡처해야 할 화면 상태와 비교 기준
- **출력**: 저장할 문서/이미지, 표 스키마, 파일 경로
- **완료 증거**: 출처 URL, 타임스탬프, 변경 파일, 검증 결과
- **금지**: 근거 없는 기억 보완, 서로 다른 버전 혼합, 조사 단계의 UI 코드 변경

## 10. 결정 게이트

### 조사 완료 게이트

아래 조건을 모두 만족해야 레이아웃 권고를 확정한다.

- 30개 이상 후보를 같은 기준으로 선별했다.
- 12개 이상을 화면 상태별로 깊게 조사했다.
- 두 그리드 이동, 위치 시너지, 가격·목적지 비교 각각에 최소 3개의 근거 사례가 있다.
- 직접 유사 사례가 부족하면 그 사실과 조합해야 할 대체 패턴을 명시했다.
- 레이아웃 3안 모두 동일한 핵심 시나리오와 평가표로 비교했다.
- 권고안의 각 주요 결정이 최소 한 개의 외부 증거와 한 개의 현 프로젝트 제약에 연결된다.

### 구현 착수 게이트

- 선택한 안과 개편 범위를 사용자가 확인했다.
- 유지할 핵심 루프와 공개 가능한 가격 정보 수준이 명시됐다.
- 수정 파일과 프리팹 충돌 범위를 확인했다.
- 드래그·툴팁·지도·수첩의 입력/Z-order 회귀 계획이 있다.
- 구현 전후를 비교할 사용성 시나리오와 기록 방식이 준비됐다.

### 최종 완료 기준

조사는 문서 작성으로 끝나지 않는다. 선택한 레이아웃이 프로젝트에 반영되고, §7의 다섯 시나리오에서 공간·가격·시너지·목적지 판단이 막히지 않으며, 기존 구매/판매·빠른 이동·회전·지도·수첩 흐름에 치명적 회귀가 없을 때 완료한다.

## 11. 이번 조사에서 하지 않을 것

- 전체 비주얼 아트 스타일·세계관 아트 방향 재설계
- 경제 밸런스 수치 자체의 재조정
- 새로운 거래 규칙이나 시너지 규칙 추가
- 모바일·게임패드 UI 최적화
- 근거 수집 전 프리팹을 먼저 고치는 작업

필요성이 발견되면 별도 후속 과제로 제안하되, 이번 레이아웃 결정과 섞지 않는다.
