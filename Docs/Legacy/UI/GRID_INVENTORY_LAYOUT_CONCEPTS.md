# 그리드 인벤토리 거래 UI — 1920×1080 레이아웃 3안 (R4)

> 작성일: 2026-11-18 · 범위: 문서 설계만 · PC 마우스·키보드
> 상태: **중간안 B를 우선 프로토타입 후보로 권고 / 최종 선택·구현 승인·사용성 검증 아님**
> 유일한 작성 파일: `Docs/Research/GRID_INVENTORY_LAYOUT_CONCEPTS.md`

## 1. 판단 요약과 증거 경계

**문제는 두 보드의 존재보다, 잡은 화물의 현재 거래·배치 결과·알고 있는 목적지 기회가 서로 다른 문맥으로 흩어지는 데 있다.** 현 구조의 같은 셀 크기와 세로 중심은 보존한다. 세 안 모두 기차 5×5와 시장 7×6를 동시에 보여 주며, 가격·시너지·여정은 서로 다른 값으로 표시한다.

- **A 보수안 — 기존 좌우 구조 + 우측 선택 비교 열:** 가장 작은 배치 변경. 먼저 고정 정보가 실제로 도움이 되는지 확인하기 좋다.
- **B 중간안 — 거래 중 근접 두 보드 + 고정 견적 도크:** 역의 일상 화면은 유지하고 시장에서만 요약 띠·보드·정보 열을 재배치한다. 우선 권고 후보다.
- **C 재구성안 — 시장→기차 작업대 + 여정 선반:** 시장을 왼쪽, 기차를 가운데로 바꾸고 아래 여정 비교를 상시 유지한다. 거래와 경로의 연결은 강하지만 학습·입력·프리팹 변경 비용이 가장 크다.

### 아직 닫히지 않은 조사 게이트

- R1: MobyGames 접근 403으로 등재 대조 미완료. 30개는 후보 목록이지 검증된 그리드 사례 30개가 아니다.
- R2: A4/B3/C1 정지 화면. B≥4, 엄밀한 인접 시너지 3건, 실제 이동·드래그·거래 후 연속 상태 미달.
- R3: D 비교군 4개가 있으나 통합 가격·목적지 비교 화면 3건 확보는 미달.
- 따라서 **3안 작성은 완료할 수 있어도 조사 완료·최종 권고 확정·구현 착수 게이트는 통과하지 않았다.** 점수는 다음 실험의 우선순위다.

## 2. 세 안 공통 계약

### 2.1 화면·표현

- 좌상단 원점, `(x, y, w, h)`는 기준 UI px. `x+w≤1920`, `y+h≤1080`이다. ASCII는 관계도이며 축척 도면이 아니다. 정확한 규격은 좌표표를 따른다.
- 화면 여백 40, HUD `(40,16,1840,60)`, 상태 줄 `(40,92,1840,32)`, 본문 `(40,140,1840,780)`, 하단 고정 UI `(40,936,1840,128)` 유지.
- 기차와 시장 셀은 모두 **97.6px**. 기차 488×488, 시장 683.2×585.6. 보드 외곽 면적 합계 약 30.8%를 유지한다. 셀은 시각적 8pt 규칙의 예외인 기존 좌표 계약을 승계한다.
- 기차는 감사의 현행 기준 25칸이다. 화차별 비활성 칸은 모델에 따라 별도 표시/포인터 제외하며, 빈칸 수만으로 비정형 화물이 들어간다고 보장하지 않는다.
- 본문 16pt, 제목 24/20pt, 보조 14pt, 배지 12pt. 행이 넘치면 본문 스크롤 또는 `외 N개`와 상세 보기. 핵심 금액·실패 이유를 말줄임/작은 글자로 숨기지 않는다.
- 표시용 고스트·영향선·견적은 레이캐스트를 받지 않는다. 보드 위 유일한 드래그 고스트는 실제 점유 모양을 따르며, 출발지에는 원자리 표시만 남긴다.
- 색 외에 `✓ 가능 / × 겹침 / ! 거래 불가`, `+/-`, 제목·테두리 모양을 중복 사용한다. 선택 테두리색을 유효성색과 같은 의미로 쓰지 않는다.

### 2.2 같은 수치를 같은 뜻으로 쓰기

| 층 | 공통 표시 | 주의 |
|---|---|---|
| 즉시 현금 | `구매 지출 -100`, `판매 수입 +90`, `자금 200 → 100` | 현재 행동에 맞는 매입/매도 하나를 우선. 양방향 호가가 필요하면 각각 라벨을 붙임 |
| 현재 물품 | `기본 가치`, `현재 가치`, `실제 매입원가` | 원가 데이터가 없으면 `기록 없음`; 기본 가치로 대신하지 않음 |
| 배치 결과 | `다음 정산 가치 전→후`, `변화 Δ`, 출발/도착 이웃 영향 | Δ를 즉시 현금 수익에 더하지 않음. 현재 평가와 미래 정산을 같은 시점끼리 비교 |
| 여정 | `관측 판매 기회`, `이동 시간`, `운임`, `도착 시 화물/의뢰 기한` | 미래 가치가 곧 목적지 판매가는 아님. 경로 거리값을 소요 턴으로 그대로 표시하지 않음 |
| 상세 | 태그·규칙·성장/번식/보존 설명 | 평상시 호버/상세에서 제공. 드래그 중 긴 중첩 툴팁은 숨김 |

`100/90/200` 등의 숫자는 표시 형식 예시이며 경제 밸런스나 현재 테이블의 값이 아니다. 신선도는 현행 규칙이 고정이면 `변화 없음`으로 표시하고 임의의 부패 시뮬레이션을 만들지 않는다. 새 위험/중량/마모 규칙도 추가하지 않는다.

### 2.3 알려진 목적지 정보만 보여 주기

| 지식 수준 | 표기 예 | 계산/정렬 계약 |
|---|---|---|
| 정확 관측값 | `도시 A · 관측 매도가 140 · 방문 · 2일 전` | 과거 값임을 명시. 현재/도착 확정가로 부르지 않음 |
| 범위 | `도시 B · 120–160 · 소문 · 1일 전` | 실제 공개된 경계가 있을 때만 범위 계산. 임의 중앙값 금지 |
| 등급/추세 | `도시 C · 비쌈 ↑ · 소문` | 숫자 순익 환산 금지. 정성적 기회로 분리 |
| 미확인 | `도시 D · 시세 미확인` | 0원/적자로 처리하지 않음. 알려진 경로의 시간·운임은 독립 표시 가능 |

선택한 화물에 대해 기본 2개, C에서는 최대 3개의 후보만 요약한다. 후보가 없으면 `알려진 판매 기회 없음`이며 숨은 시세로 상위 후보를 뽑지 않는다. 숫자 후보와 정성 후보는 구분하고, 기본 순서는 사용자 고정 후보→알려진 경로 순으로 둔다. 같은 수준·같은 시간 기준의 비교가 가능할 때만 숫자 정렬을 허용한다.

- 신규 구매의 `추정 여정 차익 = 목적지 추정 매도가 - 현재 구매가 - 해당 여정 운임`.
- 이미 가진 화물의 `지금 팔기 대비 보유 기회 차이 = 목적지 추정 매도가 - 현재 매도가 - 추가 운임`.
- 두 식은 대체 관계다. 매입원가를 양쪽에 다시 빼지 않는다. 여러 화물의 추정치를 합산할 때 공통 운임을 중복 차감하지 않는다.
- 현재 데이터로 목적지 판매 견적/원가/기한을 계산할 수 없다면 해당 값을 `계산 불가`로 표시한다. 테이블 접근 가능성을 정보 공개 권한으로 오인하지 않는다.

### 2.4 조작·확정·복구 정책

세 안의 비교에서 거래 규칙 변경 효과를 섞지 않기 위해 **유효 위치에서 놓기=즉시 거래 확정**을 유지한다. `드롭 직전`은 잡은 채 유효 후보를 가리키는 상태이며 별도 확인 버튼 단계가 아니다. GW6의 판매액/취소는 결과와 취소 경계를 명확히 하자는 근거이지, 모든 판매에 모달을 추가하자는 근거가 아니다.

1. 선택 대상은 드래그 시작 때 고정된다. 단순 클릭을 추가할 경우 감사의 ‘드래그 임계값 없음’을 고려하여, 이번 후보의 필수 입력으로 삼지 않는다. 선택 핀 버튼/키와 클릭 판별은 R5에서 별도 결정한다.
2. 드래그 중 회전은 기존 잡은 칸 기준을 유지한다. 우클릭 회전이 동시에 뒤로가기를 실행하지 않는다.
3. 무효 후보는 `공간 불가`와 `거래 불가`를 나눠 표시한다. 놓으면 돈·원본 좌표를 바꾸지 않고 마지막 사유를 남긴다. 화면 밖/포커스 상실/Esc 취소도 원본 유지다.
4. 평가·확정은 서비스의 같은 견적/규칙을 사용한다. 가격·자금·영업·대상이 달라졌으면 재평가 후 실패/갱신하며 낡은 미리보기대로 강행하지 않는다.
5. Ctrl+클릭은 기존 자동 빈자리 탐색·즉시 거래를 유지한다. 수동 후보와 다른 위치면 확정 후 **실제 위치/결과**를 표시한다. 전체 최적 시너지 자동 탐색을 약속하지 않는다.
6. 확정 후 범용 undo는 제공한다고 쓰지 않는다. 기존 구매취소 경로가 있다면 그 조건만 별도 안내하고, 판매·시간 진행까지 복원하는 기능으로 확대하지 않는다.
7. 지도·수첩 열기와 거래 드래그는 중첩하지 않는다. 드래그 중 해당 열기 버튼을 비활성/안내하고, 먼저 취소하거나 놓도록 한다. 이는 기존 입력 대비 제안 변경이므로 R5/회귀 검토 대상이다.
8. 기존 Esc 우선순위(검색/메뉴/이동 확인→드래그→상성표/지도/수첩→역 복귀→일시정지)를 보존한다. 지도 중 시장 거래는 차단하고, 기차 정리는 현행 허용 범위를 따른다. 이동 확인/연출은 기차도 차단한다.

### 3.2 여섯 상태

| 상태 | 가격 | 공간·시너지 | 목적지 | 숨김/확정·복구 |

### 5.3 강점·약점·적용 비용

- **강점:** 알려진 기회와 이동 비용을 거래의 상시 비교 대상으로 만든다. 단순 후보 비교는 지도 전환 없이 가능하다. 소유권은 제목·위치·외곽선으로 명시한다.
- **약점:** 기존 기차 왼쪽 습관을 뒤집는다. 58px 선반에는 정보 생략이 불가피하고, 긴 한국어·3개 후보·배지의 과밀 위험이 크다. 기차가 중앙으로 옮겨 지도·시설·화차 바 연계 비용이 커진다.
- **비용: 높음.** 역 상태 머신/지도 배치/고정 UI 참조/입력 대상/선택 복원을 함께 재검토해야 한다. 단순 프리팹 위치 수정이 아니다.
- **근거 연결:** M1 소유/거래 의미 분리, P3 도시 선택→상세 조건, X1 선택 결과 유지, R2 시간/비용 규칙→작업대+선반 조합. **원작에 이 완성 레이아웃이 존재한다는 주장이 아니라 합성 설계**다. 현 프로젝트의 소문 공개·단일 trainView·분리 Canvas가 비용/표시 한계를 결정한다.

### 공통 합격 기준과 기록

- 구매: 실제 가능한 공간을 찾고 지출·거래 후 잔액·배치 효과를 설명한다. 확정 결과와 마지막 유효 미리보기가 일치한다.
- 재배치: 출발과 도착의 이득/손실을 함께 설명한다. 화차 전환 중 원본·선택·잡은 칸이 보존된다.
- 판매: 기본 가치/매입원가/현재 판매 수입/도착 예상 기회를 구별한다. 미확인 시세를 숫자 이익으로 설명하지 않는다.
- 여정: 시간·운임·화물/의뢰 기한을 확인하고 실제 이동은 기존 확인 절차로만 실행한다.
- 복구: 원인별 이유를 말할 수 있고 무효/취소 후 돈·재고·좌표에 변화가 없다. 포커스 상실/화면 밖/회전/Ctrl도 별도 회귀 검사한다.
- 기록: 과제 완료 시간, 클릭/호버/화면 전환 수, 무효 드롭 수, 가격/시너지/기한 오판, 사후 설명, 돈/좌표 정합성. 경로가 다른 과제는 시작/종료 이벤트를 먼저 통일한다.
- 우선 통과 조건은 치명적 오류 0건이다. 속도 개선 임계값은 플레이어 수·반복 횟수·순서 교차 실험을 설계한 뒤 정한다. 지금 ‘몇 % 개선’ 수치를 만들지 않는다.
