# 맵 데이터와 화면 구성

맵(교역 지도) 관련 사실의 위치를 한 곳에 모은 참조 문서다. 다른 세션이 기획서를 읽지 않아도 **어디서 무엇을 고쳐야 하는지** 알 수 있게 저장소 좌표만 적는다. 게임 규칙·의도는 [게임 기획서](<../게임 기획서.md>) 3장·7장, 테이블 일반 계약은 [TABLES](TABLES.md), 시간 구현 계약은 [게임 시간 시스템](<게임 시간 시스템.md>)이 원본이다.

## 1. 맵을 구성하는 저장소

맵은 **테이블 4종 + 지도 프리팹 + 지형 배경 이미지 + 시간 계산 코드**로 구성한다.

| 저장소 | 경로 | 맵에서 담당하는 것 |
|---|---|---|
| 노드 테이블 | `Assets/Resources/Tables/PuzzleTableData.json` | 마을 31·지역 7·`startCity`·`planningTargetCityId`, 각 마을의 시장 격자와 재고 |
| 노선 테이블 | `Assets/Resources/Tables/PuzzleRouteTableData.json` | 방향 노선 100항목의 표시 선과 같은 `points`·요금용 `distance`·`cost`·`highSpeed`, 거리·적재 단가 |
| 시간 테이블 | `Assets/Resources/Tables/PuzzleTimeTableData.json` | 낮 길이·시작 시각·휴식·거리당 이동 시간(`hoursPerDistance`) |
| 시간·판정 테이블 | `Assets/Resources/Tables/PuzzleTradeTableData.json` | `deadlineHours` 336(14일)·`debtCityId` |
| 지도 프리팹 | `Assets/Art/PuzzleWorldMap.prefab`<br>guid `ab2441b70b1c4490988e4eb2ca06784a` | 화면 좌표·선분·라벨 등 모든 시각 요소, 그리고 Presenter/View/NodeView 컴포넌트 자체 |
| 시간 계산 | `Assets/Scripts/Runtime/Core/PuzzleTimeManager.cs` | 실시간 시계의 정수 게임 시간·야간 판정·노선 이동 시간(거리 × `hoursPerDistance`). 밸런스는 시간·노선 테이블이 원본 |

- 맵 UI 스크립트(PuzzleMapPresenter 1·PuzzleMapView 1·PuzzleMapNavigation 1·PuzzleMapTravelView 1·PuzzleMapNodeView 31)는 **전부 프리팹 안에 자기 완결로 들어 있다.** `Assets/Scenes/Game.unity`는 프리팹 인스턴스 하나를 사용한다.
- `Game.unity`의 인스턴스는 루트 RectTransform(fileID 700011)에 프로퍼티 오버라이드 11개(pivot·anchor·sizeDelta·localScale)를 저장한다. 노드·선분·라벨 좌표는 전부 프리팹에 있고 씬 오버라이드는 없다.
- 배경 이미지의 지리 원본은 `rail_map_geography_seed_20265146.json`이며, `Game.unity`는 지도 프리팹 인스턴스를 사용한다.
- 역 연결은 생성 데이터 `ProjectWorldData.json`(seed 20265146)의 `projectMapData` 43개에서 시작해 Map Editor로 고쳤다(현재 왕복 51개, R01~R52 중 R29 없음. R52는 메르트–세르그라드). 역 좌표와 노선 모양도 Map Editor로 편집한 값이다. 표에 들어갈 값은 `targetTables`가 지정한 3개 테이블에 넣고, 표시 좌표와 노선 폴리라인은 [rail_map_layout_seed_20265146.json](rail_map_layout_seed_20265146.json)에 따로 저장한다. 원본 `ProjectWorldData.json`(1.5MB, 지형 배열 포함)은 저장소에 넣지 않고 위 파일만 보관한다. 지역 구분·태그 경제·시장 격자는 생성 데이터 대신 기존 테이블 값을 유지한다.
- 프리팹에도 노드 좌표·노선 선분·시간 라벨·환승 표시를 적용해 저장했다. `Tools/MyJG/Apply Rail Map Layout (seed 20265146)`으로 같은 레이아웃을 다시 적용할 수 있다(§4).

## 노선 데이터 무결성

- 실행 표의 100개 방향 연결과 레이아웃의 50개 철도, 지도 프리팹의 노선 시간 50개 참조가 일치한다. 자기 연결·중복 방향·누락 도시·끊긴 참조가 없고 모든 역이 출발지에서 도달 가능하다.
- 왕복 점 배열은 역순으로 일치하며 거리·고속 여부도 같다. 폴라인 끝점은 역 좌표와 일치하고 실행 표와 레이아웃의 원본 `points`·거리·기본요금이 일치한다. `displayPoints`를 노선 표 `points`와 왕복 테이블에 동기화한다(그리기 전용). 기본요금은 모두 3, 노선 거리는 1~7이다.
- 현재 역과 직접 연결된 노선만 이동 시간 표시 대상이며 자금 부족 여부로 숨기지는 않는다. 다른 역의 선택·호버는 표시 대상을 확장하지 않는다. 줌·겹침 회피 조건은 유지한다.
- 노선 거리 분포는 1 26개 · 2 19개 · 3 4개 · 6 1개 · 7 1개다(이동 시간은 ×3시간). 거리가 운임의 거리 항도 맡는다. 구조 확인은 경제/야간 동선의 플레이 밸런스 검증을 뜻하지 않는다.

- 공업 지역 안 연결은 R06·R11·R20·R23·R35·R44(포르베르↔카르포트)·R45(에른아 공업역↔포르베르)·R51(헤일포드↔노르노바)이다.
- 지도 재열기 시 확대 배율과 이동 위치를 유지하며 최초 열기·전체 보기 요청 때만 전체 배치를 맞춘다.

### 지명과 역의 대응

- 노드의 cityId로 테이블 이름을 표시하고, 위치와 클릭/호버도 같은 노드 ID를 사용한다. 다르안은 city.daran, 세르그라드는 city.sergrad다. 줌 시 다른 역 쪽으로 배치된 지명이 잘못 연결되어 보이지 않도록 각 지명에 해당 역까지 안내선을 붙인다.
- 최초에는 프리팹의 이름 배치 방향, 이후에는 직전 성공 방향을 먼저 사용한다. 공간이 없으면 테이블의 탐색 거리/간격 안에서 다른 방향·거리를 찾는다. 이름·배지·역 링·현재 위치 테두리는 실제 RectTransform/텍스트 크기로 예약하고, 안내선이 다른 역·이름·안내선을 가로지르는 후보는 제외한다.
- 지역의 mapLabelPriority와 역의 mapLabelImportance가 기본 가중치다. 여기에 현재/호버/목표/직결/환승/기타 중 해당하는 상태 가산점을 더한다. 현재와 호버 가산점은 기본 중요도보다 높게 설정했다. 같은 점수는 cityId 순으로 결정한다.
- 85% 미만에서는 중요도 200 이상 핵심 역과 현재/호버/목표 역의 이름을 우선 표시한다. 일반 역 표식은 유지하고 확대하면 일반 역명도 배치한다. 핵심 역은 더 큰 굵은 글씨로 구분한다. 기준 임계값·폰트 크기 및 상태 가산점은 지도 프리팹(`Assets/Art/PuzzleWorldMap.prefab`)의 `PuzzleMapView` 컴포넌트 값에서 수정한다.
- 100% 미만에서는 같은 지역에 이미 표시한 이름 수 × regionCrowdingPenalty를 가중치에서 빼 다음 후보를 고른다. 한 지역이 이름 공간을 먼저 차지하지 않게 하며 실패한 배치는 지역 표시 수에 포함하지 않는다. 감점 수치와 적용 줌 범위도 지도 프리팹에서 수정한다.
- 이름끼리·안내선끼리는 겹치지 않는다. 일반 역은 후보가 없으면 이름만 생략하고 역은 유지한다. 필수 이름(핵심 역·현재·목표·선택 역)은 빈자리가 없으면 다른 필수 역 표식만 피하고 일반 역 표식 위에 배치해, 최소 줌(35%)에서도 지역별 핵심 역 이름이 모두 보인다(에디트 모드 배치 계산으로 35~100% 확인, 화면·플레이 확인은 하지 않음). 호버 시 이름을 우선 배치하고 상세 정보에도 같은 cityId를 표시한다. 지역마다 연결 수가 가장 많은 역을 초기 핵심으로 지정했으며 현재 가중치는 테이블에 명시돼 있다. 노선 모양을 바꿔도 중요도가 자동으로 바뀌지는 않는다.
- LabelConnector Image 30개는 프리팹의 각 노드에 저장하며 런타임에 만들지 않는다. 탐색 간격·거리·선 두께는 지도 프리팹(`Assets/Art/PuzzleWorldMap.prefab`)의 `PuzzleMapView` 컴포넌트 값에서 수정한다.
- 축소 시 입력은 실제 역 표식 영역으로 제한한다. 두 표식이 겹치는 위치는 더 가까운 역이 입력을 받고, 같은 거리이면 cityId 순으로 결정한다. 이전 역의 늦은 포인터 이탈이 새 역의 설명을 지우지 않도록 이탈 ID도 확인한다.
- 줌·이동·화면 크기 변경 때 다시 배치한다. 변경 후 플레이/화면 확인은 수행하지 않았다.

### 표시 선과 시간·수동 라벨 계약

- 노선 거리는 노선 표 `distance` 정수가 원본이며 운임의 거리 항과 이동 시간에 쓴다. 맵/경유점 에디터는 displayPoints를 레이아웃 points와 왕복 노선 테이블 points에 동기화하지만 선 모양을 바꿔도 거리는 바뀌지 않는다. 선 길이로 다시 맞추려면 노선 거리 자동 계산 버튼을 쓴다.
- labelManual=true인 라벨은 자동 배치·프리팹 역 겹침 보정·런타임 위치 이동에서 제외한다. 좌표 입력/드래그는 자동으로 고정하며 기존 저장 좌표도 고정으로 보존했다. 실행 화면은 고정 라벨 영역부터 예약해 역명을 피하도록 배치한다. 화면 밖·역 표식·다른 고정 라벨과 충돌하면 임의로 옮기지 않고 숨긴다.
- 선택 노선의 자동 배치는 해당 고정을 해제한다. 전체 자동 배치는 고정되지 않은 것만 처리하며 `고정 해제 후 전체 자동 배치`로 명시적으로 전체를 풀 수 있다. 라벨 좌표는 저장 후 재적용해도 같은 값을 쓴다.

### 통합 맵 에디터

- `Tools/MyJG/Map Editor`에서 역·노선·지역·지형·공통 설정을 편집한다. 지형 탭은 지형 종류 또는 지역을 붓(반경 칸 단위)으로 칠하며 획 하나가 Undo 하나다. 저장하면 지형 원본·지형 이미지·지도 프리팹 지형 영역을 함께 갱신하고 실패 시 복구한다. 역 탭의 `주요 역` 토글(켜면 기준값, 끄면 기준-1)과 지역 탭의 소속 역 중요도 목록으로 지명 중요도를 편집한다(기준은 지도 프리팹 `PuzzleMapView.majorStationThreshold`). 창 내부에 왼쪽 목록·가운데 지도 캔버스·오른쪽 속성 편집을 배치했다. 프리팹/Scene을 열지 않고 지형 원본과 초안의 역·역명·노선·선택 경유점·선택적 시간을 직접 렌더링하며, 필드 변경과 드래그를 즉시 반영한다.
- 캔버스에서 역 표식을 클릭/드래그해 선택·이동하고 선을 클릭해 노선을 선택한다. 선택 노선의 사각 경유점을 드래그해 표시 경로를 편집한다(노선 거리는 그대로). 시간 표시를 켜면 선택 노선의 턴 라벨 중심도 드래그할 수 있다. 휠은 포인터 기준 확대/축소, 빈 곳 또는 중간/오른쪽 버튼 드래그는 지도 이동이다. `전체 보기`·`선택 보기`, 지형/격자/역명/시간 표시 토글을 제공한다. 역명은 겹치지 않는 후보 위치를 찾아 해당 역까지 안내선으로 연결한다.
- **역**: 이름·ID·지역·지명 중요도·환승역 표식·좌표를 수정한다. `ID 바꾸기`는 역·노선·레이아웃·시작/목표 역·마을 행동(`PuzzleCityActionTableData`)·상환 장소(`PuzzleTradeTableData`)의 참조를 함께 바꾸고, 저장 때 지도 프리팹 노드는 이름만 바꾼다. 지역을 바꾸면 같은 지역 역(특산 태그가 지역 생산 목록에 있는 역) 중 하나에서 특산 태그·태그 가격·시장 격자/고정 재고·지역 재고를 복사하며, `교역 설정을 지역 기준으로 맞추기`로 다시 맞출 수 있다.
- **시장·교역**: 구매/판매 허용·기본 배율, 특산 태그(지역 생산 태그 목록), 지역/일반 재고 설정(후보 화물 표시), 태그 가격 표(태그·구매%·판매 등급·우선순위 추가/삭제), 시장 격자 크기와 고정 재고(화물·x·y·회전, 격자 미리보기에 겹침/격자 밖 표시)를 편집한다. 판매는 `흔함/일반/귀함/희귀/사용자 지정` 중 하나를 고르고, 등급의 판매 배율은 `sellGrades`에서 표시한다. 흔함·일반·귀함을 선택하면 구매 배율을 등급 값으로 맞추고, 희귀·사용자 지정은 행의 구매 배율을 유지한다. 같은 태그 중복 추가와 흔함 특산 태그의 희귀 변경은 사유를 띄우고 막는다. 고정 재고 배치 ID는 `<역 ID>.stock.N`으로 자동으로 붙는다. 이 역의 테이블 오류를 패널 아래에 바로 보여 준다. 나머지 필드는 상세 JSON으로 수정한다.
- 추가는 선택 역의 시장·교역 설정을 복제한다. 새 역 이름을 넣으면 ID를 비워도 이름 로마자로 만든다(받침 없는 '으'는 모음을 빼 리오브루크 → `city.riobruk`). 삭제는 연결 노선도 제거하며 시작/목표/상환 역 삭제는 차단한다.
- **노선**: 기존 노선을 분류·고속선 템플릿으로 선택하고 출발/도착 역을 지정해 왕복 노선을 추가한다. 연결 역 변경·삭제, 왕복 노선 거리/고속 여부·방향별 기본요금·색 그룹·분류·시간 라벨 위치를 수정한다. 경유점은 표시에 사용하며 왕복 테이블에 역순으로 반영한다. 새 연결은 처음에 두 역 사이 직선으로 생성하며 기준 기본요금과 선 길이에 따른 노선 거리를 적용한다.
- **요금·노선 거리 자동 설정**: `공통 설정 → 노선 요금 일괄 설정`에서 기준 기본요금·거리 1당 지도 길이를 편집한다. 기준값은 PuzzleRouteTableData.defaultBaseCost(현재 3)와 pixelsPerDistance(100)이다. `전체 왕복 기본요금에 적용`과 `전체 노선 거리 자동 계산`은 초안만 갱신하며 Undo 가능하다. 노선별 길이·기존 거리→계산 거리 미리보기를 제공하고, 선택 노선의 속성에서도 선 길이로 거리를 계산할 수 있다. 거리는 displayPoints(없으면 points)의 전체 구간 길이 합 ÷ 기준 길이를 반올림(정확한 중간은 큰 쪽), 최소 1로 계산해 왕복과 레이아웃(`distance`)에 동일하게 기록한다. 줌·교차점 표시 틈은 계산에 영향을 주지 않는다. 표시 경로를 바꿔도 거리는 버튼을 누르기 전까지 그대로다.
- **역 이동**은 연결 노선 끝점을 함께 옮긴다. 노선 거리는 자동 계산 버튼을 누를 때만 바뀐다.
- **시간 라벨 자동 배치**: 선택 노선의 속성에서 `이 노선 시간 라벨 자동 배치`, 공통 설정에서 `전체 시간 라벨 자동 배치`를 사용한다. 역·노선·이름 변경 후 자동 재배치는 기본 켜짐이며 수동으로 옮긴 라벨은 고정해 유지한다. 드래그 중에는 배치를 미루고 놓을 때 한 번 계산해 같은 Undo 단위로 묶는다. 표시 경로의 길이상 중간을 우선하며 역 표식·기본 역명 영역·다른 시간 라벨·다른 노선을 피하는 후보를 탐색한다. 빈 공간이 없으면 기존 위치를 유지하고 해당 노선 ID를 알려준다. 배치는 지도 좌표로 저장되며 줌별 최종 겹침 처리는 런타임 지도의 기존 배치 규칙을 따른다.
- **지역**: 이름·지명 우선순위·물가, 소속 역 지명 중요도, 지역 재고 후보 화물(같은 재고 설정을 쓰는 모든 역에 적용)과 상세 지역 데이터를 수정한다. **공통 설정**: 시작 역·지도 목표 표식·거리당/적재 칸당 단가를 수정한다. 상환 장소는 별도 `PuzzleTradeTableData.debtCityId` 설정을 유지한다.
- 조작은 Undo/Redo 가능한 초안이다. `전체 저장 · 프리팹 반영`이 PuzzleTableData·PuzzleRouteTableData·PuzzleCityActionTableData·PuzzleTradeTableData·레이아웃·지형 JSON과 프리팹을 함께 갱신한다. 새 역은 기존 역 프리팹 구조를 복제해 nodes 참조까지 연결하며 삭제된 역·노선의 표시도 정리한다. 기존 도구의 미리보기는 통합 편집 창이 열려 있는 동안 숨긴다.
- 도구 막대의 `검증 오류 N`/`검증 통과`는 초안을 테이블 규칙(`TableManager.ValidateSources`, 콘솔 대신 목록으로 수집)으로 검사한 결과이며 누르면 전체 오류를 펼친다. 검증 오류가 있으면 파일을 쓰기 전에 저장을 막는다. 외부 파일 변경·프리팹의 미저장 편집·중복 ID/연결·잘못된 좌표 시에도 반영을 중단한다. 파일 기록/프리팹 반영 중 실패하면 원본을 복구한다. `초안 내보내기`로 세 원본의 초안을 별도 JSON에 보관할 수 있다. 저장은 초안 Undo 이력을 초기화한다.
- 통합 맵 에디터의 저장·캔버스 입력·플레이 확인은 수행하지 않았다. 기존 경유점 도구의 확인 범위는 아래와 같다.

### 기존 노선 모양·경유점 편집

1. `Tools/MyJG/Edit Rail Routes`를 연다.
2. `지도 프리팹 열기`를 누르거나 Game 씬의 PuzzleMapView를 편집 지도에 지정한다. sourceId와 출발/도착 이름으로 노선을 선택하고 `선택 노선 보기`로 2D Scene 화면을 맞춘다. Scene 창이 없으면 자동으로 열며, 지도 패널이 비활성이어도 역·전체 노선·선택 경유점을 편집용 미리보기로 표시한다.
3. 경유점을 Scene 핸들로 드래그하거나 창에서 좌표를 입력한다. 선택 점 다음에 추가/삭제, 격자 스냅, 선택적 시간 라벨 위치 편집을 지원한다. 출발/도착 역 좌표는 고정한다. Undo/Redo는 미저장 초안에 적용된다.
4. `저장하고 지도 프리팹 반영`을 누른다. 레이아웃 JSON의 해당 sourceId.displayPoints와 labelX/Y를 저장하고 기존 RailMapLayoutTool로 프리팹에 적용한다. 저장은 초안 Undo 이력을 초기화한다.

- 편집한 표시 경로를 레이아웃 points와 왕복 노선 테이블에도 동기화한다. 역 연결·운임·노선 거리·다른 메타데이터는 유지한다. 불러온 JSON의 알 수 없는 필드도 보존한다. 수동으로 옮긴 시간 라벨은 고정해 저장하고 역 겹침 보정에서 제외한다.
- 외부에서 레이아웃 파일이 바뀌거나 지도 Prefab Stage에 다른 미저장 변경이 있으면 적용을 막는다. 경유점 이동 중에는 씬/프리팹을 수정하지 않는다. 프리팹 적용 실패 시 이 창이 기록한 레이아웃 변경은 복구한다.
- 현재 연결의 모양만 편집하며 역 연결 추가/삭제는 제공하지 않는다. Unity 에디터 컴파일, 실제 메뉴/창 열기, 프리팹 연결, 경유점 드래그·추가·삭제와 Undo/Redo를 확인했다. 확인에 사용한 초안은 원상 복구했다. 저장/프리팹 반영과 플레이 확인은 수행하지 않았다.

### 표시 경로와 교차점

- 경유점이 있는 노선은 R03(2개)·R21·R22·R30·R31·R36(각 1개)이고 나머지는 두 역을 잇는 직선이다.
- 교차점의 틈은 비환승 교차를 나타낸다. 정차/이동 가능 여부는 역 표식과 실행 테이블 연결로만 판정한다. 지도 우회선의 길이로 시간·운임을 다시 계산하지 않는다.

## 3. 노선과 이동 시간

- `PuzzleRouteTableData.routes[].distance`가 노선 거리의 원본이다. 방향 100개(왕복 50철도)를 기록하며 왕복 값은 같아야 한다. 운임 = 기본요금 + 거리 × `costPerDistance` + 점유 칸 × `costPerCell`이다. 이동 시간 = 거리 × `PuzzleTimeTableData.hoursPerDistance`(3시간)이고 이동 1회가 1턴이다.
- `routes[].points`는 표시 선과 동기화된 그리기 전용 좌표이며 역방향은 같은 점의 역순이다. 선 길이는 Map Editor의 노선 거리 자동 계산(`pixelsPerDistance` 100당 1)에만 쓴다.
- 노선 거리는 1~7(1 26 · 2 19 · 3 4 · 6 1 · 7 1)이다. 값은 턴제 전환 전의 요금 거리를 그대로 옮겼다. 거리·적재 단가 1과 기본요금 3은 바꾸지 않았다.
- `PuzzleTimeManager`가 실시간 시계의 정수 게임 시간을 보유하고 표시·이동·물품 보유 시간·가치 누적이 같은 시계를 쓴다. 06:00 시작, 낮 06:00~24:00, 밤 00:00~06:00이다([게임 시간 시스템](<게임 시간 시스템.md>)).
- 지도 시간 라벨·시장 입력 그룹·Game 씬의 아침 대기와 상환 금액 배치는 프리팹에서 수정한다. 원본 레이아웃의 좌표와 노선 연결은 유지했다.

- 아침 대기는 06:00까지 시간·보유 시간을 진행한다. 턴·요금·시장 재고는 변경하지 않으며 시너지 정산 주기를 넘으면 가치를 정산한다.

## 6. 세션 시간

- `PuzzleInventoryService.Time.ElapsedHours`가 단일 게임 시간이다. 실시간 시계가 1시간씩 확정하고 UI 시계는 `D일 HH:MM · 낮/밤 · N턴`으로 표시한다. 날짜는 06:00에 바뀐다. 기한은 시작부터의 경과 시간으로 비교한다.
- 이동 시간은 `PuzzleTimeManager.TravelHours(route, timeRules)`로 노선 거리 × `hoursPerDistance`를 계산한다. `Time.ArrivalAt`은 누적 범위를 먼저 검사한다.
- 출발(`DepartLeg`)은 운임을 내고 `Journey`를 만든다. 시계가 이동 시간만큼 흐르면 도착(`CompleteJourney`)해 도시와 턴을 바꾼다. 가치 변화는 이동 중 통과한 6시간 정산 횟수만큼이며 호버 예측도 같은 횟수를 사용한다.
- 보유 시간은 상태 확정 중 갱신하고, 날짜 변경 부산물을 생성한 뒤 `TimeAdvanced`를 발행한다. 새 부산물의 보유 시간은 0에서 시작한다. 이벤트는 `previousHours`·`elapsedHours`·`DeltaHours`를 제공한다.

## 7. 표 검증

- 낮 시간은 1 이상, 24시간 미만이다. 시작 시각은 0~23 범위이고 휴식 시간·거리당 이동 시간은 양수다. 노선 거리는 양수이며 왕복 값이 같아야 한다.
- 폴라인은 유한한 x,y 쌍이 두 점 이상이고 길이가 양수여야 한다. 왕복 폴라인은 정확한 역순이다. 
- 기존 도시 참조·노선 중복·거리·비용·양방향 연결과 근거리 교역 제한 검증을 유지한다. 테이블 오류는 모아서 보고하고 사용 전에 `RequireValid()`로 차단한다.

## 9. 남은 확인

- 실시간 시계(이동 1턴·거리 비례 이동 시간·역 행동 무료)에서의 경제 밸런스는 잠정이며 플레이 검증이 필요하다.
- 낮 18시간(실제 3분) 안의 정차·거래 수, 밤 대기와 상환 기한·자금 압박, 이동 대기 체감은 실제 플레이로 확인하지 않았다.
- `highSpeed`는 시간 계산에 참여하지 않는 기존 필드다.
