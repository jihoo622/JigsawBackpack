# 현재 구현 상태

구현 사실과 기획 대비 차이를 관리한다. 규칙·의도·설계 미정 사항은 [게임 기획서](<../게임 기획서.md>)를 본다. 구현 완료는 플레이 검증 완료를 뜻하지 않는다.

## 지도와 상환 목표

- 지도 라벨은 지역 mapLabelPriority + 역 mapLabelImportance + 상태 가산점으로 배치한다. 축소 시 지역별 핵심 역부터 표시하고 한 지역의 표시 수가 늘면 다음 후보 점수에 감점을 준다. 확대 시 일반 역명을 추가하며 핵심은 굵은 큰 글씨로 구분한다. 수치 원본과 편집법은 [MAP](MAP.md)을 따른다.
- Tools/MyJG/Edit Rail Routes에서 표시 경유점을 Scene 핸들/좌표로 편집·추가·삭제하고 초안 Undo/Redo를 사용할 수 있다. 저장은 레이아웃 displayPoints와 지도 프리팹에 반영하며 역 연결·이동 시간 원본·요금은 유지한다. 이번 변경의 컴파일·도구 실행·플레이 확인은 수행하지 않았다.

- 연결된 역을 누르면 목적지·소요 시간·요금·이동 후 자금을 보여주는 확인창에서 확인·취소를 선택한다. 확인 시 사전 배치한 기차·진행률 연출을 표시하고 완료 후 `Travel`을 한 번 호출한다. 이동 성공 시 도착 표시 후 지도를 닫고, 실패 시 지도에 이유를 표시한다. 취소·패널 닫힘·비활성화는 대기 중 연출을 정리한다. 연출 시간은 거래 테이블의 `travelEffectSeconds`·`travelArrivalHoldSeconds`가 원본이다.
- 확인창·연출 중 지도 입력과 중복 확인을 차단한다. 확인창의 Esc는 취소만 처리하고 일시정지를 함께 열지 않는다. 일시정지 입력도 복제한 액션 자산의 `UI/Cancel`로 전환했다. 확인창과 연출 UI는 지도 프리팹에 저장되어 있고 `Tools/MyJG/Apply Map Travel UI`로 재적용한다. 플레이·입력 확인은 수행하지 않았다.

- 확장 검토안의 실제 상태는 아래 기획 대조 목록에 정리했다. 동물 부산물과 화물칸 간 이동은 이미 동작 경로가 있으며 내구도는 표시·저장만 한다. 전용칸·인카운터·검문소·기관차 효과·철도 투자·위치 교환은 게임 연결이 없다. 티켓 표기는 [작업 트래커 대응](TASK_TRACKER.md)을 본다.

- 생산 지역 21개 마을·수도권 5개·일반 마을 4개, 양방향 연결 44개를 적용했다. 기존 43개에 카르포트↔포르베르 공업 노선 R44(요금 거리 3, 기본요금 6, 잠정 K=28 기준 10시간 31분)를 추가했다. 공업·수도권은 각 5개, 나머지 생산 지역은 각 4개다. 원본 레일 생성 seed 20265146의 `ProjectWorldData.json`(`projectMapData`) 43개 연결을 유지하고 프로젝트 보완 노선 R44를 더했다. 노선·마을 이름·표시 좌표는 생성 데이터가 정하고, 지역 구분과 태그 경제는 기존 테이블을 유지한다. 마을 ID와 생성 역(`S01`~`S30`)의 대응, 좌표·폴리라인은 [MAP](MAP.md)과 [rail_map_layout_seed_20265146.json](rail_map_layout_seed_20265146.json)에 있다. **이번 판에서 ID 대응이 바뀌어** 같은 이름이 다른 `city.*`에 붙었다(라센턴은 `city.mine.dig`).
- 공업 5개 마을 모두 출발 가능한 경로지만 실제 시작 설정은 `city.industry.ironworks`(에른아 공업역)이다. 무작위 출발·출발지 선택은 연결하지 않았다.
- `city.capital.finance`(금융마을)을 `planningTargetCityId`로 지도에 표시하고, 같은 ID를 `debtCityId`에 넣어 **상환 가능 장소를 금융마을로 제한**했다. `CanClearGame`이 현재 도시를 확인한다. 기획서가 전제해 온 "금융마을에서 상환"이 구현과 일치하게 됐다.
- 지도 프리팹에 외부 데이터의 노드 30개·레일 44개의 시간용 폴리라인 87구간과 표시 조각 107개·시간 라벨 44개를 저장했다. 노선별 출발·도착 바인딩과 환승 표시도 갱신했다. 에디터 표시 이름·시간·노선 색상도 `Presentation`을 통해 저장하며, 재적용 도구는 `Assets/Scripts/Editor/Build/RailMapLayoutTool.cs`다.
- 외부 지형의 육지·바다·고도·강·경제 지역 경계를 배경 이미지로 적용했다. 지도 영역만 휠 확대·축소(35~250%)·드래그 이동하며, 전체 보기·현재 위치 버튼을 제공한다. 현재 역은 금색 링·확대된 역 테두리·배지·굵은 글씨로 강조한다. 제목·범례·도시 정보·조작 버튼은 확대 대상에서 제외하고 화면 가장자리 여백에 맞춰 고정했다. UI 구성 재적용은 `Tools/MyJG/Apply Map Presentation`을 사용한다.
- 줌은 지형과 역 사이 거리만 확대하고 글자·마커·배지·선 굵기는 역배율로 보정한다. 지명은 직전 방향을 먼저 사용하고 필요하면 주변 빈 공간을 탐색하며 원래 역에 안내선으로 연결한다. 실제 이름/배지 크기와 역 링/현재 위치 테두리, 다른 라벨·안내선의 충돌을 함께 검사하고 겹침 강제 표시는 하지 않는다. 안내선 30개를 지도 프리팹에 사전 배치했으며 Apply Map Presentation도 같은 연결을 생성한다. 축소 시 보이지 않는 노드 사각형 대신 실제 역 표식 영역으로 입력을 제한하고, 겹친 표식은 가까운 역을 선택한다. 시간 표시는 현재 역 직결 노선·85% 이상에 한정하며 지명/안내선을 피한다. 변경 후 컴파일·플레이 확인은 수행하지 않았다.
- 336시간 기한·조기 상환·기한 초과 패배 코드가 존재한다. 상환에는 버튼 입력이 필요하다. 옛 이동횟수 기반 빚 일정과 비활성 코드는 제거했다.
- 시작 자금 200, 증차 50, 상환 금액 1,500을 임시 사용한다. 경제 밸런스는 미검증이다.

## 시간·거래·자산

- 게임 UI를 상단 정보·같은 폭의 좌우 본문·하단 상태 안내로 나눴다. 기차 보드·화물칸 바와 역 행동/시장/술집/휴식을 각 영역에 배치하고 버튼 글자 크기·줄바꿈·여백을 정리했다. 상환·지도 버튼은 폭을 따로 확보한다. 툴팁 폭·커서 간격·화면 여백과 모달 표시 순서도 설정했다. 공통 제작 원본은 기초데이터 `ui.layout.*`이며 `Tools/MyJG/Apply UI Overhaul`로 저장한다([UI 배치](UI_LAYOUT.md)). 플레이·입력·캡처 확인은 수행하지 않았다.
- 좌측에 기차·화물칸 바, 우측에 역 행동 목록(시장·술집·휴식·다른 역 이동)을 배치했다. 시장과 술집은 우측 하위 화면으로 열고 뒤로 가기로 목록에 돌아온다. 야간 시장은 진입과 모델 거래를 함께 차단한다. 최신 develop의 술집 대화 기능과 시장·술집 아이콘을 합쳤다. `TavernContent` 안에 기존 소식 UI를 연결했고 기차 조작은 좌측에서 유지한다. 지도 열림 중 역 메뉴 입력도 차단한다.
- 술집은 지도 전체의 미방문·판매 허용 도시에서 구매/판매 배율이 모두 100%를 넘는 마을·품목 후보 하나를 무작위로 안내한다. 방문당 한 번 대화하고 버튼을 비활성화하며 새 도시 도착 시 다시 활성화한다. 들은 소식은 세션 로컬 기록으로 보관하고 우측 접이식 대화 로그 한 개에 들은 게임 날짜·시각 - 들은 마을 - 내용 순서로 표시한다. 기록 순서로 쌓고 새 기록과 펼침 시 마지막 기록으로 스크롤한다. 접은 상태는 새 기록으로 바꾸지 않는다. 지도와 역 화면이 같은 로그를 공유하며 패널 밖의 조작은 허용한다. 로그 위의 휠은 지도 줌에 전달하지 않는다. 재시작하면 기록은 초기화한다. 술집 문구·서식과 주요 배치값도 기초데이터를 사용한다. 선택 정책과 남은 공통 스타일·매핑은 [추가 후보](BASIC_DATA_CANDIDATES.md)에 정리했다.
- 휴식 화면은 시간 테이블의 `restMinutes`(현재 60분)만큼 시간 보내기와 야간의 다음 일출까지 대기를 제공한다. 시계·보유 시간·기한 판정과 6시간 경계의 시너지 정산을 진행하며 요금·이동 횟수·재입고는 변경하지 않는다. UI 제작 메뉴는 `Tools/MyJG/Apply Station Actions UI`다.
- 화물 기본 가치를 화물 정의에 통합하고 도시 재고를 7개 공유 프로필로 정리했다. 가격 표·옛 빚 일정 표·미사용 구매 할증 필드를 제거해 도메인 JSON은 8개다. 기존 가격·배치 ID·슬롯 추첨 순서는 유지하며 사과를 일반·집산 후보에 추가했다.
- 최신 툴팁 프리팹·포인터·신선도 표시와 화물칸 폭 갱신을 병합했다. 툴팁 색·문구·폭은 최신 값을 유지하며 신선도 색/구간/치수·포인터 간격도 기초데이터에서 읽는다. 신선도 글자는 슬롯 프리팹에 미리 배치하고 `Tools/MyJG/Apply Freshness Display`로 재적용한다. 역 메뉴 공통 제작과 씬 저장도 반영했다.
- 기초데이터는 37개 그룹·712개 항목이다. 중복 제작 치수와 사용 위치 메타데이터를 제거하고 의미 있는 조회 키를 사용한다. 필수 키 계약은 `Tools/MyJG/Tables/Generate Basic Data Contract`로 생성한다.
- 공통 문구·서식·색·지도/UI 조정값·제작 치수·규칙 참조 ID·레이어 번호를 기초데이터로 옮겼다. 도메인 수치는 기존 표가 소유한다. 공통 로더와 필수 키·유한값·서식·색상 검증을 사용하며, 구조상 코드에 유지하는 값은 [BASIC_DATA](BASIC_DATA.md)에 명시했다.
- 시계는 `PuzzleInventoryService.Time`의 `PuzzleTimeManager` 하나이며 `ElapsedMinutes`가 원본이다. `ElapsedTime`도 분 단위 조회 별칭이다. 물품은 `OwnedMinutes`로 보유 시간을 보관한다.
- 노선 시간은 고정 폴라인 길이 합을 시간 테이블의 K(잠정 28픽셀/시간)로 나누고 분 미만을 올림한다. 요금용 `distance` 1~9와 독립적이며 화면 확대율은 영향을 주지 않는다. 기존 시간 가중치는 제거했다.
- 실제 가치는 게임 시작 기준 6시간 경계를 넘을 때 `(시너지 계산값−기본 가치) × 정산 횟수`로 변한다. 주기는 `PuzzleSynergyTableData.activationIntervalHours`가 원본이다. 이동·휴식·아침 대기가 같은 시계를 사용하며 배치·구매·도착으로 초기화하지 않는다. 행동 시작 배치로 정산하고 부산물은 행동 종료 후 생성해 이후 행동부터 시너지에 참여한다. 호버 예측도 같은 정산 횟수를 표시한다. 하단 예측 목적지 선택 UI는 없다. 지도에서 이동할 역을 선택하면 예측 목적지를 갱신하고 미선택 시 미래 가치만 숨긴다.
- 최신 develop의 상품 팝업 라벨/수치 분리와 보유 효과 설명, 생선의 화물 보너스 제외 수정 및 지도 지역 색상 수정을 보존했다. 새 팝업의 미래 가치 라벨에 예상 정산 횟수를 표시하고 효과 설명 제목에 적용 주기를 표시한다.
- 시작 06:00, 일출 18시간(06:00~24:00), 야간 6시간(00:00~06:00)이다. 야간에는 시장 보드를 비활성화하고 모델에서도 거래·시장 내 재배치를 차단한다. 기차 내 재배치·이동은 허용한다. 아침 대기는 다음 06:00까지 시계·보유 시간을 진행하며 요금·이동 횟수는 변경하지 않으며 6시간 경계의 시너지는 정산한다.
- 일반 마을은 특산품·태그별 가격 규칙 없이 기본 구매 100%·판매 90%, 물가 100%다. 수도권 물가는 125%다. 수도권·일반 마을 재고는 집산품 3개·수입품 1개·랜덤 2개다.
- 거래와 시너지는 복수 태그를 공유하고 흔함을 귀함보다 우선한다. 구매는 기본 가치, 판매는 누적 실제 가치에 배율을 적용한다.
- 출발 시장만 새 화물 ID로 재입고한다. 도착 시장과 기차 화물은 보존한다.
- 추가 수요는 마을별 임시 고정값이다. 랜덤 재추첨 방식은 미정이다.
- 상품 정의는 16개다. 최신 develop의 일반 가축 제거·소/소고기 재고 교체와 사용하지 않는 아이콘 삭제를 반영했다. 내구도 초기값·아이콘 배치 필드·음수 가격은 유지하고 미사용 희귀 고정 단가 분기는 제거했다. 표시 크기 안에서 아이콘 종횡비를 보존하고, 소처럼 표시 오프셋이 있는 아이콘도 물품과 함께 회전하도록 실제 표시와 드래그 미리보기의 공통 계산을 수정했다.
- Game 씬에서 바로 시작하며 재시작 시 해당 판을 초기화한다. 영구 저장·재개와 타이틀 진입 흐름은 미연결이다.

- 하단 예측 선택 버튼·이벤트·제작 코드·전용 테이블 항목을 제거했다. 하단 상태 안내는 전체 폭을 사용한다. 상환 금액은 거래 테이블의 1,500이며 제작 시 버튼 문구에도 반영한다.

- 지도 표시 경로 11개를 우회·분리해 직통선이 테라카·금융마을 등 비경유 역에 붙지 않도록 했다. 그리기는 선택적 `displayPoints`를 우선 사용하며 게임 시간/운임의 원본 `points`와 역 좌표는 보존한다. 교차점에는 아래 노선의 틈을 저장하고 지역 간→중립→지역 내부 순으로 그린다. 노선 굵기는 통일하고 중립 선·역 테두리는 같은 밝은 회색을 사용한다.

- 소문 로그는 `PanelBase` View와 별도 Presenter로 나눴다. `TavernRumorRecorded`를 세션별로 구독해 즉시 갱신하며 static 초기화 시 이벤트를 정리한다. 본문은 사전 배치된 TMP 한 개와 ScrollRect/Viewport/Content를 사용한다. 문구·형식·치수는 기초데이터 `presentation.rumorLog.*`·`ui.rumorLog.*`이며 `Tools/MyJG/Apply Rumor Log Panel`로 프리팹과 씬을 재적용한다.

## 기획과 구현의 정합성

- 콘솔·오류와 게임 분석 원본을 모두 LogKit으로 전송한다. 분석은 Telemetry, 테이블은 TelemetryRules/rules_chunk이며 로컬 보관과 동일한 원본을 사용한다. 테이블은 앱 세션 안에서 해시별 한 번만 보내며 초기 씬 전 로거 준비·종료 로그 선기록·전송 실패 재시도를 연결했다. 서버 수신 확인은 수행하지 않았다.

- 분석 로그 schemaVersion 3는 구매·판매·재배치의 의미와 drag/quick_transfer 방식을 분리한다. 시작 상태와 행동별 관측 변화(도시·자금·화물칸 수·위치·가치·내구도), 명시적 실패, 소문, 승패/재시작 경계를 기록한다. introduced는 생성 시각이 아닌 최초 관측이며 숨은 시장은 방문 시 관측한다. 적용 테이블 원본은 해시별 Rules 파일이다. 외부 복원 순서·좌표·결측/실패 해석은 [PLAY_LOG](PLAY_LOG.md), 보관은 [TELEMETRY](TELEMETRY.md)를 따른다. 집계는 외부에서 수행하며 이 변경의 컴파일·플레이 확인은 수행하지 않았다.

- 거래 예상 금액과 결제는 `PuzzleInventoryService.TryQuoteTrade`를 공유한다. 구매는 기본 가치·판매는 보존된 실제 가치에 도시 배율과 지역 물가를 곱하고 최종 반올림한다. 미사용 `rareValue` DTO·검증 예외·거래 분기는 제거했다.
- 앞선 재구매 예상가 조사에는 정정이 있다. 기존 Presenter가 시장 물품을 기본 가치로 보정하므로 항상 잘못 결제되는 상태는 아니었다. 현재는 시장에서도 보존된 실제 가치를 표시하고 구매 예상은 공유 견적의 기본 가치 기준을 쓴다.
- 툴팁에 기본 가치와 현재 배치의 정산 1회 효과를 추가하고 가능한 효과 설명과 구분했다. 새 행은 프리팹·씬에 저장하며 `Tools/MyJG/Apply Tooltip Trade Details`로 재적용한다. 런타임에 행을 생성하지 않는다.
- 기차 합계는 현재 선택 화물칸의 누적 실제 가치 합과 기본 가치 합을 표시한다. 시장에는 물가 배율을 표시하고 정보 영역을 늘렸다. 지도에서 미방문 마을은 지역 이름만 공개하며 물가·특산·수요는 방문 후 보여준다. 단, 소문을 들은 대상 마을은 이름 옆에 `?`를 붙이고 호버 시 해당 마을의 소문 기록만 미확인 정보로 공개한다. 방문 후 `?`를 지우고 확인된 정보를 표시하며 과거 소문은 로그에 남긴다. 로그 TMP의 리치 텍스트를 활성화해 날짜·장소 강조 태그를 해석한다.
- 기한 초과 패배도 승리와 같은 결과 패널에 연결했다. 결과 제목·안내를 구분하고 시간 정지·인벤토리 입력 차단·재시작·종료를 공유한다.
- 사과를 일반·집산 재고 후보에 연결했다. 빈자리 조건을 만족하는 한 칸 상품이며 별도의 고정 입고 수량은 추가하지 않았다.
- 현재 동작인 에른아 고정 출발·고정 추가 수요·시작 목재 2개·음수 가치와 처분 비용·화물칸 간 무료 이동을 기획서의 잠정 규칙으로 명시했다. 내구도 100 표시·감소 없음과 날짜 변경 행동당 동물 부산물 생성/처분/인접 효과도 6장에 명시했다. 새 부패·보호·비료 규칙은 추가하지 않았다.
- 기획의 거리 평균을 약 2.84로, 지역 구성을 생산 5개 지역 21개 마을·수도권 5개·일반 4개로 정리했다. 과거 시간 기준과 HUD 문서의 글자 크기 설명도 현재 구조로 맞췄다.
- 전용 화물칸·내구도 감소/보호·농업 비료 매입·인카운터·검문소·기관차 효과·위치 교환·철도 투자·랜덤 시세·자동 경로·강제매각·저장/재개는 여전히 미정/확장안이다. 현재 규칙과 구분하며 이번 수정에서 구현하지 않았다.
- 노션 기획서 조회는 404로 실패했다. 소문 표시·지도 상태 유지·공업 노선 연결을 포함한 로컬 기획 수정은 노션 미반영 상태이며 공통 기준은 갱신하지 않았다. 재접속 시 이전 지도·시간·UI 미반영분과 함께 부분 병합해야 한다.
- 전체 미방문 지역 대상 추첨·대화 후 비활성화·증차 한 줄 문구를 유지한다. 책/페이지 방식은 우측 소문 로그로 교체했다. 구매 배율/금액의 유불리 색도 구매 관점으로 적용한다.
- 컴파일·테이블 초기화와 제작 도구의 씬/프리팹 연결을 반영했다. 플레이·입력·해상도별 가독성 확인은 수행하지 않았다.

## 경로 계산과 확인 범위

K=28 잠정치의 금융마을까지 최단 이동 합은 카르포트 25시간 36분, 노르노바 36시간 26분, 에른아 공업역 39시간 53분, 헤일포드 45시간 26분, 포르베르 54시간 46분이다. 대기·거래·자금 및 실제 플레이 가능성은 포함하지 않는다. 단일 레일은 2시간 54분~30시간 51분이다. 경제·야간 동선 밸런스는 플레이 검증 전 잠정 상태다.

- 로컬 기획서는 시간·지도·UI 규칙을 반영한다. 과거 노션 접근 복구 시 6장 시너지 정산·호버 안내를 반영했으나 이전 지도·시간·UI 변경은 미동기화 상태다. 현재 조회는 다시 404로 실패했다. 원격의 최신 본문과 공통 기준은 갱신하지 않았다([동기화 규칙](NOTION_SYNC.md)).
- Unity CLI로 지도 프리팹과 역 메뉴 씬을 편집·저장했다. 커밋 전 Visual Studio의 Remove and Sort와 ProjectValidation의 검증 본체를 적용했다. 테이블은 정상이며 기존 Preload·Title 빌드 목록 누락과 Input Handling Both 안내가 남아 있다.
- 플레이·입력 실험·캡처는 수행하지 않았다. 남은 확인은 [BACKLOG](BACKLOG.md)에서 관리한다.
- 기술·운영 계약은 [관리 문서 안내](README.md)를 따른다.

- 지도는 최초 열기에서만 전체 보기를 적용하고 재열기에는 확대 배율·이동 위치를 유지한다. 행동 목록 복귀 버튼과 소문 탭의 폭·줄바꿈을 정리했다.
