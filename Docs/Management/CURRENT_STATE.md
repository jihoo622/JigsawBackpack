# 현재 구현 상태

구현 사실과 기획 대비 차이를 관리한다. 규칙·의도·설계 미정 사항은 [게임 기획서](<../게임 기획서.md>)를 본다. 구현 완료는 플레이 검증 완료를 뜻하지 않는다.

- `Assets/Art/External/POC_06`에 사용 허가를 확인한 이미지 90개와 열차 시각 전용 UGUI 프리팹 3개를 추출했다. `feature/아트리소스`에서 Game 씬의 화물칸 선택 바·기관차 장식·역 메뉴 아이콘 4개, 지도 이동 연출의 측면 열차에 적용했다. 배치는 해당 프리팹에서 수정하며 퍼즐 보드/상품 아이콘은 유지한다. 라이선스·원본 커밋·파일별 출처/해시를 함께 보관한다. 플레이·해상도별 확인은 미수행이다([외부 에셋](ASSET_IMPORTS.md)).

## 지도와 상환 목표

- 이동 시간의 원본 points를 표시 폴라인과 동기화했다. 역/경유점/선 모양 수정 시 시간도 비례해 바뀌고 요금 거리 자동 계산은 같은 길이를 사용한다. 시간 전용 경로 모드는 제거했다. 현재 50개 왕복 노선에 적용했고 K=28 기준 단일 구간 3~26시간이다.
- 시간 라벨 좌표 입력/드래그는 위치를 고정한다. 자동 배치·프리팹 위치 보정·런타임 위치 이동에서 고정을 존중하며 기존 저장 좌표도 유지한다. 고정 라벨과 충돌하는 역명은 다른 위치를 찾고, 라벨 자체가 역 표식/다른 고정 라벨/화면 경계에 걸리면 옮기는 대신 숨긴다. 선택/전체 고정 해제 후 자동 배치로 되돌릴 수 있다. 이동 시간 기준은 노션과 로컬 기획서의 해당 부분에 반영했고 기존 전체 동기화 기준은 유지했다.
- 새 노선의 시간 배경이 글자보다 위에 그려져 검은 상자만 보이던 문제를 수정했다. 시간 배경→글자 순서를 프리팹·레이아웃/지도 표기 제작 도구·런타임 초기 배치에서 고정한다.
- 맵 에디터에 선택/전체 시간 라벨 자동 배치와 역·노선·이름 수정 후 재배치를 추가했다. 길이상 중간부터 역/기본 역명/다른 라벨/다른 노선을 피하며, 공간이 없으면 기존 위치를 유지하고 노선을 알린다. 자동 재배치는 끌 수 있고 드래그 종료 시 계산해 Undo 한 번으로 복구한다. 자동 배치 입력·저장·플레이는 미확인이다.
- 기본요금은 현재 왕복 50개/방향별 100개 노선과 레이아웃, 기준값 `defaultBaseCost` 모두 3이다(경제 시뮬레이션 결과로 6에서 내렸다). 맵 에디터의 공통 설정에 기본요금 일괄 적용과 표시 선 길이 비례 정수 거리 계산을 추가했다. 초기 기준은 지도 길이 100당 거리 1이며 반올림·최소 1, 왕복 동일하게 적용한다. 선택/전체 거리 계산은 미리보기 후 초안에 적용하고 기존 거리·이동 시간은 자동으로 덮어쓰지 않는다. 새 노선에는 기준 기본요금과 계산 거리를 적용한다.
- `Tools/MyJG/Map Editor`를 추가했다. 역 추가/삭제·이름/지역/위치/중요도/시장 설정, 왕복 노선 추가/삭제/연결 변경·요금/거리/경유점, 지역 이름/우선순위/물가·소속 역 중요도, 지형 칠하기와 공통 이동 단가를 한 창에서 편집한다. 창 내부 캔버스가 지형·역·역명·노선·시간을 렌더링하며 역/선 클릭 선택과 역/경유점/시간 라벨 드래그, 휠 확대/축소·지도 이동·전체/선택 보기를 지원한다. 프리팹/Scene을 열지 않고 초안을 편집하며 표시 경로와 시간 경로를 동일하게 유지한다. 저장 시 테이블·레이아웃·프리팹과 역 참조를 함께 반영하며 실패 시 원본을 복구한다. 상세 필드는 창 내부 JSON으로 편집한다. 통합 도구의 저장·캔버스 입력·플레이는 미확인이다([사용법](MAP.md)).
- 지도 라벨은 지역 mapLabelPriority + 역 mapLabelImportance + 상태 가산점으로 배치한다. 축소 시 지역별 핵심 역부터 표시하고 한 지역의 표시 수가 늘면 다음 후보 점수에 감점을 준다. 확대 시 일반 역명을 추가하며 핵심은 굵은 큰 글씨로 구분한다. 수치 원본과 편집법은 [MAP](MAP.md)을 따른다.
- Tools/MyJG/Edit Rail Routes에서 표시 경유점을 Scene 핸들/좌표로 편집·추가·삭제하고 초안 Undo/Redo를 사용할 수 있다. 저장은 레이아웃 displayPoints와 지도 프리팹에 반영하며 역 연결·이동 시간 원본·요금은 유지한다. 에디터 어셈블리의 런타임 내부 필드 접근 오류를 수정하고 컴파일·실제 메뉴 열기·프리팹 연결·경유점 드래그/추가/삭제·Undo/Redo를 확인했다. Scene 창 자동 열기와 비활성 지도용 2D 편집 미리보기를 제공한다. 저장/프리팹 반영·플레이는 미확인이다.

- 연결된 역을 누르면 목적지·소요 시간·요금·이동 후 자금을 보여주는 확인창에서 확인·취소를 선택한다. 확인 시 사전 배치한 기차·진행률 연출을 표시하고 완료 후 `Travel`을 한 번 호출한다. 이동 성공 시 도착 표시 후 지도를 닫고, 실패 시 지도에 이유를 표시한다. 취소·패널 닫힘·비활성화는 대기 중 연출을 정리한다. 연출 시간은 거래 테이블의 `travelEffectSeconds`·`travelArrivalHoldSeconds`가 원본이다.
- 확인창·연출 중 지도 입력과 중복 확인을 차단한다. 확인창의 Esc는 취소만 처리하고 일시정지를 함께 열지 않는다. 일시정지 입력도 복제한 액션 자산의 `UI/Cancel`로 전환했다. 확인창과 연출 UI는 지도 프리팹에 저장되어 있고 배치는 프리팹에서 수정한다. 플레이·입력 확인은 수행하지 않았다.

- 확장 검토안의 실제 상태는 아래 기획 대조 목록에 정리했다. 동물 부산물과 화물칸 간 이동은 이미 동작 경로가 있으며 내구도는 표시·저장만 한다. 전용칸·인카운터·검문소·기관차 효과·철도 투자·위치 교환은 게임 연결이 없다. 티켓 표기는 [작업 트래커 대응](TASK_TRACKER.md)을 본다.

- 생산 지역 24개 마을·수도권 5개·일반 마을 2개, 양방향 연결 50개다. 원본 레일 생성 seed 20265146의 `ProjectWorldData.json`(`projectMapData`) 43개 연결에서 시작해 Map Editor로 노선·역 좌표를 고쳤다. 광산·공업 각 6개(오스베르는 광산, 테라그라드는 공업으로 옮겼고 라스부르크를 추가), 수도권 5개, 나머지 생산 지역은 각 4개다. 마을 이름은 생성 데이터, 지역 구분과 태그 경제는 기존 테이블을 따른다. 마을 ID와 생성 역(`S01`~`S30`)의 대응, 좌표·폴리라인은 [MAP](MAP.md)과 [rail_map_layout_seed_20265146.json](rail_map_layout_seed_20265146.json)에 있다. 역 ID는 `city.<역 이름 로마자>`(예: 라센턴 `city.rasenton`)로 지역과 무관하며, 바꿀 때는 Map Editor `ID 바꾸기`로 모든 참조를 함께 고친다.
- 공업 6개 마을 모두 출발 가능한 경로지만 실제 시작 설정은 `city.erna`(에른아 공업역)이다. 무작위 출발·출발지 선택은 연결하지 않았다.
- `city.finance`(금융마을)을 `planningTargetCityId`로 지도에 표시하고, 같은 ID를 `debtCityId`에 넣어 **상환 가능 장소를 금융마을로 제한**했다. `CanClearGame`이 현재 도시를 확인한다. 기획서가 전제해 온 "금융마을에서 상환"이 구현과 일치하게 됐다.
- 지도 프리팹에 노드 31개·레일 50개의 시간용 폴리라인 57구간과 표시 조각 57개·시간 라벨 50개를 저장했다. 노선별 출발·도착 바인딩과 환승 표시도 갱신했다. 에디터 표시 이름·시간·노선 색상도 `Presentation`을 통해 저장하며, 재적용 도구는 `Assets/Scripts/Editor/Build/RailMapLayoutTool.cs`다.
- 지형 배경은 칸 격자 지형 원본(지형 종류·지역)에서 만들며 Map Editor 지형 탭에서 칠한다. 기존 지도 둘레에 육지를 생성해 동쪽 해안을 빼면 대륙 일부로 보이게 했다(에디트 모드 렌더로 35·65·120% 확인, 플레이 확인 안 함). 지도 영역만 휠 확대·축소(35~250%)·드래그 이동하며, 전체 보기·현재 위치 버튼을 제공한다. 현재 역은 금색 링·확대된 역 테두리·배지·굵은 글씨로 강조한다. 제목·범례·도시 정보·조작 버튼은 확대 대상에서 제외하고 화면 가장자리 여백에 맞춰 고정했다. 배치는 프리팹에서 수정하며 지형 이미지는 Map Editor 저장 때 다시 만든다.
- 줌은 지형과 역 사이 거리만 확대하고 글자·마커·배지·선 굵기는 역배율로 보정한다. 지명은 직전 방향을 먼저 사용하고 필요하면 주변 빈 공간을 탐색하며 원래 역에 안내선으로 연결한다. 실제 이름/배지 크기와 역 링/현재 위치 테두리, 다른 라벨·안내선의 충돌을 함께 검사하고 겹침 강제 표시는 하지 않는다. 안내선 30개를 지도 프리팹에 사전 배치했다. 축소 시 보이지 않는 노드 사각형 대신 실제 역 표식 영역으로 입력을 제한하고, 겹친 표식은 가까운 역을 선택한다. 시간 표시는 현재 역 직결 노선·85% 이상에 한정하며 지명/안내선을 피한다. 변경 후 컴파일·플레이 확인은 수행하지 않았다.
- 336시간 기한·조기 상환·기한 초과 패배 코드가 존재한다. 상환에는 버튼 입력이 필요하다. 옛 이동횟수 기반 빚 일정과 비활성 코드는 제거했다.
- 시작 자금 200, 증차 50, 상환 금액 1,500을 임시 사용한다. 최대 객차 수는 8칸(`PuzzleTradeTableData.maxWagonCount`)으로 상한에 도달하면 증차가 거부되고 버튼이 비활성화된다. 판매 배율은 일반 90→100%·귀함 120→130%(흔함 70% 유지), 기본요금은 6→3으로 조정했다. 목표는 시너지를 고려하지 않아도 11~12일차 상환이다. Economy Analyzer Loop 봇 1,000판 기준 시너지·신선도를 끈 순수 거래는 승률 100%·상환 p10/중앙값/p90 8.5/9.1/9.7일, 시너지를 켜고 배치는 신경 쓰지 않으면 승률 98.8%·10.5일(p10 9.7, p90 12.2)이다(시너지 면 단위 적용 후 재측정). 승리 경로는 헤일하임(`city.heilheim`)↔카르포트(`city.karport`) 왕복(기계·소고기·소)에 집중된다. 바로 옆만 보는 Greedy 봇은 금속·기계 이중 귀함(라센폴·발렌리에·베르스카 판매 160%, 의도)에 끌려가 이 왕복을 놓쳐 0%다. 플레이 확인은 수행하지 않았다.
- 시너지 상성표: 하단 상태 바 오른쪽 `상성표` 버튼으로 연다. 행은 대상 태그(제외 방식 규칙은 "모든 화물(… 제외)"), 열은 이웃 태그, 칸은 면 하나당 효과 %이며 제외 이웃은 각주로 표시하고 오른쪽에 화물별 태그 배지를 둔다. 프리팹 `Assets/Art/PuzzleSynergyChart.prefab`이 배치 원본(칸은 `GridLayoutGroup`)이고 `PuzzleSynergyChartPresenter`가 시너지 표(`PuzzleSynergyChart`)에서 문구·색만 채운다. 규칙의 대상·이웃 태그 종류가 바뀌어 행·열 수가 달라지면 프리팹의 칸 수를 맞춰야 하며 맞지 않으면 시작 시 오류를 낸다. 닫기는 버튼으로 하며 Esc는 아직 일시정지 메뉴가 받는다. 플레이 확인은 수행하지 않았다.
- `Tools/MyJG/Economy Analyzer`는 편집 모드에서 현재 테이블로 품목별 최저 구매·최고 판매처, 노선별 칸당 차익·1량 시간당 이익, 품목×도시별 적용 가격 규칙(태그 판정: 일치 규칙 전부·합산 배율·복합 표시), 봇 N판 시뮬레이션(일자별 자금·자산 p10/p50/p90, 결과 분포, 지출·수입 항목, 품목·도시 흐름)을 보여주고 `Logs/Economy`에 CSV로 내보낸다. 계산은 숨김 임시 `PuzzleInventoryService`를 `EconomyProbe`·`EconomySimulation`(Runtime/Analysis)이 조작해 실제 규칙을 그대로 쓴다. 봇은 Loop(기본: 고정 재고 기준 시간당 수익이 가장 큰 인접 왕복을 남은 시간 안에서 골라 오감), 바로 옆 도시만 보는 Greedy, 2구간 앞을 보는 Planner, Random이다. 가치가 음수인 화물만 처분하고 배치 최적화·도축·개조·의도적 번식은 쓰지 않으므로 승률은 왕복을 아는 플레이어 기준이다. 실험 옵션 '신선도 고정'(`shelfLifeHours` 0)과 '시너지 끄기'(배율 100%·배설 0·번식 없음)는 실행 동안만 메모리 값을 바꾸고 끝나면 되돌린다. 플레이 중에는 실행하지 않는다.

## 시간·거래·자산

- 게임 UI를 상단 정보·같은 폭의 좌우 본문·하단 상태 안내로 나눴다. 기차 보드·화물칸 바와 역 행동/시장/술집/휴식을 각 영역에 배치하고 버튼 글자 크기·줄바꿈·여백을 정리했다. 상환·지도 버튼은 폭을 따로 확보한다. 툴팁 폭·커서 간격·화면 여백과 모달 표시 순서도 설정했다. Game 씬 UI는 패널별 프리팹(`Assets/Art/UI/`)으로 분리되었으며 배치는 프리팹에서 수정한다([UI 배치](UI_LAYOUT.md)). 플레이·입력·캡처 확인은 수행하지 않았다.
- Game 씬 UI는 패널별 프리팹(`Assets/Art/UI/`) 인스턴스이며 배치는 프리팹에서 수정한다.
- 좌측에 기차·화물칸 바, 우측에 역 행동 목록(시장·술집·휴식·다른 역 이동)을 배치했다. 시장과 술집은 우측 하위 화면으로 열고 뒤로 가기로 목록에 돌아온다. 야간 시장은 진입과 모델 거래를 함께 차단한다. 최신 develop의 술집 대화 기능과 시장·술집 아이콘을 합쳤다. `TavernContent` 안에 기존 소식 UI를 연결했고 기차 조작은 좌측에서 유지한다. 지도 열림 중 역 메뉴 입력도 차단한다.
- 술집은 지도 전체의 미방문·판매 허용 도시에서 구매/판매 배율이 모두 100%를 넘는 마을·품목 후보 하나를 무작위로 안내한다. 방문당 한 번 대화하고 버튼을 비활성화하며 새 도시 도착 시 다시 활성화한다. 들은 소식은 세션 로컬 기록으로 보관하고 우측 접이식 대화 로그 한 개에 들은 게임 날짜·시각 - 들은 마을 - 내용 순서로 표시한다. 기록 순서로 쌓고 새 기록과 펼침 시 마지막 기록으로 스크롤한다. 접은 상태는 새 기록으로 바꾸지 않는다. 지도와 역 화면이 같은 로그를 공유하며 패널 밖의 조작은 허용한다. 로그 위의 휠은 지도 줌에 전달하지 않는다. 재시작하면 기록은 초기화한다. 술집 문구·서식과 주요 배치값도 기초데이터를 사용한다. 선택 정책과 남은 공통 스타일·매핑은 [추가 후보](BASIC_DATA_CANDIDATES.md)에 정리했다.
- 술집 운송 의뢰를 구현했다. 술집 화면 아래 의뢰 게시판(사전 배치 슬롯 2개)에서 방문마다 새로 걸린 의뢰를 수락하면 의뢰 화물을 현재 화물칸부터 빈자리에 싣고, 보증금 패널티면 보증금을 낸다. 목적지 도착 시 자동 완료해 보상 + 화물 실제 가치 + 보증금을 지급한다. 기한 초과나 화물 소실(판매·만료로 똥이 됨)은 실패이며 보증금 몰수 또는 의뢰 지역의 거래 배율 불이익(`RateFor`에 가산)을 적용한다. 평판 단계로 동시 진행 수가 정해지며 완료하면 화물 생산 태그에 숙련 경험치를 준다(실패해도 평판·숙련은 줄지 않음). 수락·완료·실패는 하단 상태 줄과 수첩의 의뢰 탭에 표시한다. 지도에서는 진행 중 의뢰의 목적지 역 링을 의뢰 색으로 바꾸고 이름 옆에 `[의뢰 남은 시간]`(여럿이면 건수·가장 급한 시간)을 붙이며 줌과 관계없이 이름을 보인다. 역 정보 끝에는 의뢰 화물·남은 시간·보수를 덧붙인다. `QuestChanged`·`TimeAdvanced`로 갱신한다. 납품 의뢰와 "보상이 문제를 일으킴" 패널티는 아직 없다. 규칙·잠정 수치 원본은 `TrainventoryQuestTableData`, 의뢰 화물은 `PuzzleTableData`의 `piece.quest*`(Quest 태그·시장 제외)다. 컴파일·테이블 검증만 했고 플레이 확인은 하지 않았다.
- 태그별 거래 숙련을 구현했다. 숙련 대상은 지역 생산 태그 합집합(`TableManager.ProficiencyTags`, 10종)이다. 화물 인스턴스별로 얻은 마을·방문·구입 품목·낸 금액을 기록한다(`tradeOrigins`). 시장 구매, 작업대(도축·개조·정제)에서 기차로 옮긴 산출물, 수락한 의뢰 화물이 기록 대상이다. 다른 마을 출신이거나 기록이 없는 화물을 팔면 판매 금액에 비례한 경험치를 생산 태그 수로 나눠 준다. 거래 이득은 `TryQuoteTrade`가 도시 배율까지 적용한 최종가에 가장 높은 태그 레벨 × 0.5%를 곱해 구매는 깎고 판매는 올린다(툴팁·실제 거래 공통, `TryQuoteTradeAt` 기반 경제 분석에는 미적용). 같은 방문 중 산 마을에 같은 품목 그대로 되팔면 구매 취소(`PuzzleDropResult.PurchaseCancel`)로 낸 금액을 그대로 돌려주고 상태 줄에 "구매 취소"로 표시한다. 의뢰 화물도 일반 화물과 같이 숙련 이득·판매 경험치를 받는다. 생산 태그가 없는 의뢰 화물의 완료 경험치는 의뢰 틀 `fallbackProficiencyTags`로 간다. 평판은 숙련 레벨 합으로 계산하며 따로 저장하지 않는다. 레벨이 오르면 거래·의뢰 결과 상태 줄 끝에 알림을 붙이고, 수첩 의뢰 탭에 숙련 목록을 보인다. 수치 원본은 `TrainventoryProficiencyTableData`다. 한 판 단위이며 컴파일·테이블 검증만 했고 플레이 확인은 하지 않았다.
- 휴식 화면은 시간 테이블의 `restMinutes`(현재 60분)만큼 시간 보내기와 야간의 다음 일출까지 대기를 제공한다. 시계·보유 시간·기한 판정과 6시간 경계의 시너지 정산을 진행하며 요금·이동 횟수·재입고는 변경하지 않는다. UI 배치는 프리팹(`Assets/Art/UI/StationActionsPanel.prefab`)에서 수정한다.
- 화물 기본 가치를 화물 정의에 통합하고 도시 재고를 7개 공유 프로필로 정리했다. 가격 표·옛 빚 일정 표·미사용 구매 할증 필드를 제거해 기초데이터를 포함해 JSON은 9개다. 기존 가격·배치 ID·슬롯 추첨 순서는 유지하며 사과를 일반·집산 후보에 추가했다.
- 최신 툴팁 프리팹·포인터·신선도 표시와 화물칸 폭 갱신을 병합했다. 툴팁 색·문구·폭은 최신 값을 유지하며 객차 바·인벤토리 보드·툴팁·지도 뷰의 런타임 배치 상수는 프리팹 직렬화 필드로 옮겼다. 신선도 판정 구간(`lowThreshold`·`mediumThreshold`)은 게임 규칙으로 `rules.freshness` 그룹으로 이동했다. 지도 줌·라벨/노선 우선순위·패딩·폰트 크기 수치도 지도 프리팹(`Assets/Art/PuzzleWorldMap.prefab`) 직렬화 필드로 이동했다. 역 메뉴 공통 제작과 씬 저장도 반영했다.
- 기초데이터의 필수 키 계약은 `Tools/MyJG/Tables/Generate Basic Data Contract`로 생성한다. 배설과 번식 설정은 `PuzzleSynergyTableData.animals`에 둔다.
- 공통 문구·서식·색·제작 치수·규칙 참조 ID·레이어 번호를 기초데이터로 옮겼다. 모든 UI 배치 수치는 프리팹으로 전환을 완료했다. 도메인 수치는 기존 표가 소유한다. 공통 로더와 필수 키·유한값·서식·색상 검증을 사용하며, 구조상 코드에 유지하는 값은 [BASIC_DATA](BASIC_DATA.md)에 명시했다.
- 시계는 `PuzzleInventoryService.Time`의 `PuzzleTimeManager` 하나이며 `ElapsedMinutes`가 원본이다. `ElapsedTime`도 분 단위 조회 별칭이다. 물품은 `OwnedMinutes`로 보유 시간을 보관하고, 성장 진행은 `GrowthElapsedMinutes`로 분리해 이동·재배치로 초기화되지 않는다.
- 노선 시간은 고정 폴라인 길이 합을 시간 테이블의 K(잠정 28픽셀/시간)로 나눈 뒤 시간 단위(`PuzzleTimeTableData.travelRoundingMinutes` 60분)로 올림한다(25시간 44분 → 26시간). 시각·기한·가치 누적은 계속 분 단위로 처리한다. 요금용 `distance` 1~6과 독립적이며 화면 확대율은 영향을 주지 않는다. 기존 시간 가중치는 제거했다.
- 이동·휴식·아침 대기는 게임 시작 기준 6시간 경계에서 그 시각의 배치로 실제 가치를 정산한다. 배설·식품 만료·성장·출산으로 바뀐 배치는 이후 정산에 반영한다. 지도에서 선택한 목적지의 호버 미래 가치도 같은 경계 계산을 사용한다.
- 동물의 배설은 인스턴스별 진행 상태로 흐르고 첫 발생은 이후 처음 맞는 달력 경계에 맞춘다. 같은 객차에서 상하좌우로 맞닿은 성체 소 두 마리는 48시간 후 송아지를 낳는다. 기존 쌍을 먼저 유지하고 한 마리당 한 쌍만 맺는다. 시간 경과 전 같은 쌍의 재결합은 진행도를 보존하고, 분리·상대 변경 상태로 시간이 흐르면 기존 쌍의 진행도를 지운다. 산출물을 놓을 자리가 없으면 그 개체·쌍만 `animals.completionHoldHours` 시간 직전에서 대기하고, 자리가 돌아오면 그 시간만큼 더 지나 완료한다. 공간 부족이 다른 동물의 사건이나 게임 진행을 멈추지 않는다.
- 산출물을 모두 놓지 못하면 그 개체·쌍만 완료 직전에서 대기하고 부분 생성은 하지 않는다. 송아지도 성체 자리가 없으면 성장 시계만 `growthHours - growthBlockedHours`에서 멈추고 이동·휴식은 정상 진행되며, 자리 확보 후 `growthBlockedHours`가 더 지나면 성체가 된다. 대기 상태는 모두 씬 로컬 세션 상태이며 시간 진행 사본에서만 흐르고 확정 시에만 반영한다. 배설·출산 분석 이벤트는 아직 없다.
- 최신 develop의 상품 팝업 라벨/수치 분리와 보유 효과 설명, 생선의 화물 보너스 제외 수정 및 지도 지역 색상 수정을 보존했다. 새 팝업의 미래 가치 라벨에 예상 정산 횟수를 표시하고 효과 설명 제목에 적용 주기를 표시한다.
- 시작 06:00, 일출 18시간(06:00~24:00), 야간 6시간(00:00~06:00)이다. 야간에는 시장 보드를 비활성화하고 모델에서도 거래·시장 내 재배치를 차단한다. 기차 내 재배치·이동은 허용한다. 아침 대기는 다음 06:00까지 시계·보유 시간을 진행하며 요금·이동 횟수는 변경하지 않으며 6시간 경계의 시너지는 정산한다.
- 일반 마을은 특산품·태그별 가격 규칙 없이 기본 구매 100%·판매 100%다. 지역 물가(`pricePercent`)는 모두 100%이고, 수도권 5곳은 같은 규칙으로 도시 기본 배율 구매·판매 125%, 귀함은 대표 특산품 5종(150/130 규칙, 최종 175/155)이며 추가 수요는 없다. 시장 정보와 지도 정보는 지역 물가 대신 도시의 전 품목 구매·판매 %를 표시한다. 수도권·일반 마을 재고는 집산품 3개·수입품 1개·랜덤 2개다.
- 거래와 시너지는 복수 태그를 공유한다. 거래 배율은 도시 기본 배율 + Σ(일치한 태그 규칙 − 100%)이며 하한 없이 0 이하도 허용한다(판매 배율이 음수면 팔 때 돈을 낸다). 시너지는 증가·감소를 구분하지 않고 100% + Σ(효과 − 100%)이며 하한 없이 음수 배율도 허용한다. 툴팁의 적용 규칙은 일치한 태그를 모두 표시한다. 구매·판매 모두 신선도 구간(60% 이상 100%·20~59% 80%·1~19% 50%)을 반영한 실제 가치에 배율을 적용한다. 판매한 화물은 실제 가치 그대로 시장에 남아 그 가치로 다시 살 수 있고, 가치가 음수인 화물은 판매(처분) 즉시 시장에서 사라진다. 판매 등급 흔함·일반·귀함·희귀(70/100/130/150%)의 수치는 `PuzzleTableData.sellGrades` 단일 원본이고 도시 태그 행은 `sellGradeId`로 참조하며 등급과 수치를 중복 저장하지 않는다. 희귀는 구매·판매 대칭 150% 등급으로 Map Editor에서 마을별 태그에 지정하며 행의 `buyPercent`도 150으로 맞춘다.
- 출발 시장만 새 화물 ID로 재입고한다. 도착 시장과 기차 화물은 보존한다.
- 생산 지역의 귀함 태그는 공업 음식·금속·목재, 광산 음식·기계·물, 목축 금속·곡물, 농업 기계·금속, 해안 금속·곡물·목재·기계다. 각 마을의 특산 태그는 흔함을 유지한다.
- 다르폴 3×3 도축대와 버튼은 Game 씬에 연결했다. 도시별 `PuzzleButcheryState`가 대기·작업·회수 상태를 보유하고, 작업 확정과 완료는 `butchery_committed`·`butchery_ready`로 기록한다.
- 에른아의 3×3 개조대는 확인 시 기계 프레임을 냉장 프레임으로 즉시 바꾼다. 같은 객차의 인접 음식은 냉장 프레임 한 개당 유통기한 소모율이 50% 줄며, 두 개부터 소모가 멈춘다. 이동 미리보기는 실제 시간 진행과 같은 냉장·만료 계산을 사용한다.
- 인접한 냉장 프레임과 음식 사이에는 냉장원에서 음식으로 향하는 녹색 화살표를 기차 객차에만 표시한다. 시간 정산과 같은 `PuzzleRefrigeration` 판정을 읽어 실제 소모율에 기여한 접촉만 보이고, 가치 화살표와 다른 레인을 쓰며 드래그로 숨긴 품목의 화살표는 숨긴다.
- 효과 품목은 화물 외곽 테두리 색을 따로 쓴다. 신선 보존 효과(`preservationEffect.enabled`)가 있는 품목(냉장 프레임·소금 자루)은 하늘색, 배설물 태그(`animals.wasteTag`) 품목(똥·폐기물)은 갈색이며 기차·시장·작업대 보드와 드래그 고스트에 같이 적용한다. 색은 기초데이터 `presentation.inventory.refrigerationOutline`·`wasteOutline`이다.
- 화물 정의는 18개다(냉장 프레임·송아지·똥 포함). 상한 음식은 기초데이터 `rules.PuzzleInventoryService.expiredFoodPieceId`에 따라 똥(`piece.poo`)으로 바뀌며 별도 식품 폐기물 품목은 제거했다. 최신 develop의 일반 가축 제거·소/소고기 재고 교체와 사용하지 않는 아이콘 삭제를 반영했다. 내구도 초기값·아이콘 배치 필드·음수 가격은 유지하고 미사용 희귀 고정 단가 분기는 제거했다. 표시 크기 안에서 아이콘 종횡비를 보존하고, 소처럼 표시 오프셋이 있는 아이콘도 물품과 함께 회전하도록 실제 표시와 드래그 미리보기의 공통 계산을 수정했다.
- Game 씬에서 바로 시작하며 재시작 시 해당 판을 초기화한다. 영구 저장·재개와 타이틀 진입 흐름은 미연결이다.

- 하단 예측 선택 버튼·이벤트·제작 코드·전용 테이블 항목을 제거했다. 하단 상태 안내는 전체 폭을 사용한다. 상환 금액은 거래 테이블의 1,500이며 제작 시 버튼 문구에도 반영한다.

- 지도 표시 경로 11개를 우회·분리해 직통선이 테라카·금융마을 등 비경유 역에 붙지 않도록 했다. 그리기는 선택적 `displayPoints`를 우선 사용하며 게임 시간/운임의 원본 `points`와 역 좌표는 보존한다. 교차점에는 아래 노선의 틈을 저장하고 지역 간→중립→지역 내부 순으로 그린다. 노선 굵기는 통일하고 중립 선·역 테두리는 같은 밝은 회색을 사용한다.

- 소문 로그는 `PanelBase` View와 별도 Presenter로 나눴다. 소문·의뢰 탭을 두고 `TavernRumorRecorded`·`QuestChanged`·`TimeAdvanced`를 세션별로 구독해 즉시 갱신하며 static 초기화 시 이벤트를 정리한다. 본문은 사전 배치된 TMP 한 개와 ScrollRect/Viewport/Content를 사용한다. 문구·형식은 기초데이터 `presentation.rumorLog.*`이며 배치는 프리팹(`Assets/Art/PuzzleTradeNotebook.prefab`)에서 수정한다.

## 기획과 구현의 정합성

- 콘솔·오류와 게임 분석 원본을 모두 LogKit으로 전송한다. 분석은 Telemetry, 테이블은 TelemetryRules/rules_chunk이며 로컬 보관과 동일한 원본을 사용한다. 테이블은 앱 세션 안에서 해시별 한 번만 보내며 초기 씬 전 로거 준비·종료 로그 선기록·전송 실패 재시도를 연결했다. 서버 수신 확인은 수행하지 않았다.

- 분석 로그 schemaVersion 3는 구매·판매·재배치의 의미와 drag/quick_transfer 방식을 분리한다. 시작 상태와 행동별 관측 변화(도시·자금·화물칸 수·위치·가치·내구도), 명시적 실패, 소문, 승패/재시작 경계를 기록한다. introduced는 생성 시각이 아닌 최초 관측이며 숨은 시장은 방문 시 관측한다. 적용 테이블 원본은 해시별 Rules 파일이다. 외부 복원 순서·좌표·결측/실패 해석은 [PLAY_LOG](PLAY_LOG.md), 보관은 [TELEMETRY](TELEMETRY.md)를 따른다. 집계는 외부에서 수행하며 이 변경의 컴파일·플레이 확인은 수행하지 않았다.

- 거래 예상 금액과 결제는 `PuzzleInventoryService.TryQuoteTrade`를 공유한다. 구매·판매 모두 신선도 반영 실제 가치에 합산한 도시 배율과 지역 물가(현재 모두 100%)를 곱하고 최종 반올림한다. 미사용 `rareValue` DTO·검증 예외·거래 분기는 제거했다.
- 앞선 재구매 예상가 조사에는 정정이 있다. 기존 Presenter가 시장 물품을 기본 가치로 보정하므로 항상 잘못 결제되는 상태는 아니었다. 현재는 시장에서도 보존된 실제 가치를 표시하고 구매 예상은 공유 견적의 기본 가치 기준을 쓴다.
- 툴팁에 기본 가치와 현재 배치의 정산 1회 효과를 추가하고 가능한 효과 설명과 구분했다. 새 행은 프리팹(`Assets/Art/PuzzleItemTooltip.prefab`)에 저장하며 배치는 프리팹에서 수정한다. 런타임에 행을 생성하지 않는다.
- 일반 효과 행은 기차의 현재 Placement와 세션에서 읽은 진행도를 설명 아래 녹색 한 줄로 덧붙인다. 번식은 붙어 있는 쌍이 있을 때만 그 쌍의 진행도를 쓰고 짝이 없으면 0으로 표시하며, 성장은 성장 품목만 own 시계를 보인다. 시장·도축·개조 보드에는 진행도를 보여주지 않고 배설·가치 정산에는 진행도 행이 없다.
- 공간 부족 대기에 새로 진입하면 번식 부모 두 개체와 성장 품목에 가치 변동과 독립된 미확인 알림을 남긴다. 같은 아이콘을 쓰므로 한쪽만 읽어도 다른 쪽은 남고, 툴팁을 열면 미확인 표시만 사라진다. 실제로 대기 중이면 빨간 `공간 부족` 진행도는 계속 표시되고, 보드 선택·객차 변경·이동/휴식 후 아이콘과 열린 툴팁을 다시 그린다.
- 기차 합계는 현재 선택 화물칸의 누적 실제 가치 합과 기본 가치 합을 표시한다. 시장에는 도시의 전 품목 구매·판매 배율을 표시하고 정보 영역을 늘렸다. 지도에서 미방문 마을은 지역 이름만 공개하며 물가·특산·수요는 방문 후 보여준다. 단, 소문을 들은 대상 마을은 이름 옆에 `?`를 붙이고 호버 시 해당 마을의 소문 기록만 미확인 정보로 공개한다. 방문 후 `?`를 지우고 확인된 정보를 표시하며 과거 소문은 로그에 남긴다. 로그 TMP의 리치 텍스트를 활성화해 날짜·장소 강조 태그를 해석한다.
- 기한 초과 패배도 승리와 같은 결과 패널에 연결했다. 결과 제목·안내를 구분하고 시간 정지·인벤토리 입력 차단·재시작·종료를 공유한다.
- 사과를 일반·집산 재고 후보에 연결했다. 빈자리 조건을 만족하는 한 칸 상품이며 별도의 고정 입고 수량은 추가하지 않았다.
- 에른아 고정 출발·고정 추가 수요·시작 목재 2개·음수 가치와 처분 비용·화물칸 간 무료 이동을 기획서의 잠정 규칙으로 명시했다. 자정마다 객차에 배설하는 규칙과 번식·인접 효과는 6장에 반영했다.
- 기획의 거리 평균을 약 2.84로, 지역 구성을 생산 5개 지역 21개 마을·수도권 5개·일반 4개로 정리했다. 과거 시간 기준과 HUD 문서의 글자 크기 설명도 현재 구조로 맞췄다.
- 전용 화물칸·내구도 감소/보호·농업 비료 매입·인카운터·검문소·기관차 효과·위치 교환·철도 투자·랜덤 시세·자동 경로·강제매각·저장/재개는 여전히 미정/확장안이다. 현재 규칙과 구분하며 이번 수정에서 구현하지 않았다.
- 노션 기획서 조회는 404로 실패했다. 소문 표시·지도 상태 유지·공업 노선 연결을 포함한 로컬 기획 수정은 노션 미반영 상태이며 공통 기준은 갱신하지 않았다. 재접속 시 이전 지도·시간·UI 미반영분과 함께 부분 병합해야 한다.
- 전체 미방문 지역 대상 추첨·대화 후 비활성화·증차 한 줄 문구를 유지한다. 책/페이지 방식은 우측 소문 로그로 교체했다. 구매 배율/금액의 유불리 색도 구매 관점으로 적용한다.
- 컴파일·테이블 초기화와 제작 도구의 씬/프리팹 연결을 반영했다. 플레이·입력·해상도별 가독성 확인은 수행하지 않았다.

## 경로 계산과 확인 범위

K=28 잠정치의 금융마을까지 최단 이동 합은 카르포트 27시간, 테라그라드 30시간, 포르베르 32시간, 에른아 공업역 35시간, 노르노바 36시간, 헤일포드 41시간이다. 대기·거래·자금 및 실제 플레이 가능성은 포함하지 않는다. 단일 레일은 3~26시간이다. 경제·야간 동선 밸런스는 플레이 검증 전 잠정 상태다.

- 로컬 기획서는 시간·지도·UI와 동물 시너지 규칙을 반영한다. 노션 접근이 막혀 지도·시간·UI와 6장의 동물·냉장 규칙이 미동기화 상태다. 공통 기준은 유지한다. [동기화 규칙](NOTION_SYNC.md)
- Unity CLI로 지도 프리팹과 역 메뉴 씬을 편집·저장했다. 커밋 전 Visual Studio의 Remove and Sort와 ProjectValidation의 검증 본체를 적용했다. 테이블은 정상이며 기존 Preload·Title 빌드 목록 누락과 Input Handling Both 안내가 남아 있다.
- 플레이·입력 실험·캡처는 수행하지 않았다. 남은 확인은 [BACKLOG](BACKLOG.md)에서 관리한다.
- 기술·운영 계약은 [관리 문서 안내](README.md)를 따른다.

- 지도는 최초 열기에서만 전체 보기를 적용하고 재열기에는 확대 배율·이동 위치를 유지한다. 행동 목록 복귀 버튼과 소문 탭의 폭·줄바꿈을 정리했다.
