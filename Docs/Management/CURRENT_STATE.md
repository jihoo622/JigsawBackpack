# 현재 구현 상태

구현 사실과 기획 대비 차이를 관리한다. 규칙·의도·설계 미정 사항은 [게임 기획서](<../게임 기획서.md>)를 본다. 구현 완료는 플레이 검증 완료를 뜻하지 않는다.

## 지도와 상환 목표

- 팀 작업 트래커의 확장 구상은 기획서 11장에 정리했다. 내구도·부산물·전용칸·인카운터·검문소·기관차 업그레이드·철도 투자·위치 교환의 구현 여부는 이번 문서 작업에서 확인하거나 변경하지 않았다. 티켓 대응과 상충 사항은 [작업 트래커 대응](TASK_TRACKER.md)을 본다.

- 생산 지역 26개 마을과 일반 마을 4개, 양방향 연결 43개를 적용했다. 공업·수도권은 각 5개, 나머지 생산 지역은 각 4개다. 레일 생성 seed 20265146의 `ProjectWorldData.json`(`projectMapData`)이 준 값 그대로 옮겼다. 노선·마을 이름·표시 좌표는 생성 데이터가 정하고, 지역 구분과 태그 경제는 기존 테이블을 유지한다. 마을 ID와 생성 역(`S01`~`S30`)의 대응, 좌표·폴리라인은 [MAP](MAP.md)과 [rail_map_layout_seed_20265146.json](rail_map_layout_seed_20265146.json)에 있다. **이번 판에서 ID 대응이 바뀌어** 같은 이름이 다른 `city.*`에 붙었다(라센턴은 `city.mine.dig`).
- 공업 5개 마을 모두 출발 가능한 경로지만 실제 시작 설정은 `city.industry.ironworks`(에른아 공업역)이다. 무작위 출발·출발지 선택은 연결하지 않았다.
- `city.capital.finance`(금융마을)을 `planningTargetCityId`로 지도에 표시하고, 같은 ID를 `debtCityId`에 넣어 **상환 가능 장소를 금융마을로 제한**했다. `CanClearGame`이 현재 도시를 확인한다. 기획서가 전제해 온 "금융마을에서 상환"이 구현과 일치하게 됐다.
- 지도 프리팹에 외부 데이터의 노드 30개·레일 43개의 폴리라인 85구간·시간 라벨 43개를 저장했다. 노선별 출발·도착 바인딩과 환승 표시도 갱신했다. 에디터 표시 이름·시간·노선 색상도 `Presentation`을 통해 저장하며, 재적용 도구는 `Assets/Scripts/Editor/Build/RailMapLayoutTool.cs`다.
- 외부 지형의 육지·바다·고도·강·경제 지역 경계를 배경 이미지로 적용했다. 지도 영역만 휠 확대·축소(35~250%)·드래그 이동하며, 전체 보기·현재 위치 버튼을 제공한다. 현재 역은 금색 링·확대된 역 테두리·배지·굵은 글씨로 강조한다. 제목·범례·도시 정보·조작 버튼은 확대 대상에서 제외하고 화면 가장자리 여백에 맞춰 고정했다. UI 구성 재적용은 `Tools/MyJG/Apply Map Presentation`을 사용한다.
- 줌은 지형과 역 사이 거리만 확대한다. 역 이름·마커·현재 위치 배지·시간 라벨·노선 굵기는 역배율로 보정한다. 이름은 현재 역·가리킨 역·목표 역·직접 연결 역 순으로 공간을 확보하고, 겹치면 배치 방향을 바꾸거나 생략한다. 시간 라벨은 85% 이상에서 이름·마커를 가리지 않는 위치에 표시한다. 실제 가독성·입력 확인은 아직 수행하지 않았다.
- 336시간 기한·조기 상환·기한 초과 패배 코드가 존재한다. 상환에는 버튼 입력이 필요하다. 옛 이동횟수 기반 빚 일정은 비활성이다.
- 시작 자금 200, 증차 50, 상환 금액 500을 임시 사용한다. 경제 밸런스는 미검증이다.

## 시간·거래·자산

- 시계는 `PuzzleInventoryService.Time`의 `PuzzleTimeManager` 하나다. `ElapsedTime`은 조회 별칭이며 이동당 한 번 시간을 진행한다. 물건의 `OwnedHours`는 실제 시간을 추적한다.
- 노선 시간 가중치는 레일 43개 중 39개가 1(8시간) · 3개가 2(16시간) · 1개가 4(32시간)다. 요금용 `distance`는 1~9로 가중치와 분리해 다른 값을 쓴다. 이전 판처럼 두 필드에 같은 값을 넣지 않는다.
- 가치 변화는 시간 가중치 단위, 보유 시간은 실제 시간 단위다. 호버 미래 가치는 8시간 기준이다.
- 일반 마을은 특산품·태그별 가격 규칙 없이 기본 구매 100%·판매 90%, 물가 100%다. 수도권 물가는 125%다. 수도권·일반 마을 재고는 집산품 3개·수입품 1개·랜덤 2개다.
- 거래와 시너지는 복수 태그를 공유하고 흔함을 귀함보다 우선한다. 구매는 기본 가치, 판매는 누적 실제 가치에 배율을 적용한다.
- 출발 시장만 새 화물 ID로 재입고한다. 도착 시장과 기차 화물은 보존한다.
- `purchaseMarkupPercent: 110`은 저장·검증만 하며 가격에 미적용이다. 적용 또는 제거는 기획 결정이 필요하다.
- 추가 수요는 마을별 임시 고정값이다. 랜덤 재추첨 방식은 미정이다.
- 상품 정의는 17개다. 원격의 소·소고기·사과·똥 정의와 이미지를 병합했고, 기존 과일·동물·고기·빈 상자는 유지한다. 내구도 초기값·아이콘 배치 필드·음수 가격·희귀 단가 처리도 원격 변경을 반영했다.
- Game 씬에서 바로 시작하며 재시작 시 해당 판을 초기화한다. 영구 저장·재개와 타이틀 진입 흐름은 미연결이다.

## 경로 계산과 확인 범위

| 공업 출발 마을 | 금융마을까지 최단 이동 시간 |
|---|---|
| 카르포트 | 1일 8시간 |
| 에른아 공업역 | 1일 16시간 |
| 노르노바 | 2일 |
| 헤일포드 | 2일 |
| 포르베르 | 2일 8시간 |

전 마을 기준 최장도 2일 8시간이다. 14일 기한 대비 최단 경로 여유는 8.4배로, 이전 판(3.2배)보다 시간적으로 여유롭다. 대신 레일 평균 요금이 8.0에서 8.8로 올랐고 이동 가능 횟수가 약 20회에서 약 37회로 늘어 총 운송비가 커진다. 막다른 역(차수 1) 8개는 왕복 2회의 시간 비용이 든다. 그래프 시간 합산 결과이며 자금·적재 요금·거래 수익과 실제 플레이 가능성을 검증한 결과가 아니다.

- 이번 지도 변경(마을 표시 이름·노선 수치·상환 장소 제한)은 로컬 기획서와 테이블에만 반영했다. 노션 페이지는 접근 수단이 없어 **미반영**이며, 공통 기준 데이터도 갱신하지 않았다. 연결이 회복되면 미반영분부터 반영한다 ([동기화 규칙](NOTION_SYNC.md)).
- Unity CLI로 지도 프리팹을 편집·저장했다. 검증 메뉴·플레이·입력 실험·화면 캡처는 실행하지 않았다.
- 플레이·입력 실험·캡처는 수행하지 않았다. 남은 확인은 [BACKLOG](BACKLOG.md)에서 관리한다.
- 기술·운영 계약은 [관리 문서 안내](README.md)를 따른다.
