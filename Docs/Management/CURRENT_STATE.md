# 현재 구현 상태

- 시작 지급 화차는 `startingTrain`의 5×5 외곽에서 13칸을 제거한 12칸이다. 화면 위에서 두 줄 전체·세 번째 줄 오른쪽 두 칸·맨 아래 네 번째 칸을 제외하며, 시작 목재 묶음 하나를 사용 가능한 칸으로 옮겼다. 시작 전용 보드는 구매 상품과 분리되어 있고 구매 화차는 `train`을 사용한다. 제거한 칸은 격자 표시·포인터·수동/자동 배치·성장·시간 진행 사본에서 함께 제외한다. Unity 컴파일·플레이·시각 확인은 남아 있다.

구현 사실과 기획 대비 차이를 관리한다. 규칙·의도·설계 미정 사항은 [게임 기획서](<../게임 기획서.md>)를 본다. 구현 완료는 플레이 검증 완료를 뜻하지 않는다.

- `Assets/Art/External/POC_06`에 사용 허가를 확인한 이미지 90개와 열차 시각 전용 UGUI 프리팹 3개를 추출했다. `feature/아트리소스`에서 Game 씬의 화물칸 선택 바·기관차 장식·역 메뉴 아이콘 4개, 지도 이동 연출의 측면 열차에 적용했다. 배치는 해당 프리팹에서 수정하며 퍼즐 보드/상품 아이콘은 유지한다. 라이선스·원본 커밋·파일별 출처/해시를 함께 보관한다. 플레이·해상도별 확인은 미수행이다([외부 에셋](ASSET_IMPORTS.md)).

## 지도와 목표

- 피벗(`ReTurnBase`, 2026-11-18): 기차 인벤토리 덱빌딩 무역 게임으로 목표를 바꿨다. 점수는 14일(56턴)이 끝난 뒤 결산할 때의 잔액이고 목표 잔액(`PuzzleTradeTableData.targetFunds` 1,500) 이상이면 승리한다. 상환·상환 도시(`debtCityId`)·클리어 비용(`gameClearCost`)은 없앴다. 출발지는 금융마을(`startCity`)이다. 영업 기간이 끝나면 이동·휴식·작업은 막히고(`TimeUp`) 거래만 할 수 있으며, 결산 버튼(`TryFinishRun`)으로 판을 끝낸다. 태그 숙련은 그대로 쓴다. 경제 시뮬레이터는 상환 전략을 걷어내고 기간 끝에 화물을 팔아 결산하도록만 바꿨다(전략 재설계는 남음).
- 화차는 역마다 파는 종류가 다르다(`PuzzleTableData.cities[].wagonProductIds`). 화차 상품 8종(`PuzzleTradeTableData.wagonProducts`)은 보드 모양(`board`: 4×4~7×5, 막힌 칸)과 냉장 여부가 다르고 가격은 120~450(판매가는 절반)이다. 화차 시설은 그 역의 화차만 보이고 다른 역 화차 구매는 `not_sold_here`로 막는다. 증차 기본비(`wagonAddCostBase`)는 없앴다. 냉장 외 화차 고유 효과(유물 효과)는 아직 없다.
- 의뢰 숙련 경험치를 되살렸다. 의뢰마다 숙련 태그 하나와 경험치(보상 × `proficiencyXpPercentOfReward`)를 정해 목록·상세에 보이고 완료 때 그 태그에 준다. 태그는 의뢰 틀 `proficiencyTags` 후보 → 화물 생산 태그 → 목적지 지역 생산 태그 → 전체 숙련 태그 순으로 고른다(예전에는 생산 태그 없는 신선 식품 의뢰가 경험치 0이었다).
- 지도에 전장의 안개를 넣었다(`PuzzleInventoryService.Fog.cs`). 기차로 들른 역(정차·통과)과 그 역에 연결된 역만 보이고(`Known`), 노선은 한쪽 끝을 들렀을 때만 보인다. 소문·수락한 의뢰로 알게 된 역은 위치·이름만 보인다(`Located`). 나머지 역·노선은 숨긴다. 안개는 고지도 층(`FogOfWar`)이 덮는다. 고지도 이미지(`PuzzleMapOldTerrain.png`, 지형 칸당 1픽셀·점 필터)는 바다·강이 밝고 땅이 채도 낮은 갈색이며, 들른 역 주변(90)과 달려 본 노선 양옆(28)만 칸 단위로 걷힌다. 달려 본 노선은 지역 색으로 밝게, 달려 보지 않은 노선은 짙은 회색으로 그리고, 노선 아래 외곽선 층(`SubwayMapTrackOutlines`)으로 어두운 외곽선을 두른다. 핵심 도시 8곳(`cities[].landmark`)은 처음부터 위치·이름만 보인다. 의뢰를 수락하면 목적지까지의 최단 경로 노선이 드러나고 경유역은 이름 없이 둔다(경로 계획 창 "미확인 역"). 경로 계획은 아는 노선만 잇고, 길을 모르면 `failureUnreachable`("아는 노선으로는 … 길을 모릅니다")를 보인다. 지도 검색도 보이는 역만 찾는다. 교역 정보 공개(방문 기준)는 그대로다.

- 노선 거리는 노선 표 `distance` 정수가 원본이며 운임의 거리 항과 의뢰 보상, 최단 경로 동률 판정에 쓴다. 이동은 노선과 관계없이 1턴(`PuzzleTimeTableData.travelTurns`)이다. 지도 선(`points`)은 그리기 전용이고, Map Editor의 노선 거리 자동 계산만 선 길이 ÷ 100을 반올림해 거리를 채운다.
- 시간 라벨 좌표 입력/드래그는 위치를 고정한다. 자동 배치·프리팹 위치 보정·런타임 위치 이동에서 고정을 존중하며 기존 저장 좌표도 유지한다. 고정 라벨과 충돌하는 역명은 다른 위치를 찾고, 라벨 자체가 역 표식/다른 고정 라벨/화면 경계에 걸리면 옮기는 대신 숨긴다. 선택/전체 고정 해제 후 자동 배치로 되돌릴 수 있다. 이동 시간 기준은 노션과 로컬 기획서의 해당 부분에 반영했고 기존 전체 동기화 기준은 유지했다.
- 새 노선의 시간 배경이 글자보다 위에 그려져 검은 상자만 보이던 문제를 수정했다. 시간 배경→글자 순서를 프리팹·레이아웃/지도 표기 제작 도구·런타임 초기 배치에서 고정한다.
- 맵 에디터에 선택/전체 시간 라벨 자동 배치와 역·노선·이름 수정 후 재배치를 추가했다. 길이상 중간부터 역/기본 역명/다른 라벨/다른 노선을 피하며, 공간이 없으면 기존 위치를 유지하고 노선을 알린다. 자동 재배치는 끌 수 있고 드래그 종료 시 계산해 Undo 한 번으로 복구한다. 자동 배치 입력·저장·플레이는 미확인이다.
- 기본요금은 현재 왕복 50개/방향별 100개 노선과 레이아웃, 기준값 `defaultBaseCost` 모두 3이다(경제 시뮬레이션 결과로 6에서 내렸다). 맵 에디터의 공통 설정에 기본요금 일괄 적용과 표시 선 길이 비례 정수 거리 계산을 추가했다. 초기 기준은 지도 길이 100당 거리 1이며 반올림·최소 1, 왕복 동일하게 적용한다. 선택/전체 거리 계산은 미리보기 후 초안에 적용하고 기존 거리·이동 시간은 자동으로 덮어쓰지 않는다. 새 노선에는 기준 기본요금과 계산 거리를 적용한다.
- `Tools/MyJG/Map Editor`를 추가했다. 역 추가/삭제·이름/지역/위치/중요도/시장 설정, 왕복 노선 추가/삭제/연결 변경·요금/거리/경유점, 지역 이름/우선순위/물가·소속 역 중요도, 지형 칠하기와 공통 이동 단가를 한 창에서 편집한다. 창 내부 캔버스가 지형·역·역명·노선·시간을 렌더링하며 역/선 클릭 선택과 역/경유점/시간 라벨 드래그, 휠 확대/축소·지도 이동·전체/선택 보기를 지원한다. 프리팹/Scene을 열지 않고 초안을 편집하며 표시 경로와 시간 경로를 동일하게 유지한다. 저장 시 테이블·레이아웃·프리팹과 역 참조를 함께 반영하며 실패 시 원본을 복구한다. 상세 필드는 창 내부 JSON으로 편집한다. 통합 도구의 저장·캔버스 입력·플레이는 미확인이다([사용법](MAP.md)).
- 지도 라벨은 지역 mapLabelPriority + 역 mapLabelImportance + 상태 가산점으로 배치한다. 축소 시 지역별 핵심 역부터 표시하고 한 지역의 표시 수가 늘면 다음 후보 점수에 감점을 준다. 확대 시 일반 역명을 추가하며 핵심은 굵은 큰 글씨로 구분한다. 수치 원본과 편집법은 [MAP](MAP.md)을 따른다.
- Tools/MyJG/Edit Rail Routes에서 표시 경유점을 Scene 핸들/좌표로 편집·추가·삭제하고 초안 Undo/Redo를 사용할 수 있다. 저장은 레이아웃 displayPoints와 지도 프리팹에 반영하며 역 연결·이동 시간 원본·요금은 유지한다. 에디터 어셈블리의 런타임 내부 필드 접근 오류를 수정하고 컴파일·실제 메뉴 열기·프리팹 연결·경유점 드래그/추가/삭제·Undo/Redo를 확인했다. Scene 창 자동 열기와 비활성 지도용 2D 편집 미리보기를 제공한다. 저장/프리팹 반영·플레이는 미확인이다.

- 연결된 역을 누르면 목적지·이동 턴·도착 시간대(밤 여부)·요금·이동 후 자금을 보여주는 확인창에서 확인·취소를 선택한다. 확인하면 이동 연출(`travelEffectSeconds`) 뒤 `Travel`로 운임을 내고 1턴을 진행해 도착하고, 도착 표시(`travelArrivalHoldSeconds`) 후 지도를 닫는다. 연출 중 취소하면 이동하지 않는다. 실패 시 지도에 이유를 표시한다. 지도 노선 라벨은 기본 운임(적재 요금 제외)이다.
- 확인창·연출 중 지도 입력과 중복 확인을 차단한다. 확인창의 Esc는 취소만 처리하고 일시정지를 함께 열지 않는다. 일시정지 입력도 복제한 액션 자산의 `UI/Cancel`로 전환했다. 확인창과 연출 UI는 지도 프리팹에 저장되어 있고 배치는 프리팹에서 수정한다. 플레이·입력 확인은 수행하지 않았다.

- 확장 검토안의 실제 상태는 아래 기획 대조 목록에 정리했다. 동물 부산물과 화물칸 간 이동은 이미 동작 경로가 있으며 내구도는 표시·저장만 한다. 전용칸·인카운터·검문소·기관차 효과·철도 투자·위치 교환은 게임 연결이 없다. 티켓 표기는 [작업 트래커 대응](TASK_TRACKER.md)을 본다.

- 생산 지역 25개 마을·수도권 5개·일반 마을 1개(메르트), 양방향 연결 51개(지역 내 33·지역 간 18, 막다른 역 없음)다. 원본 레일 생성 seed 20265146의 `ProjectWorldData.json`(`projectMapData`) 43개 연결에서 시작해 Map Editor로 노선·역 좌표를 고쳤다. 광산·공업 각 6개(오스베르는 광산, 테라그라드는 공업으로 옮겼고 라스부르크를 추가), 목축·수도권 각 5개(세르아를 목축으로 옮김), 해안·농업 각 4개다. 메르트–세르그라드 노선(R52)을 추가했다. 마을 이름은 생성 데이터, 지역 구분과 태그 경제는 기존 테이블을 따른다. 마을 ID와 생성 역(`S01`~`S30`)의 대응, 좌표·폴리라인은 [MAP](MAP.md)과 [rail_map_layout_seed_20265146.json](rail_map_layout_seed_20265146.json)에 있다. 역 ID는 `city.<역 이름 로마자>`(예: 라센턴 `city.rasenton`)로 지역과 무관하며, 바꿀 때는 Map Editor `ID 바꾸기`로 모든 참조를 함께 고친다.
- 공업 6개 마을 모두 출발 가능한 경로지만 실제 시작 설정은 `city.erna`(에른아 공업역)이다. 무작위 출발·출발지 선택은 연결하지 않았다.
- 금융마을(`city.finance`)이 출발지다. `planningTargetCityId`는 비워 지도 ★ 표식을 쓰지 않는다.
- 지도 프리팹에 노드 31개·레일 50개의 시간용 폴리라인 57구간과 표시 조각 57개·시간 라벨 50개를 저장했다. 노선별 출발·도착 바인딩과 환승 표시도 갱신했다. 에디터 표시 이름·시간·노선 색상도 `Presentation`을 통해 저장하며, 재적용 도구는 `Assets/Scripts/Editor/Build/RailMapLayoutTool.cs`다.

- 좌측에 기차·화물칸 바, 우측에 역 행동 목록(시장·술집·휴식·다른 역 이동)을 배치했다. 시장과 술집은 우측 하위 화면으로 열고 뒤로 가기로 목록에 돌아온다. 야간 시장은 진입과 모델 거래를 함께 차단한다. 최신 develop의 술집 대화 기능과 시장·술집 아이콘을 합쳤다. `TavernContent` 안에 기존 소식 UI를 연결했고 기차 조작은 좌측에서 유지한다. 지도 열림 중 역 메뉴 입력도 차단한다.

- 거래와 시너지는 복수 태그를 공유한다. 거래 배율은 도시 기본 배율 + Σ(일치한 태그 규칙 − 100%)이며 하한 없이 0 이하도 허용한다(판매 배율이 음수면 팔 때 돈을 낸다). 시너지는 증가·감소를 구분하지 않고 100% + Σ(효과 − 100%)이며 하한 없이 음수 배율도 허용한다. 툴팁의 적용 규칙은 일치한 태그를 모두 표시한다. 구매·판매 모두 신선도 구간(60% 이상 100%·20~59% 80%·1~19% 50%)을 반영한 실제 가치에 배율을 적용한다. 판매한 화물은 실제 가치 그대로 시장에 남아 그 가치로 다시 살 수 있고, 가치가 음수인 화물은 판매(처분) 즉시 시장에서 사라진다. 판매 등급 흔함·일반·귀함·희귀(70/100/130/200%)의 수치는 `PuzzleTableData.sellGrades` 단일 원본이고 도시 태그 행은 `sellGradeId`로 참조하며 등급과 수치를 중복 저장하지 않는다. 구매 배율은 도시 행의 `buyPercent`를 사용하며 Map Editor에서 희귀를 지정해도 그 값을 유지한다.
- 매일 오전 6시 개장에 모든 시장을 새 화물 ID로 재입고한다. 같은 개장 주기 내에 돌아오면 시장의 구매·판매 후 재고가 유지된다.
- 생산 지역의 귀함 태그는 공업 음식·금속·목재, 광산 음식·기계·물, 목축 금속·곡물, 농업 기계·금속, 해안 금속·곡물·목재·기계다. 각 마을의 특산 태그는 흔함을 유지한다.
- 작업장은 `TrainventoryWorkTableData`(작업: 입력·시간·산출·비용)와 `TrainventoryWorkshopTableData`(종류·보드·작업 ID·수수료 계수), 역의 `PuzzleTableData.cities[].workshopIds`로 정한다. 다르폴 도축장·노르노바 정제소·에른아 개조소가 공용 5×5 보드를 쓴다. 수수료는 화물마다 `⌈cost × costPercent/100⌉ + workHours × feePerHour + extraCost`의 합이고, 함께 맡긴 화물은 가장 긴 작업 시간이 지나면 모두 나온다. 맡길 때 시간을 쓰지 않으며 작업 대기 팝업은 쓰지 않는다. 반입·반출·확정은 `puzzle_action`(`workbench_load`·`workbench_unload`·`workbench_confirm`)으로, 완료는 `workbench_ready`로 기록한다(`actionId`는 작업장 ID, 개조 `modeId`는 작업 ID).
- 개조는 테이블의 작업 시간이 지난 뒤 에른아 작업대에서 회수한다. 같은 객차의 인접 음식은 냉장 프레임 한 개당 유통기한 소모율이 50% 줄며, 두 개부터 소모가 멈춘다. 이동 미리보기는 실제 시간 진행과 같은 냉장·만료 계산을 사용한다.
- 인접한 냉장 프레임과 음식 사이에는 냉장원에서 음식으로 향하는 녹색 화살표를 기차 객차에만 표시한다. 시간 정산과 같은 `PuzzleRefrigeration` 판정을 읽어 실제 소모율에 기여한 접촉만 보이고, 가치 화살표와 다른 레인을 쓰며 드래그로 숨긴 품목의 화살표는 숨긴다.
- 효과 품목은 화물 외곽 테두리 색을 따로 쓴다. 신선 보존 효과(`preservationEffect.enabled`)가 있는 품목(냉장 프레임·소금 자루)은 하늘색, 배설물 태그(`animals.wasteTag`) 품목(똥·폐기물)은 갈색이며 기차·시장·작업대 보드와 드래그 고스트에 같이 적용한다. 색은 기초데이터 `presentation.inventory.refrigerationOutline`·`wasteOutline`이다.
- 화물 정의는 18개다(냉장 프레임·송아지·똥 포함). 상한 음식은 기초데이터 `rules.PuzzleInventoryService.expiredFoodPieceId`에 따라 똥(`piece.poo`)으로 바뀌며 별도 식품 폐기물 품목은 제거했다. 최신 develop의 일반 가축 제거·소/소고기 재고 교체와 사용하지 않는 아이콘 삭제를 반영했다. 내구도 초기값·아이콘 배치 필드·음수 가격은 유지하고 미사용 희귀 고정 단가 분기는 제거했다. 표시 크기 안에서 아이콘 종횡비를 보존하고, 소처럼 표시 오프셋이 있는 아이콘도 물품과 함께 회전하도록 실제 표시와 드래그 미리보기의 공통 계산을 수정했다.
- Game 씬에서 바로 시작하며 재시작 시 해당 판을 초기화한다. 영구 저장·재개와 타이틀 진입 흐름은 미연결이다.

- 하단 예측 선택 버튼·이벤트·제작 코드·전용 테이블 항목을 제거했다. 정보 바(16~76)와 상태 안내(92~124)는 화면 위, 두 열은 140~920(780), 화물칸 바·정산·지도 버튼은 아래(936~1064)이며 보드 중심선은 Y 612다. 상환 금액은 거래 테이블의 1,500이며 제작 시 버튼 문구에도 반영한다.

- 지도 표시 경로 11개를 우회·분리해 직통선이 테라카·금융마을 등 비경유 역에 붙지 않도록 했다. 그리기는 선택적 `displayPoints`를 우선 사용하며 게임 시간/운임의 원본 `points`와 역 좌표는 보존한다. 교차점에는 아래 노선의 틈을 저장하고 지역 간→중립→지역 내부 순으로 그린다. 노선 굵기는 통일하고 중립 선·역 테두리는 같은 밝은 회색을 사용한다.

- 소문 로그는 `PanelBase` View와 별도 Presenter로 나눴다. 소문·의뢰 탭을 두고 `TavernRumorRecorded`·`QuestChanged`·`TimeAdvanced`를 세션별로 구독해 즉시 갱신하며 static 초기화 시 이벤트를 정리한다. 본문은 사전 배치된 TMP 한 개와 ScrollRect/Viewport/Content를 사용한다. 문구·형식은 기초데이터 `presentation.rumorLog.*`이며 배치는 프리팹(`Assets/Art/PuzzleTradeNotebook.prefab`)에서 수정한다.

## 기획과 구현의 정합성

- 콘솔·오류와 게임 분석 원본을 모두 LogKit으로 전송한다. 분석은 Telemetry, 테이블은 TelemetryRules/rules_chunk이며 로컬 보관과 동일한 원본을 사용한다. 테이블은 앱 세션 안에서 해시별 한 번만 보내며 초기 씬 전 로거 준비·종료 로그 선기록·전송 실패 재시도를 연결했다. 서버 수신 확인은 수행하지 않았다.

- 분석 로그 schemaVersion 3는 구매·판매·재배치의 의미와 drag/quick_transfer 방식을 분리한다. 시작 상태와 행동별 관측 변화(도시·자금·화물칸 수·위치·가치·내구도), 명시적 실패, 소문, 승패/재시작 경계를 기록한다. introduced는 생성 시각이 아닌 최초 관측이며 숨은 시장은 방문 시 관측한다. 적용 테이블 원본은 해시별 Rules 파일이다. 외부 복원 순서·좌표·결측/실패 해석은 [PLAY_LOG](PLAY_LOG.md), 보관은 [TELEMETRY](TELEMETRY.md)를 따른다. 집계는 외부에서 수행하며 이 변경의 컴파일·플레이 확인은 수행하지 않았다.

- 분석 로그 schemaVersion 9: 턴제 재설계로 경로 계획 `route_planned`의 `totalMinutes`를 `totalTurns`로 바꾸고, 출발 `depart` 기록을 없앴다(이동은 `travel` 한 건, `requestedHours` 6). 시간은 행동(`travel`·`rest`·`wait_for_daylight`·`wait_for_workbench`)으로만 흐르며 1시간마다의 `advance_time`은 남기지 않는다. 시간 필드는 정수 게임 시간(`elapsedHours`·`requestedHours`·`deadlineHours`)이다. 8은 실시간 시계, 7은 3시간 턴, 6 이하는 분 단위다. 분석 사이트(`logkit-analytics-trainventory`)는 아직 6(분) 기준이다. 6에서 작업대 보드(`workbench:<cityId>:<actionId>`)를 관측하고 작업대 확정, 화차 냉장 설치(`install_wagon_modification`), 화차 순서 변경(`reorder_wagon`), 증차 상품 ID, 같은 ID 품목 변화(`transformed`), 경유역 정차 토글(`route_stop_changed`), 역 하위 화면(`station_screen`)을 기록한다. 컴파일만 확인했고 플레이로 로그를 뽑아 보지는 않았다. 서버 소비자 호환 여부는 미확인이다.
- 거래 예상 금액과 결제는 `PuzzleInventoryService.TryQuoteTrade`를 공유한다. 구매·판매 모두 신선도 반영 실제 가치에 합산한 도시 배율과 지역 물가(현재 모두 100%)를 곱하고 최종 반올림한다. 미사용 `rareValue` DTO·검증 예외·거래 분기는 제거했다.- 앞선 재구매 예상가 조사에는 정정이 있다. 기존 Presenter가 시장 물품을 기본 가치로 보정하므로 항상 잘못 결제되는 상태는 아니었다. 현재는 시장에서도 보존된 실제 가치를 표시하고 구매 예상은 공유 견적의 기본 가치 기준을 쓴다.
- 툴팁에 기본 가치와 현재 배치의 정산 1회 효과를 추가하고 가능한 효과 설명과 구분했다. 새 행은 프리팹(`Assets/Art/PuzzleItemTooltip.prefab`)에 저장하며 배치는 프리팹에서 수정한다. 런타임에 행을 생성하지 않는다.
- 일반 효과 행은 기차의 현재 Placement와 세션에서 읽은 진행도를 설명 아래 녹색 한 줄로 덧붙인다. 번식은 붙어 있는 쌍이 있을 때만 그 쌍의 진행도를 쓰고 짝이 없으면 0으로 표시하며, 성장은 성장 품목만 own 시계를 보인다. 시장·도축·개조 보드에는 진행도를 보여주지 않고 배설·가치 정산에는 진행도 행이 없다.
- 공간 부족 대기에 새로 진입하면 번식 부모 두 개체와 성장 품목에 가치 변동과 독립된 미확인 알림을 남긴다. 같은 아이콘을 쓰므로 한쪽만 읽어도 다른 쪽은 남고, 툴팁을 열면 미확인 표시만 사라진다. 실제로 대기 중이면 빨간 `공간 부족` 진행도는 계속 표시되고, 보드 선택·객차 변경·이동/휴식 후 아이콘과 열린 툴팁을 다시 그린다.
- 기차 합계는 현재 선택 화물칸의 누적 실제 가치 합과 기본 가치 합을 표시한다. 시장에는 도시의 전 품목 구매·판매 배율을 표시하고 정보 영역을 늘렸다. 지도에서 미방문 마을은 지역 이름만 공개하며 물가·특산·수요는 방문 후 보여준다. 단, 소문을 들은 대상 마을은 이름 옆에 `?`를 붙이고 호버 시 해당 마을의 소문 기록만 미확인 정보로 공개한다. 방문 후 `?`를 지우고 확인된 정보를 표시하며 과거 소문은 로그에 남긴다. 로그 TMP의 리치 텍스트를 활성화해 날짜·장소 강조 태그를 해석한다.
- 기한 초과 패배도 승리와 같은 결과 패널에 연결했다. 결과 제목·안내를 구분하고 시간 정지·인벤토리 입력 차단·재시작·종료를 공유한다.
- 사과를 일반·집산 재고 후보에 연결했다. 빈자리 조건을 만족하는 한 칸 상품이며 별도의 고정 입고 수량은 추가하지 않았다.
- 에른아 고정 출발·고정 추가 수요·시작 목재 2개·음수 가치와 처분 비용·화물칸 간 무료 이동을 기획서의 잠정 규칙으로 명시했다. 자정마다 객차에 배설하는 규칙과 번식·인접 효과는 6장에 반영했다.
- 기획의 거리 평균을 약 2.84로, 지역 구성을 생산 5개 지역 21개 마을·수도권 5개·일반 4개로 정리했다. 과거 시간 기준과 HUD 문서의 글자 크기 설명도 현재 구조로 맞췄다.
- 전용 화물칸·내구도 감소/보호·농업 비료 매입·인카운터·검문소·기관차 효과·위치 교환·철도 투자·랜덤 시세·자동 경로·강제매각·저장/재개는 여전히 미정/확장안이다. 현재 규칙과 구분하며 이번 수정에서 구현하지 않았다.
- 노션 기획서 조회는 404로 실패했다. 소문 표시·지도 상태 유지·공업 노선 연결·마을 작업대·행동 소문·희귀 판매 배율을 포함한 로컬 기획 수정은 노션 미반영 상태이며 공통 기준은 갱신하지 않았다. 재접속 시 이전 지도·시간·UI 미반영분과 함께 부분 병합해야 한다.
- 선호 소문은 `PuzzleRumorTableData.firstPreference`의 라센턴·기계 한 건이며, 시작 마을의 첫 대화에서만 0순위로 선택해 "라센턴에서 기계를 선호한데요."로 표시한다. 이동 후에는 후보가 남은 희귀 수요, 그다음이 특산·마을 행동의 종류 균등 추첨 후 후보 균등 추첨이다. 현재·방문 마을과 이전에 소문이 난 대상 마을은 모든 종류에서 제외한다. 기존의 다른 마을·태그 선호 기록은 "비싸게 거래된데요."로 표시한다. 한 번 대화하면 다음 방문까지 대화 버튼이 비활성화된다. 지도 `?` 배지는 소문 기록이 있고 아직 방문하지 않은 마을에만 보이고 도착 처리 직후 사라지며, 기록은 수첩·요약과 마을 중복 방지에 계속 쓰인다.
- 컴파일·테이블 초기화와 제작 도구의 씬/프리팹 연결을 반영했다. 플레이·입력·해상도별 가독성 확인은 수행하지 않았다.

## 경로 계산과 확인 범위

금융마을까지 최소 구간 수(= 이동 턴)는 카르포트·테라그라드 5, 포르베르·에른아 공업역·노르노바 6, 헤일포드 7이다(그 경로의 노선 거리 합 7·8·8·9·10·11). 휴식·작업·거래·자금 및 실제 플레이 가능성은 포함하지 않는다. 단일 레일의 거리는 1~7이다. 턴제 재설계에서 경제 수치는 바꾸지 않았고 6시간 미만 규칙(작업·섭취·공간 대기 3시간)만 1턴으로 올렸다. 모든 이동이 1턴이라 장거리 직통의 시간 비용이 사라졌으므로 경제·야간 동선은 플레이 검증 전 잠정 상태다.

- 로컬 기획서는 시간·지도·UI와 동물 시너지 규칙을 반영한다. 노션 접근이 막혀 지도·시간·UI와 6장의 동물·냉장 규칙이 미동기화 상태다. 공통 기준은 유지한다. [동기화 규칙](NOTION_SYNC.md)
- Unity CLI로 지도 프리팹과 역 메뉴 씬을 편집·저장했다. 커밋 전 Visual Studio의 Remove and Sort와 ProjectValidation의 검증 본체를 적용했다. 테이블은 정상이며 Input Handling Both 안내가 남아 있다.
- 빌드 씬은 Preload → Title → Game 모두 활성이다. Preload의 `PreloadController`가 `AppBootstrap`으로 LogKit 설정·분석 로그 세션·테이블 로드/검증을 한 번에 하고(LogKit 수집·전송 설정은 Preload `LogKit` 오브젝트의 GameLogger Inspector), 테이블이 올바를 때만 `FlowTableData`의 다음 씬(Title)으로 넘어간다. Title은 시작(→ Game)·종료 버튼만 있다(`Assets/Art/UI/Title/TitleScreen.prefab`, 문구 `presentation.title.*`). 에디터 Play는 `Tools/MyJG/Play From Preload`(기본 켬)로 항상 Preload에서 시작해 Play 직전에 열려 있던 씬으로 돌아간다. 끄거나 빌드 첫 씬이 아닌 씬으로 시작하면 `AppBootstrap`이 첫 씬 Awake 전에 같은 준비를 하고 경고를 남긴다. 컴파일·테이블 검증·씬 참조만 확인했고 플레이 확인은 하지 않았다.
- 플레이·입력 실험·캡처는 수행하지 않았다. 남은 확인은 [BACKLOG](BACKLOG.md)에서 관리한다.
- 기술·운영 계약은 [관리 문서 안내](README.md)를 따른다.

- 지도는 최초 열기에서만 전체 보기를 적용하고 재열기에는 확대 배율·이동 위치를 유지한다. 행동 목록 복귀 버튼과 소문 탭의 폭·줄바꿈을 정리했다.
