# JigsawBackpack 구현 계획

## 목적과 범위
- 요구사항은 `Docs/Management/Archive/JigsawBackpack 기획서.md`와 초기 직각삼각형 퍼즐 설계(현재 저장소에 별도 문서 없음)를 따른다. `Assets/Resources/Images/puzzles1.png`는 원본 실루엣 참고 자료다. 이 문서는 구현 순서와 작업 계약을 정리한다.
- 2D 화면에서 왼쪽 팔레트의 조각을 오른쪽 5×5 인벤토리로 드래그하고, 회전·배치·재배치·삭제한다. 게임 규칙, 저장, 점수, 승리 조건은 추가하지 않는다.
- 작업 전 `AGENTS.md`, `README.md`, `Docs/Management/TABLES.md`를 읽는다. 구현이 바뀌면 관련 문서를 함께 갱신한다. 테스트·플레이·검증용 실험은 사용자가 요청할 때만 한다.

## 기획 해석과 구현 가정
- **기본 슬롯**은 격자 한 칸이며, **조각**은 상하좌우로 연결된 하나 이상의 기본 슬롯을 가진 팔레트 항목이다. 참고 이미지의 독립 실루엣 7종을 테이블에 정의한다.
- 조각 로컬 좌표는 외접 사각형의 왼쪽 위가 `(0,0)`이며 오른쪽과 아래로 증가한다. `(0,0)`은 비어 있을 수 있다. 보드 좌표는 왼쪽 아래가 `(0,0)`이며 오른쪽과 위로 증가한다. 각 슬롯의 네 변은 `Flat`, `In`, `Out` 중 하나이고 같은 조각의 내부 인접 변은 양쪽 모두 `Flat`이다.
- 조각의 슬롯 좌표와 변 방향을 90도씩 함께 시계방향으로 회전한다. 회전한 좌표에서 최소 X·Y를 빼 정규화하고, 원본 슬롯과의 대응을 유지한 채 모델에서 보드 좌표로 변환한다. 변의 상태 값은 회전해도 유지된다. 바인딩은 Input Actions에 명시한다.
- 모든 기본 셀은 격자 안에 있어야 한다. 돌출부는 빈 칸이나 격자 경계 밖을 향해 나갈 수 있다. 인접 칸에 다른 조각이 있으면 두 변이 `Out`/`In`인 조합만 돌출과 결합한다. 돌출이 없는 `Flat`/`Flat`, `Flat`/`In`, `In`/`In`도 허용한다. `Out`/`Flat`, `Out`/`Out`은 양쪽 방향 모두 거부한다.
- 팔레트는 새 조각 하나를 제공한다. 보드에서 일반 드래그는 개별 조각을 이동하고, 좌·우 Shift를 누른 채 시작하면 인접한 `Out`–`In`의 연쇄 연결 전체를 선택한다. 모델은 포인터를 누른 순간 이동 대상을 고정하고 판정에서 해당 대상의 기존 점유를 제외한다. 유효한 보드 위치에 놓으면 배치를 한 번에 적용한다. 팔레트 반환은 개별·단독 묶음을 삭제하며, 둘 이상인 묶음은 이동을 취소한다.
- 팔레트 드래그를 팔레트에 놓는 경우 아무 변화가 없다. 보드에 겹치는 좌표와 팔레트가 겹치지 않도록 화면을 구성한다. 잡은 셀을 기준점으로 유지하여 포인터에 맞춰 정렬하고 회전 시에도 그 셀을 기준으로 회전한다.
- 위 가정은 미정 사항을 실행 가능한 형태로 정한 것이다. 기획 의도와 다르면 구현 전 이 문서와 기획서를 함께 수정한다.

## 공통 설계 계약
- 데이터는 `Assets/Resources/Tables` JSON → `GameTables.cs`/`GameTableRecords.cs` DTO → `TableManager` → `GameTableRules`의 기존 4계층을 따른다. 보드 크기, 조각 ID, `slotCount`, 슬롯 좌표와 네 방향 상태의 원본은 테이블이다. 동작 수치를 씬이나 코드에 중복 저장하지 않는다.
- 팔레트는 ID 오름차순으로 표시한다. 배열 순서나 에셋 이름에 의미를 두지 않는다. `PuzzleInventoryUI`는 공용 에셋을 참조하고, View는 방향별 상태로 `Flat`·`In`·`Out` 스프라이트를 선택한다.
- 게임 상태와 배치 판정은 모델이 소유하고 Presenter가 모델·View·입력을 연결한다. View는 프리팹에 미리 배치한 표시 슬롯을 재사용한다. 배치·고스트·외곽선은 보드의 최대 점유 셀 수를 수용하고 팔레트는 원본 조각의 슬롯 수를 수용한다.
- 입력은 `Assets/InputSystem_Actions.inputactions`의 액션과 Input System UI 모듈을 사용한다. 좌표 변환은 UI 카메라와 Canvas를 고려하고 구 Input API나 직접 장치 폴링을 쓰지 않는다. 필요한 액션 자산은 복제해 사용하고 활성화·해제 및 정리를 대칭으로 한다.
- 패널이 필요하면 `PanelBase`와 `startOpen` 규약을 따른다. 색·표시 문구는 `Presentation`, 설명 원문은 테이블에 둔다. 도메인 이벤트가 필요한 경우 `GameEvents`로 발행하고 구독을 대칭 정리한다. 분석 이벤트는 실제 요구가 생길 때만 기존 기록 계약에 연결한다.
- 런타임 코드는 전역 네임스페이스, 에디터 코드는 `Editor` 폴더를 사용한다. asmdef·테스트 asmdef를 추가하지 않고 정적 상태가 생기면 SubsystemRegistration에서 초기화한다.
- 검증은 사용자가 직접 진행한다. 컴퓨터 조작 등을 활용하여 직접 검증하지 않는다.

## 병렬 작업 배분

사용자가 아래 워커를 직접 지정한다. 별도 오케스트레이션이나 자동 위임을 전제하지 않는다. 각 워커는 이 문서 전체와 `AGENTS.md`를 읽고, 지정된 소유 범위만 수정한다. 다른 워커의 미완성 변경을 되돌리지 않으며, 소유 범위 밖의 수정이 필요하면 소유자에게 요청한다.

| 워커 | 책임과 수정 소유권 | 병렬 작업 중 수정하지 않는 것 | 완료 후 전달물 |
|---|---|---|---|
| A: 데이터·모델 | `Assets/Resources/Tables/`의 조각 데이터, `Assets/Scripts/Runtime/Data/`의 DTO·로더·검증, 신규 인벤토리 모델·배치 판정 코드 | Game 씬, UI 에셋·View, Input Actions, Presenter | 조각 ID와 데이터 형식, 모델 API, 판정 결과·거부 사유, 변경 파일과 남은 연결 사항 |
| B: 시각 에셋·View | 삼각형·외곽선 에셋과 UI 프리팹, 인벤토리 View 코드, `Presentation`의 표시 색·문구 | Game 씬, 테이블·모델, Input Actions, Presenter | 공용 에셋의 상태별 참조와 방향, 표시 용량, View API 및 좌표·피벗 기준 |
| C: 입력·Presenter | `Assets/InputSystem_Actions.inputactions`, 신규 입력 처리와 인벤토리 Presenter 코드 | Game 씬, 테이블·모델, UI 프리팹·View·`Presentation` | 액션 맵·액션 이름, Presenter API와 필요한 씬 참조, 입력 활성화·정리 조건 |
| D: 통합 | `Assets/Scenes/Game.unity`, 필요한 씬 연결, `README.md`, `Docs/Management/TABLES.md`와 이 계획의 실제 상태 | A·B·C 소유 파일의 병렬 수정 | 연결된 씬, 참조 목록, 미해결 사항과 미실행 확인 항목 |

### 착수와 의존 순서
1. **계약 확정 — A, B, C의 구현 전:** A는 조각 ID, 슬롯·회전·배치 판정 계약을 정한다. B는 공용 삼각형의 슬롯 크기·중심 피벗과 View 표시 입력을 확인한다. C는 포인터가 잡은 원본 슬롯과 모델의 후보 포즈를 전달하는 방식을 확인한다. 계약이 바뀌면 소비 코드와 함께 갱신한다.
2. **병렬 구현 — A·B·C:** A는 단계 1의 데이터 부분과 단계 2를 담당한다. B는 단계 1의 시각 에셋 부분과 단계 3의 프리팹·View 부분을 담당한다. C는 단계 4의 Input Actions와 Presenter를 담당한다. C는 합의된 API에 맞춰 작성하며, 실제 모델·View가 준비되기 전 통합 완료로 보고하지 않는다.
3. **통합 — D:** A·B·C의 결과와 전달물을 받은 뒤 단계 3의 씬 구성 및 단계 5를 수행한다. 씬 배치와 직렬화 참조 연결은 D만 수행한다. API·에셋 불일치는 해당 소유 워커가 수정한 후 D가 다시 연결한다. 문서에는 실제 완료된 내용만 반영한다.
4. **확인:** 아래 시나리오는 사용자가 별도로 요청할 때만 실행한다. 확인을 요청받지 않았다면 각 워커와 D는 수행하지 않은 플레이·테스트 결과를 주장하지 않는다.

### 공유 작업 시 주의
- 하나의 Unity 프로젝트를 여러 Unity 에디터 인스턴스에서 동시에 열어 편집하지 않는다. 에디터가 필요한 에셋 제작과 씬 연결은 사용자 지정 순서로 진행한다. 파일을 직접 편집하는 병렬 작업도 위 소유권을 따른다.
- 같은 프리팹·스크립트·`.meta` 파일은 한 워커만 수정한다. B가 만든 프리팹을 D가 수정해야 한다면 B가 작업을 마치고 명시적으로 넘긴 뒤 D가 수정한다. 원본 이미지 `puzzles1.png`는 읽기 전용이다.
- A가 기존 샘플 테이블을 변경할 때 소유 범위 밖의 해금 코드 수정이 필요하면 해당 변경을 D에게 알리고, 충돌하지 않는 시점에 담당자를 정해 처리한다.
- 계약이 아직 없으면 임시 API나 하드코딩된 조각 데이터를 다른 워커의 소유 파일에 만들지 않는다. 인터페이스가 확정되기 전에도 원본 이미지 분석이나 독립적인 에셋 준비는 가능하다.

## 구현 단계

### 1. 데이터와 조각 원본 정의 — A·B
**대상:** `Assets/Resources/Tables/`, `Assets/Scripts/Runtime/Data/`, `Assets/Resources/Images/puzzles1.png`.

1. **A:** 이미지의 7개 실루엣을 슬롯 단위로 해석해 고유 ID, 설명, `slotCount`, 각 슬롯의 좌표와 네 방향 상태를 기록한다. 최소 X·Y는 각각 0이다.
2. 직렬화 DTO를 추가하고 `TableManager`에 로드와 ID 조회를 연결한다. 기존 샘플 테이블을 제거·변경한다면 이를 참조하는 기존 검증과 해금 코드도 함께 정리해 프로젝트가 유효한 상태를 유지한다.
3. `GameTableRules`에서 격자 크기, ID·설명, 슬롯 수와 좌표, 연결성, 방향별 상태 및 내부 연결 면을 항목별로 검증한다. 초기화는 `RequireValid()` 이후에 진행한다.
4. **B:** 북쪽을 향하는 공용 삼각형 `Flat`·`In`·`Out`과 상태별 외곽선을 에셋으로 준비한다. 크기와 슬롯 중심 피벗을 통일하고, `PuzzleSlot`에 네 방향의 표시 요소를 배치한다.

**완료 기준:** 7개 원본을 테이블의 슬롯 좌표와 방향별 상태로 복원하고, 공용 에셋으로 표시할 수 있다. 잘못된 데이터는 항목별 오류로 수집된다.

### 2. 격자 모델과 배치 판정 — A
**대상:** `Assets/Scripts/Runtime/`의 신규 인벤토리 모델·규칙 코드.

1. 씬 로컬 모델에 조각 인스턴스 ID, 조각 정의 ID, 기준 셀, 회전 상태와 셀별 점유를 보관한다. 팔레트 정의와 배치 인스턴스를 분리한다.
2. 회전된 상대 셀과 네 변을 산출하고, 후보 셀이 모두 격자 내부인지, 다른 조각이 점유하지 않는지, 인접 조각의 변이 결합 규칙에 맞는지 판정한다. 같은 조각 내부 면은 검사하지 않는다.
3. 기존 조각 이동 시 자기 자신의 기존 점유를 제외해 후보를 판정하고, 성공할 때만 이전 점유를 교체한다. 실패·취소는 위치와 회전을 보존한다. 삭제는 해당 인스턴스의 점유만 해제한다.
4. 모델은 배치 가능 여부와 거부 사유를 반환한다. 검사와 실제 적용은 같은 판정 경로를 사용해 미리보기와 결과가 어긋나지 않게 한다.

**완료 기준:** 다중 셀과 네 방향 회전에서 기본 셀의 경계 이탈을 거부하고 돌출부의 경계 이탈을 허용한다. 점유 중복 및 인접 변 충돌을 거부하고, 실패한 변경은 모델을 바꾸지 않는다.

### 3. 2D 씬과 정적 UI 구성 — B·D
**대상:** `Assets/Scenes/Game.unity`, UI 프리팹·스프라이트, `Presentation`.

**현재 상태.** Game 씬의 Screen Space Overlay Canvas(1920×1080 기준, Expand) 아래에 `PuzzleInventoryUI`가 있다. 프리팹에는 팔레트 7곳에 각각 5슬롯, 보드 배경·배치·고스트·외곽선에 각각 25슬롯과 드래그 조작 안내가 준비되어 있다.

1. **D:** Game 씬에 2D 표시를 구성하고 Canvas와 Input System UI 모듈을 연결한다. 왼쪽에는 7종 팔레트, 오른쪽에는 5×5 격자 및 조각 표시 영역을 배치한다. 기존 Preload → Title → Game 빌드 씬과 흐름 테이블 계약은 유지한다.
2. **B:** 팔레트·격자·배치·고스트·외곽선 슬롯을 프리팹에 미리 구성한다. 외곽선은 후보 포즈와 판정 결과를 사용하며 같은 조각의 내부 인접 변을 숨긴다. **D:** 프리팹을 씬의 Canvas에 연결한다.
3. **B:** View에는 표시 참조와 표시 갱신만 둔다. **C:** 모델 접근과 조작 전환은 Presenter에서 담당한다. 팔레트 원본은 배치 상태와 무관하게 변경하지 않는다.

**완료 기준:** 플레이 중 UI 오브젝트를 생성하지 않고, 두 영역과 모든 조각 및 미리보기를 표시할 수 있다. 시각 상태는 모델의 격자 좌표와 일치한다.

### 4. 입력과 드래그 상호작용 — C
**대상:** `Assets/InputSystem_Actions.inputactions`, 인벤토리 입력 처리·Presenter. View와 Game 씬 연결은 각각 B와 D의 소유다.

1. 포인터 위치·누르기·해제, 회전 및 취소를 Input Actions에 정의하고 UI 이벤트 경로와 연결한다. 회전은 기본 `R`, 취소는 `Escape`로 설정한다. UI 모듈의 Submit/Cancel과 충돌하지 않도록 액션 맵 활성 상태를 조정한다.
2. 팔레트 또는 기존 조각에서 드래그를 시작하고 잡은 셀을 보존한다. `GroupMoveModifier`는 좌·우 Shift를 읽으며, 보드 위 포인터와 Shift 상태에 따라 이동 대상을 강조한다. 드래그 중 고스트는 잡은 슬롯에 정렬하고, 보드 위에서는 전체 후보의 배치 가능 여부를 외곽선 색으로 표시한다.
3. 놓는 영역과 후보 유효성에 따라 배치·이동·삭제·취소를 위 계약대로 처리한다. 화면 밖 해제, 입력 취소, 패널 비활성화와 씬 종료 시 드래그 상태 및 표시를 정리한다.

**완료 기준:** 팔레트 원본은 유지되고 배치된 조각은 이동·회전·팔레트 반환이 가능하다. 무효 위치에는 배치되지 않으며 취소 시 이전 상태가 보존된다.

### 5. 연결 정리와 문서 갱신 — D
**대상:** 관련 씬·프리팹, `README.md`, 필요한 경우 `Docs/Management/TABLES.md`.

**현재 상태:** `PuzzleInventoryPresenter`와 `PuzzleInventoryInput`을 Game 씬의 프리팹 인스턴스 루트에 추가했다. Presenter는 같은 루트의 View와 `SceneServices`의 씬 로컬 모델을 사용한다. Input의 `uiInputModule`은 EventSystem의 모듈을 참조하고, 해당 액션 자산의 `UI` 맵과 `PuzzleInventory/Rotate`, `PuzzleInventory/Cancel`을 사용한다. Preload·Title에서 Game으로 넘어가는 실행 컴포넌트와 Play Mode 확인은 남아 있다.

1. Game 씬의 Presenter와 Input을 공용 에셋과 표시 슬롯을 가진 View에 연결한다. 참조가 누락되거나 표시 용량이 부족하면 초기화 오류로 알린다.
2. 실제 구현된 구조와 남은 제약만 README에 짧게 반영하고, 테이블 구성이 달라졌다면 테이블 문서를 갱신한다. 계획 문서의 완료 여부를 사실에 맞게 갱신한다.
3. 사용자가 별도로 검증을 요청한 경우에만 아래 확인 항목을 실행하고 결과를 보고한다. 요청이 없다면 실행하지 않는다.

**완료 기준:** 씬 연결과 문서가 같은 구현을 가리키며, 실행하지 않은 검증을 완료로 기록하지 않는다.

## 사용자 요청 시 확인할 시나리오
- 각 팔레트 원본에서 조각을 반복 배치해 원본이 유지되는지, 7종이 이미지와 동일한 형태인지 확인한다.
- 단일·다중 셀 조각을 네 방향으로 회전하고 네 번 회전 후 원래 형태가 되는지 확인한다. 격자 가장자리와 모서리에서 돌출부가 경계 밖으로 나가는 배치는 허용되고, 기본 셀이 격자 밖에 놓이는 배치는 거부되는지 확인한다.
- 모든 인접 변 조합과 반대 방향을 확인한다. 특히 `Out`/`In` 허용, `Out`/`Flat`·`Out`/`Out` 거부, 빈 셀을 향한 `Out` 허용, 점유 셀 중복 거부를 확인한다.
- 개별 조각과 Shift로 선택한 연결 묶음을 회전·이동하고, 무효 위치·화면 밖·취소 시 원상 복구되는지 확인한다. 팔레트에 놓을 때 개별·단독 묶음은 삭제되고 두 조각 이상인 묶음은 기존 위치로 돌아와야 한다.
- 포인터가 잡은 셀과 정렬되고 미리보기의 유효성이 놓기 결과와 일치하는지 확인한다. 패널 비활성화와 씬 재진입 시 드래그·입력 구독이 남지 않는지도 확인한다.
- 테이블의 중복 ID·좌표, 잘못된 변, 끊어진 조각, 누락 참조를 각각 수정해 오류가 모여 보고되고 초기화가 차단되는지 확인한 후 원본을 복구한다.
