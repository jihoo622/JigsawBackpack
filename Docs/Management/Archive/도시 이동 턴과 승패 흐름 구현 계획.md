# 도시 이동 턴과 승패 흐름 구현 계획

## 목적과 적용 범위

도시 이동을 턴 진행의 기준으로 삼고, 인접 화물의 가치 변동과 정기 빚 차감을 턴 종료에 처리한다. 마지막 빚을 갚은 뒤의 자금으로 승패를 판정한다. 이 문서는 구현 계획이며 완료 기록이 아니다.

현재 `PuzzleInventoryService`는 기차·도시별 시장·자금을 소유하고 도시를 순환한다. `PuzzleInventoryValuation`은 인접 시너지를 현재 배치에 즉시 반영하며, 거래는 기차 내 최종 가치 등을 가격에 사용한다. 이번 변경에서는 기차 화물의 실제 가치가 턴 경과에 따라 변한다. 거래 가격은 도시·태그별 비율을 쓰며, 실제 가치와 거래 가격을 연동하는 작업은 이후 별도 단계에서 다룬다.

`AGENTS.md`의 테이블 4계층, 씬 로컬 상태, 미리 배치한 MVP View, `Presentation`, Input System 및 `GameEvents` 규칙을 따른다. 각 단계의 완료 기준은 구현 요구사항이다. 테스트·플레이·검증용 입력이나 캡처·원인 조사 실험은 사용자가 별도 요청할 때만 수행한다.

## 확정된 규칙

- 도시를 한 번 이동할 때 한 턴을 소모한다. 이전·다음 버튼으로 유효한 다른 도시에 도착하는 이동은 각각 한 번으로 센다. 시작 도시는 이동 횟수 0이다.
- 기차 화물의 실제 가치는 인접 상태가 바뀌는 즉시 변하지 않는다. 도시 이동으로 턴이 지날 때 기존 `multiplierPercent` 시너지 계산으로 변화하던 값만큼 증가하거나 감소한다. 변화 결과는 개별 화물 인스턴스의 실제 가치에 누적한다.
- 여러 슬롯이 같은 이웃 인스턴스에 닿으면 그 이웃은 한 번 계산한다. 같은 종류라도 서로 다른 이웃 인스턴스가 여러 개 접하면 각각 계산한다.
- 도시 이동 2회마다 빚을 차감한다. 현재 빚 차감은 2·4·6번째 이동에서 각각 50·100·200이다. 값과 차감 주기는 테이블에 둔다.
- 차감 직전 소지금이 해당 빚보다 적으면 패배한다. 마지막 빚을 전액 갚으면 차감 후 잔액이 0이어도 승리한다. 이미 종료된 게임은 추가 턴이나 거래를 처리하지 않는다.
- 기존 거래 시스템의 구매가는 아이템 가격 테이블의 기본 가치와 도시·태그별 구매 비율을 사용하고, 판매가는 기존 기차 내 시너지 반영 최종 가치와 도시·태그별 판매 비율을 사용한다. 실제 가치와 거래 가격을 연동하는 작업은 이후 별도 단계에서 다룬다.
- 승리·패배를 표시한다. 타이틀 화면이 구현되기 전이므로 타이틀 복귀 기능은 추가하지 않는다.

## 가치 계산 해석과 남은 결정

`multiplierPercent`가 기존에 만들던 변화량을 그대로 누적하는 것으로 해석한다. 기존 계산은 아이템의 기본 가치를 기준으로 증가분을 합산한 다음 감소 배율을 적용한다. 한 턴의 변화량은 **기존 방식으로 계산한 결과 − 기본 가치**이며, 이를 해당 인스턴스의 턴 시작 실제 가치에 더한다. 예를 들어 기본 가치가 100이고 기존 시너지 결과가 120이면 매 턴 실제 가치에 20을 더한다. 계산은 같은 턴의 인접 스냅샷을 기준으로 하며 이웃 인스턴스별 효과를 기존 순서대로 계산한다.

기차의 인접 관계는 도시 이동 요청이 확정되기 직전에 수집한다. 도시만 바뀌는 정상 이동에서는 기차 배치가 그대로이므로 출발 전과 도착 후의 기차 인접 관계가 같다.

실제 가치는 반올림·최솟값·상한 없이 decimal로 누적한다. 빚 부족으로 패배하는 이동도 도시 도착·턴 증가·가치 변화를 확정하고 빚은 차감하지 않는다. 결과 표시 후 패배 및 승리 여부만 ui로 제공한다.

## 턴 처리 계약

아래 순서를 실행 계약으로 따른다. 빚 부족 시에도 도시 도착·턴 증가·가치 변화를 확정한다.

1. 이동 요청이 유효한지, 게임이 진행 중인지 확인한다. 진행 중인 드래그는 기존 도시 전환 경로에서 취소한다. 무효한 요청이나 같은 도시에 대한 요청은 턴을 소비하지 않는다.
2. 출발 직전 기차의 인접 관계를 스냅샷으로 수집하고, 한 턴의 가치 변화와 다음 턴·도시·차감 결과를 계산한다. 계산에 실패하면 기존 도시·턴·화물 가치·시장·자금을 보존한다.
3. 빚 차감일이면 차감 전 자금과 해당 차감액을 비교한다. 부족하면 패배 상태를 확정한다. 충분하면 빚을 한 번 차감하고, 마지막 차감일에는 잔액이 0 이상이면 승리로 판정한다.
4. 확정된 도시·화물 가치·턴·자금·게임 상태를 한 번에 반영하고 View에 전달한다. 도시 전환과 가치 변화, 빚 차감이 입력 중복이나 재진입으로 한 턴에 두 번 적용되지 않도록 처리한다.

빚 부족으로 패배하는 이동도 도착·턴 증가·가치 변화를 확정하고 빚만 차감하지 않는다. 같은 프레임의 반복 입력과 거래 중 도시 이동은 단일 순서로 처리하며, 이전 도시·기차·각 시장의 인스턴스 소유권을 일관되게 유지한다.

## 1단계. 턴·빚 테이블과 게임 상태

**대상** `Assets/Resources/Tables/`, `GameTables.cs`, `GameTableRecords.cs`, `TableManager.cs`, `GameTableRules.cs`, `PuzzleInventoryService.cs`.

1. 차감 주기와 차수별 금액을 순서에 의존하지 않는 명시적 이동 횟수 또는 차수 ID로 정의한다. 현재 설정은 이동 2·4·6회와 금액 50·100·200이다. 자금 시작값은 기존 거래 테이블을 원본으로 쓴다.
2. 누락·중복 차수, 이동 횟수, 금액 범위, 주기와 일정의 일관성을 항목별로 모아 검증한다. 테이블 오류는 `IsValid`에 반영하고 `RequireValid()` 이전 초기화를 막는다.
3. 씬 로컬 세션에 턴·차감 진행 상태와 진행 중·승리·패배 상태를 둔다. 현재 도시와 기존 `Funds` 등 자금 원본을 재사용한다. Game 씬 재진입 시 시작 데이터로 초기화한다.

**완료 기준** 일정·자금·턴·승패의 단일 소유자가 명확하고 유효하지 않은 일정은 초기화되지 않는다.

## 2단계. 턴별 가치 변화

**대상** `PuzzleSynergyTableData.json`, 아이템 인스턴스 모델, `PuzzleInventoryValuation.cs`, 거래 가격 계산과 화물 상세 표시.

1. 기존 `multiplierPercent`와 대상·이웃 태그 규칙을 재사용한다. `Train`·`Both`에 해당하는 기차 인접 효과만 턴별 실제 가치 변동에 적용하며 기존 증가 합산과 감소 배율 계산 순서를 따른다.
2. 인접 관계 탐색과 실제 가치 변경을 분리한다. 배치·회전·거래 시 인접 정보는 갱신하되 실제 가치는 변경하지 않는다. 유효한 도시 이동 턴이 확정될 때만 기존 계산의 변화량을 각 기차 화물 인스턴스에 누적한다.
3. 실제 가치는 인스턴스별로 관리하고 보드 간 이동 및 도시 재방문 후에도 보존한다. 기존 구매·판매 가격 산식은 유지한다. 실제 가치와 거래가 연동은 후속 작업으로 둔다.

**완료 기준** 인접 변경만으로 실제 가치가 바뀌지 않고 도시 이동 턴마다 기존 시너지 변화량이 기차 화물에 누적된다. 같은 종류의 서로 다른 이웃은 각각 계산하며, 같은 이웃과의 여러 접촉 면은 한 번 계산한다.

## 3단계. 도시 이동과 빚·승패 확정

**대상** `PuzzleInventoryService.cs`, `PuzzleInventoryPresenter.cs`, 도시 이동 및 거래 처리.

1. 기존 이전·다음 도시 요청을 공통 턴 진행 경로로 연결한다. 이동을 한 번 확정할 때마다 턴이 정확히 한 번 증가한다.
2. 차감일에 해당하는 빚을 조회하고 위 턴 처리 계약에 따라 자금을 차감하거나 패배를 확정한다. 마지막 차감 이후에는 확정된 잔액 경계 규칙을 적용한다.
3. 도시 전환, 가치 변화, 자금과 게임 상태를 한 작업으로 확정한다. 실패·취소·중복 호출, 상태 변경 중 추가 요청에서 부분 적용이 남지 않도록 한다. 게임 종료 후 이동·거래·회전을 차단한다.

**완료 기준** 이동 2·4·6회에 정해진 빚이 각각 한 번 처리되고, 부족 시 패배·마지막 빚을 전액 납부하면 잔액이 0이어도 승리가 확정된다.

## 4단계. HUD와 종료 흐름 연결

**대상** `PuzzleCityView`, 관련 Presenter, `Presentation`, Game 씬과 미리 배치한 UI 프리팹.

1. 현재 도시·턴·자금·다음 빚의 차감 시점과 금액, 화물별 현재 가치와 턴 변동 조건을 표시한다. 문구와 색은 `Presentation`, 수치는 모델과 테이블에서 읽는다.
2. 승리·패배 결과 패널을 `PanelBase`로 구성하고 시작 상태·닫힘 정리·입력 차단을 명시한다. 기존 UI 모듈의 Submit/Cancel 동작을 함께 고려한다. 타이틀 복귀는 추가하지 않고 재시작 여부는 결정 후 연결한다.
3. 도메인 사건이 필요하면 `GameEvents`의 페이로드를 통해 발행한다. 분석 기록을 추가하는 경우 `TelemetryRecorder`, `TelemetryEvents`, `TelemetryPayload`, `Docs/Management/PLAY_LOG.md`와 `Docs/Management/TELEMETRY.md`를 함께 맞춘다.

**완료 기준** 턴 진행과 빚 예정·결과가 화면에 나타나며, 승패가 확정되면 결과 화면과 입력 상태가 일치한다.
