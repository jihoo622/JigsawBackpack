# 게임 기획서 동기화

## 문서 대응

- 주 관리 화면: [노션 게임 기획서](https://app.notion.com/p/41400f902d2281849db4c5e61b7f5ac3).
- 노션 페이지 ID: `41400f90-2d22-8184-9db4-c5e61b7f5ac3`.
- 저장소 대응 파일: [게임 기획서](<../게임 기획서.md>).
- 마지막 공통 본문과 변경 판별 정보: `NotionSync/game-design.json`. 사람이 편집하는 기획서가 아닌 동기화용 기준 데이터다.

노션과 로컬은 같은 기획의 두 편집 지점이다. 노션을 주 관리 화면으로 사용하되, 마지막 공통 본문 이후 양쪽 변경을 비교하며 한쪽을 무조건 우선해 덮어쓰지 않는다. 구현 현황·개발 과제·운영 계약은 기획서에 넣지 않고 이 관리 폴더에 둔다.

## 작업 규칙

1. 프로젝트 작업을 시작할 때 노션 페이지를 가져와 누락·잘림 여부를 확인하고 로컬 파일 및 마지막 공통 본문과 비교한다. 노션 변경으로 게임 규칙이 달라졌다면 구현 전에 로컬 기획서에도 반영한다.
2. 노션만 바뀌었으면 로컬에 반영한다. 로컬만 바뀌었으면 같은 작업에서 기존 노션 페이지에 반영한다. 양쪽이 같은 내용으로 바뀌었으면 새 기준으로 갱신한다.
3. 양쪽의 다른 부분이 바뀌었으면 두 변경을 병합해 양쪽에 반영한다. 같은 규칙이 서로 다르게 바뀌었으면 두 안을 보존하고 사용자에게 해당 규칙만 확인한다. 수정 시각만으로 승자를 정하지 않는다.
4. 여기서 게임 기획을 수정할 때는 로컬 파일 수정만으로 완료하지 않는다. 노션에도 해당 변경을 반영한다. 기획 변경은 코드·테이블의 구현 완료를 뜻하지 않으며 구현 차이는 `CURRENT_STATE.md`에 적는다.
5. 쓰기 직전에 노션과 로컬이 비교 이후 다시 바뀌지 않았는지 확인한다. 노션은 연결 도구의 부분 수정 기능을 우선 사용한다. 페이지 ID를 유지하고 새 사본을 만들지 않는다. 하위 페이지·첨부·표·네이티브 참조를 보존한다.
6. 양쪽 본문의 일치가 확인된 후에만 공통 본문과 판별 정보를 갱신한다. 실패한 작업을 동기화 완료로 기록하지 않는다.

## 비교와 보존

- 페이지 제목은 로컬의 첫 제목과 대응한다. 노션의 목차 블록은 본문 차이에서 제외한다.
- 줄바꿈·표 구분선의 공백과 정렬 표기·인라인 코드 표현·일반 텍스트의 이스케이프 차이는 표시 형식으로 비교한다. 수치·문구·링크·행 순서·코드 본문은 내용으로 비교한다.
- 노션에서 추가한 표현을 Markdown으로 온전히 옮기기 어려우면 원본 블록과 참조를 보존한다. 잘린 조회나 지원하지 않는 블록을 빈 내용으로 해석하지 않는다.
- 연결 장애·접근 불가·충돌이면 상대 문서와 기존 공통 기준을 보존하고 미반영 내용을 명시한다. 다시 연결되면 미반영 변경부터 처리한다.
- 연결 도구만 접근할 수 없고 사용자가 Orca 브라우저에 페이지를 열어둔 경우에는 해당 로그인 세션으로 읽고 수정할 수 있다. 가상 스크롤로 일부만 표시된 본문을 전체로 취급하지 않는다. 수정 후 페이지를 다시 불러와 저장된 전체 본문·표·순서를 확인한 뒤 공통 기준을 갱신한다. 조회할 수 없는 수정 시각을 추정하지 않는다.
- 기준 데이터가 없으면 양쪽을 직접 비교해 기준을 복구한다. 동기화가 확인되기 전에는 한쪽을 정답으로 간주하지 않는다.

## 실행 방식

현재 동기화는 에이전트가 프로젝트 작업을 시작하거나 기획을 수정할 때 연결된 노션 도구로 수행한다. 상시 감시·웹훅·예약 동기화 서비스는 설치하지 않았다. 따라서 작업 중이 아닐 때 노션에서 한 변경은 다음 작업 시작 시 가져온다. 새 작업자도 이 규칙과 페이지 ID를 먼저 확인한다.
