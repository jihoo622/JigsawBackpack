# 게임 시간 시스템

게임 시간은 **턴 단위**로만 흐른다. **1턴 = 게임 6시간**, **하루 = 4턴**(새벽·오전·오후·저녁)이다. 실시간 시계는 없다. 규칙·의도는 [게임 기획서](<../게임 기획서.md>) 3·6·7·8장이 원본이다. 예전 계획인 3시간 턴제는 [3시간 턴제 전환 계획](<../3시간 턴제 전환 계획.md>)에 경위로만 남아 있고, 그 문서의 턴 규칙은 이 문서가 대체한다.

## 원본과 소유권

- `PuzzleTimeManager`(`Assets/Scripts/Runtime/Core`)가 경과 시간 `ElapsedHours`(정수 게임 시간)를 보관한다. 값은 항상 턴 길이의 배수다.
  - 상수: `HOURS_PER_DAY` 24, `HOURS_PER_TURN` 6, `TURNS_PER_DAY` 4.
  - 턴 길이는 구조 상수라 테이블에 두지 않는다. 대신 테이블의 모든 시간 값이 6의 배수인지 검증한다(`GameTableRules.CheckTurnHours`).
  - 턴 번호 `TurnNumber` = 경과 턴 + 1, 시간대 `TurnSlot` = 시각 ÷ 6(0 새벽 00~06 · 1 오전 06~12 · 2 오후 12~18 · 3 저녁 18~24).
  - 변환: `HoursOf(턴)`, `TurnsOf(시간)`(올림).
- 시뮬레이션은 지금처럼 1시간 단위 사건 진행(`PrepareTimeAdvance` → `CommitTimeAdvance`)을 그대로 쓴다. 모든 주기가 6의 배수이고 진행은 항상 턴 단위로 일어나므로, 사건이 모두 턴 경계에 놓인다.
- `PuzzleTimeTableData.json`이 시간 설정의 원본이다.
  - `daylightHours` 18: 낮 시작(06:00)부터 이만큼이 낮이다. 새벽(00:00~06:00)이 밤이다.
  - `startHour` 6: 게임 시작 시각(1일 오전)이자 날짜 변경·재입고 시각이다.
  - `travelTurns` 1: 이동 1회가 쓰는 턴. 노선 거리와 무관하게 모든 노선이 같다.
  - `restTurns` 1: 휴식 화면을 열 때 고른 기본 휴식 턴.
- 노선 거리는 `PuzzleRouteTableData.routes[].distance`가 원본이다. 운임의 거리 항(거리 × `costPerDistance`), 의뢰 보상·후보 범위, 최단 경로의 동률 판정에 쓴다. 이동 시간에는 쓰지 않는다.
  - `points`(지도 선)는 그리기 전용이다. Map Editor의 "노선 거리 자동 계산"만 선 길이 ÷ `pixelsPerDistance`(100)를 반올림해 거리를 채운다.
- 영업 기간은 `PuzzleTradeTableData.deadlineHours`(336 = 56턴, 14일)다. 기간이 끝나면(`IsTimeUp`) 턴을 쓰는 행동은 막히고(이동 `TimeUp`, 휴식·작업은 기한 검사) 거래만 할 수 있다. 결산(`TryFinishRun`)은 그 뒤에만 되고 잔액 ≥ `targetFunds`면 승리다.
- `CityMoveCount`는 이동 횟수다. 이동 1회가 1턴이라 이동만 했다면 경과 턴과 같지만, 휴식·작업장 확정도 턴을 쓰므로 시계의 턴은 `TurnNumber`가 원본이다.

## 시간이 흐르는 행동

| 행동 | 턴 | 경로 |
|---|---:|---|
| 이동 | `travelTurns`(1) | `TravelLeg` |
| 휴식 | 1~4턴 중 고른 값 | `Rest(턴)` |
| 아침 대기(새벽) | 오전까지(1턴) | 인벤토리 화면 버튼 → `Rest(TurnsUntilDaylight)`. 경제 분석은 `WaitForDaylight` |
| 작업장 확정(도축·정제·개조) | 작업 시간(`workHours` ÷ 6, 현재 모두 1턴) | `TryConfirm*` → `WaitForWorkbench` |

- 그 밖의 행동(시장·술집·화차 시설 진입과 거래, 기차 안 재배치, 화물칸 전환, 지도·경로 계획, 결산)은 시간을 쓰지 않는다.
- 기한을 넘기는 휴식·작업장 확정은 막는다(`CanRest`, `WorkshopFitsDeadline` → `rules.workshop.deadline`). 이동도 기간을 넘기면 막는다(`PuzzleTravelFailure.TimeUp`). 기간이 끝나는 시각에 도착하는 이동은 허용한다.
- 진행 처리 순서(1시간 사건 진행 안에서): 시너지 정산 → 신선도·만료 → 배설 → 조합 → 섭취 → 성장 → 출산 → 작업장 완료 → 의뢰 실패 판정.

## 날짜와 낮·밤

- `Day = 경과 시간 / 24`, `HourOfDay = 경과 시간 % 24`(둘 다 0부터)이다. 시각은 `startHour + HourOfDay`다.
- 화면 시계는 `D일 오후 · 낮 · N턴`(`Presentation.PuzzleTime`)이다. 기록 시각(소문·의뢰 기한·도착 예정)은 `D일 오후`(`Presentation.GameTimestamp`)다. 시간대 이름은 기초데이터 `presentation.time.slot0~3`이다.
- 매일 06:00(오전 시작)에 날짜가 바뀌고 모든 시장을 재입고한다(`DaylightOpeningsThrough`).
- 새벽에는 시장에 들어갈 수 없다. 이미 들어가 있으면 나올 때까지 거래할 수 있다.

## 이동

- `TravelLeg(도시, 통과 여부)`가 이동 하나를 즉시 처리한다. 실패하면 아무것도 바꾸지 않는다.
  1. `EvaluateTravel`로 운임·도착 시간대를 평가한다.
  2. 운임을 내고 도시를 바꾸며 시설 입장·작업장 열림을 닫는다. `CityMoveCount`가 1 는다.
  3. 이동 턴만큼 시간을 진행한다(`CommitTimeAdvance`).
  4. 정차면 방문 기록·`CityArrived`·의뢰 완료를 처리하고, 통과면 `IsPassingThrough`만 켠다.
  5. 경로 계획의 구간 전진·완료·이탈을 판정한다.
- 지도 화면은 이동 연출(`PuzzleTradeTableData.travelEffectSeconds` 1.25초) 뒤 `Travel`을 한 번 호출한다. 연출 중 취소하면 확정 전에 멈춘다. 자동 이동은 구간마다 같은 연출을 하고 통과 구간은 절반 길이다.
- 최단 경로(`PuzzleRoutePlanner`)는 구간 수가 가장 적은 경로다. 구간 수가 같으면 노선 거리 합이 작은 경로, 그것도 같으면 역 ID 순서로 고른다.

## 작업장

- 원본은 세 곳이다.
  - `TrainventoryWorkTableData.works[]`(WorksData): `id`·`displayName`·`description`·`inputPieceId`·`workHours`·`outputPieceId`·`outputCount`·`cost`.
  - `TrainventoryWorkshopTableData.workshops[]`: `id`·`type`(Butchery·Refining·Modification)·`title`·`description`·`board`·`workIds`·`costPercent`·`feePerHour`·`extraCost`.
  - `PuzzleTableData.cities[].workshopIds`: 역이 가진 작업장.
- 화물 하나의 수수료 = 올림(`cost` × `costPercent` / 100) + `workHours` × `feePerHour` + `extraCost`(`TableManager.WorkFee`).
  - 맡길 때 보드 전체의 합을 낸다. 함께 맡긴 화물은 가장 긴 `workHours`가 지나면 모두 나온다(`PuzzleInventoryService.Workshops.cs`).
- 확정하면 작업 시간만큼 바로 시간이 흐르고(`WaitForWorkbench`), 결과를 같은 역 작업장에서 수령한다. 수령은 무료다. 작업 대기 팝업은 쓰지 않는다.
- 도축·정제: 작업이 등록된 화물만 받는다. 입력을 없애고 산출물을 예약해 완료 때 보드에 놓는다.
- 개조: 작업장의 작업 하나를 모드로 골라 보드 전체에 적용한다. 결과는 같은 모양·같은 기본 가치의 정의 교체다.
  - 결과 품목을 다시 맡기면 `AlreadyModified`, 다른 작업의 입력이면 `NoConversion`, 등록되지 않은 화물이면 `InvalidItem`, 기한을 넘기면 `Deadline`으로 막는다.
- 검증(`GameTableRules.ValidateWorkshops`):
  - 참조 무결성과 작업장 안의 입력 화물 중복을 본다.
  - 같은 역에 같은 종류의 작업장이 둘이면 오류다.
  - 개조는 1:1, 같은 모양, 같은 기본 가치, 태그 유지여야 한다. 개조 결과 품목은 시장 재고 후보가 될 수 없다.
  - 산출물이 빈 작업 보드에 들어가는지 확인한다.

## 시간 규칙 수치

테이블 값은 게임 시간이고 6의 배수여야 한다. 6시간보다 짧던 규칙(작업·섭취·공간 대기)은 1턴으로 올렸다.

| 항목 | 시간 | 턴 |
|---|---:|---:|
| 시너지 정산 `activationIntervalHours` | 6 | 매 턴 |
| 번식 `breedingHours` | 24 | 4 |
| 완료 전 공간 대기 `completionHoldHours` | 6 | 1 |
| 곡물 섭취 주기 `feedIntervalHours` | 6 | 매 턴 |
| 섭취 시 번식 단축 | 12 | 2 |
| 섭취 시 성장 단축 | 24 | 4 |
| 배설 `wasteIntervalHours` | 48 | 8 |
| 성장 `growthHours` | 24 | 4 |
| 성장 공간 재확인 `growthBlockedHours` | 6 | 1 |
| 조합 `requiredHours` | 12 | 2 |
| 작업 `workHours` | 6 | 1 (도축·정제·개조 모두) |
| 유통기한 `shelfLifeHours` | 72·168·336 | 12·28·56 |
| 지역 거래 불이익 `durationHours` | 72 | 12 |
| 기한 `deadlineHours` | 336 | 56 |

- 정산 횟수는 `floor(도착 시간/6) − floor(현재 시간/6)`이다(`IntervalCountAfter`). 지금은 턴마다 한 번이다.
- 신선도는 시간 단위로 소모한다. 품목마다 `(소모 시간, 누적 %)`를 두고 매시간 보존 효과를 반영한 소모율을 누적해 100이 찰 때마다 1시간을 소모한다. 냉장 50%면 1턴에 3시간 준다. 남은 유통기한은 턴으로 올림해 표시한다.
- 배설 주기는 경과 시간이 48의 배수가 되는 경계에 맞춘다. 공간이 없으면 1턴 뒤에 다시 확인한다.
- 의뢰:
  - 목적지 후보와 보상은 최단 노선 거리 합을 쓴다(`minTravelDistance`·`maxTravelDistance`·`rewardPerCellDistance`).
  - 기한(시간) = 올림(최단 이동 턴 × `deadlinePercent` / 100) × 6 + `deadlineExtraHours`. 최단 이동 턴은 최소 구간 수 × `travelTurns`다.

## UI와 이벤트

- 기간·남은 시간은 `Presentation.TurnSpan`(게임 시간 → "N턴", 올림)이다. 이동 견적, 의뢰, 유통기한, 작업장, 정산 게이지가 같은 표기를 쓴다.
- 지도 노선 라벨은 기본 운임(기본요금 + 거리 요금, 적재 요금 제외, `Presentation.PuzzleMapRouteFare`)이다.
- 이동 확인창은 이동 턴과 도착 시간대·밤 여부를, 경로 계획 요약은 총 이동 턴과 도착 시간대를 보인다.
- 휴식 화면은 `<` `>`로 1~4턴을 고르고 "저녁까지 휴식 · 1턴"을 보인다.
- 작업장 확인 버튼은 맡기기 전에만 "수수료 합 · 작업 턴"을 보인다.
- 시간 막대는 지금 턴의 가운데를 고정한 24시간 창이다. 턴이 지나면 낮·밤 구간과 정산 눈금이 한 칸 밀린다. 정산 글자는 다음 정산까지 남은 턴을 보인다.
- 화면 갱신은 `GameEvents.TimeAdvanced`에 맞춘다. 실시간 갱신(`Update`)은 하지 않는다.
- 분석 로그는 schemaVersion 9부터 경로 계획에 `totalTurns`를 쓴다. 시간 필드(`elapsedHours`·`requestedHours`·`deadlineHours`)는 게임 시간 그대로다([PLAY_LOG](PLAY_LOG.md)).

## 확인 범위

- 확인한 것: 컴파일 오류 0, 테이블 검증 오류 0, 기초데이터 계약 재생성.
- 하지 않은 것: 플레이, 입력 실험, 화면 캡처, SmokeCheck, 경제 분석 재실행.
- 경제 수치(가격·운임 단가·보상·작업 비용)는 바꾸지 않았다. 이동이 모두 1턴이 되어 장거리 노선의 시간 비용이 사라졌으므로 밸런스는 다시 봐야 한다.
