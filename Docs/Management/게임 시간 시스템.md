# 게임 시간 시스템

## 원본과 소유권

- `PuzzleTimeTableData.json`은 K·시작 시각·일출 시각·일출/야간 길이·일반 휴식 분수의 단일 원본이다. K=28픽셀/시간은 플레이 검증 전 잠정치다.
- `PuzzleRouteTableData.routes[].points`는 고정 지도 좌표의 폴라인 x,y 쌍이다. 왕복은 같은 점의 역순이며 요금용 `distance`·화면 줌과 독립적이다.
- `PuzzleInventoryService.Time`의 `PuzzleTimeManager` 하나가 경과 분을 보관한다. `ElapsedMinutes`가 원본이며 `ElapsedHours`는 소수 시간 조회값이다. `OwnedMinutes`가 물품 보유 시간의 원본이고, 성장 진행은 `GrowthElapsedMinutes`로 분리해 이동해도 초기화되지 않는다.
- `PuzzleTradeTableData.deadlineHours`는 기한 설정이다. 시계 생성 시 분으로 변환하고 정확히 기한과 같은 시각의 상환은 허용한다.

## 계산과 날짜

- `소요 분 = ceil(폴라인 구간 길이 합 / pixelsPerHour × 60 / travelRoundingMinutes) × travelRoundingMinutes`이다. 올림 단위는 60분이라 이동은 정시간 단위로 걸린다(25시간 44분 → 26시간). 시계·기한·가치 누적은 분 단위를 유지한다. 가중치 변환·코드 기본 소요 시간은 제거했다.
- 시작은 06:00이며 일출은 06:00~24:00, 야간은 00:00~06:00이다. HUD 날짜는 자정에 바뀌고 기한은 시작부터의 경과 분으로 비교한다.
- 이동 확정 전에 시간·자금·모든 화물칸 가치·기존 물품 보유 시간의 범위를 확인한다.
- 시너지는 `PuzzleSynergyTableData.activationIntervalHours`(6시간)마다 정산한다. `Time.IntervalCountAfter`가 `floor(도착 경과 분/주기 분) − floor(현재 경과 분/주기 분)`을 계산하고 이동·휴식·아침 대기가 같은 경로를 사용한다. 현재 배치의 증감량에 정산 횟수를 곱하며 호버 예측도 같은 함수를 쓴다. 구매·배치·도착으로 주기는 초기화되지 않는다.
- 정산 횟수·가치·보유 시간의 범위를 먼저 검사하고, 시너지 가치·경과 분·보유 시간을 확정하고 날짜 변경 부산물을 생성한 뒤 `GameEvents.TimeAdvanced`를 발행한다. 새로 생성한 부산물의 보유 시간은 0이다.

## 시장과 대기

- 야간에는 시장 구매·판매·시장 내 재배치를 모델의 `EvaluateDrop`에서 거부한다. UI도 시장의 `CanvasGroup` 입력을 끄고 흐리게 표시한다.
- 기차 안 재배치·화물칸 선택·역 이동은 야간에도 허용한다.
- 우측 역 메뉴의 휴식 화면에서 `restMinutes`(현재 60분)만큼 시간을 보내거나 야간에 다음 06:00까지 대기한다. 시계·보유 시간과 기한 판정을 진행하며 6시간 경계에서 시너지를 정산하며 이동 횟수·요금·시장 재고를 바꾸지 않는다.

## UI와 이벤트

- 지도 시간 라벨·이동 견적·확인창·호버는 동일한 계산 소요 분을 표시한다. 지도 시간 라벨은 현재 역에서 직접 연결된 노선에만 표시하며 줌·겹침 조건도 적용한다. 확인창에는 도착 시각과 야간 시장 휴업 여부도 표시한다.
- 하단 예측 목적지 선택 UI는 없다. 지도에서 이동할 역을 누르면 호버 미래 가치의 목적지로 기록하고 도시 도착 후 초기화한다. 미선택 시 미래 가치만 숨긴다.
- `TimeAdvanceInfo`는 `session`·`previousMinutes`·`elapsedMinutes`·`DeltaMinutes`를 제공한다. `DeltaHours`는 소수 시간 조회값이다.
- `TravelPreviewChanged`는 세션 로컬 예측 목적지 변경을 UI에 알린다. 정적 이벤트는 기존 SubsystemRegistration 경로에서 초기화한다.
- 일반 효과 툴팁은 기차 Placement와 세션에서 진행도를 읽는다. 번식은 현재 맺힌 쌍의 진행도만 쓰고 짝이 없으면 0으로 표시하며, 성장은 `GrowthElapsedMinutes`/`GrowthMinutes`를 그대로 보여준다. 시장·도축·개조 보드와 배설·가치 정산에는 진행도 행이 없다.
- 공간 부족 대기에 새로 진입한 품목·쌍은 미확인 알림을 남긴다. 가치 변동 알림과 독립이라 한쪽만 읽어도 다른 쪽은 남고, 툴팁을 열면 미확인 표시만 지워지며 대기 중이면 빨간 `공간 부족`은 유지된다.
- 냉장 화살표는 시간 정산과 같은 `PuzzleRefrigeration` 판정을 읽는다. 기차 객차에서만 표시하고 냉장원에서 음식으로 향하는 녹색 화살표를 그리며, 소모율에 실제 기여한 접촉만 보인다. 드래그로 숨긴 품목이 겹친 화살표는 숨기고, 가치 화살표와 다른 레인을 사용해 겹치지 않는다.
- 분석 세션 ID·실제 시간 시계는 `TelemetryLog`의 계약을 유지한다. 게임 시간 이벤트를 별도 분석 파일로 중복 기록하지 않는다.

## 재적용과 확인 범위

- 지도 시간 라벨·시장 입력 그룹·Game 씬의 아침 대기·상환 버튼 배치는 해당 프리팹에서 수정한다.
- 일반 표 갱신은 `Tools/MyJG/Tables/Reload Tables`를 사용한다. 플레이 중에는 재적용하지 않는다.
- 플레이·입력 실험·화면 캡처는 수행하지 않았다. K·6시간 주기 가치 변화·야간 동선과 경제 밸런스는 잠정이다.
