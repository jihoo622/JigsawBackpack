# 게임 시간 시스템

게임 시간은 **턴**으로 흐른다. 1턴은 3시간, 하루는 8턴이며 턴 안의 일부 시간은 없다. 규칙·의도는 [게임 기획서](<../게임 기획서.md>) 3·6·7·8장이 원본이고, 전환 경위와 남은 단계는 [3시간 턴제 전환 계획](<../3시간 턴제 전환 계획.md>)에 있다.

## 원본과 소유권

- `PuzzleTimeManager`(`Assets/Scripts/Runtime/Core`)의 상수가 하루 구조다. `HOURS_PER_TURN` 3, `TURNS_PER_DAY` 8.
- `PuzzleTimeTableData.json`이 나머지 시간 설정의 원본이다.
  - `daylightTurns` 6: 하루의 첫 턴부터 이만큼이 낮이고, 나머지 2턴은 밤이다.
  - `startHour` 6: 하루 첫 턴의 시각이다.
  - `restTurns` 1: 휴식이 쓰는 턴이다.
  - `stationActionTurns` 1: 시설 진입과 작업대 확정이 쓰는 턴이다.
- `PuzzleInventoryService.Time` 하나가 경과 턴 `ElapsedTurns`(정수)를 보관한다.
  - `OwnedTurns`가 물품 보유 시간의 원본이다.
  - 성장 진행은 `GrowthElapsedTurns`로 따로 센다. 이동해도 초기화되지 않는다.
- 노선 이동 턴은 `PuzzleRouteTableData.routes[].turns`가 원본이다.
  - 같은 값을 운임의 거리 항에도 쓴다: 턴 × `costPerTurn`.
  - `points`는 그리기 전용이다. 선 모양을 바꿔도 턴은 바뀌지 않는다.
  - Map Editor의 "이동 턴 자동 계산"은 선 길이 ÷ `pixelsPerTurn`(100)을 반올림한 값(최소 1)을 넣는다. 다른 계산은 하지 않는다.
- 기한은 `PuzzleTradeTableData.deadlineTurns`(112)다. 정확히 기한 턴의 상환은 허용한다.

## 날짜와 낮·밤

- `Day = 경과 턴 / 8`, `TurnOfDay = 경과 턴 % 8`(둘 다 0부터)이다. 화면에는 1을 더해 `D일 N턴 · HH:00`으로 보인다.
  - 시각은 `startHour + TurnOfDay × 3`이다.
- 하루의 첫 턴(06:00)에서 날짜가 바뀌고 모든 시장을 재입고한다(`DaylightOpeningsThrough`).
- `TurnOfDay`가 6·7이면 밤(00:00·03:00)이다. 밤에는 시장에 들어갈 수 없다.
- 아침 대기는 다음 첫 턴까지 진행한다(`TurnsUntilDaylight`).

## 역 행동

- **시장:** `TryEnterMarket`.
  - 들어갈 때 역 행동 1턴을 쓰고 `MarketEntered`를 켠다.
  - 밤 여부는 들어갈 때만 본다. 그 턴 뒤 시계가 밤이 되어도 이번 방문 동안은 거래할 수 있다.
  - 시장 거래 판정(`EvaluateDrop`)은 `CanTradeInMarket`(들어가 있음)을 요구한다.
  - 입장은 세션의 `PaidFacility`(시장·술집·화차 시설 중 하나)로 남는다. 뒤로 갔다가 같은 시설에 다시 들어가면 턴을 쓰지 않는다.
  - `PaidFacility`는 다른 시설 진입, 휴식·작업대 화면 선택(`ForgetPaidFacility`), 시설 진입이 아닌 시간 진행, 다른 역 도착 때 사라진다. 시장 거래 판정은 `PaidFacility`가 시장일 때만 통과하고, 화면 쪽은 시장 화면이 열려 있을 때만 시장 보드를 거래 대상으로 쓴다.
- **술집·화차 시설:** `TryEnterTavern`·`TryEnterWagonFacility`. 들어갈 때 1턴을 쓰며 재입장 규칙은 시장과 같다. 화차 시설 안의 구매는 턴을 쓰지 않는다. 술집 의뢰 게시판은 기차를 바꾸는 행동이 성공할 때마다(`PuzzleActionCommitted`) 수락 가능 여부를 다시 판정한다.
- **휴식:** `restTurns`.
- **작업대(도축·정제·개조):**
  - 화면 진입은 무료다.
  - 확정에 성공하면 Presenter가 작업대를 닫고 `WaitForWorkbench(actionId, stationActionTurns)`로 1턴을 쓴다.
  - 작업 시간 `workTurns`(1)가 지나면 같은 역에서 작업대를 다시 열어 결과를 수령한다. 수령은 무료다.
  - 작업 대기 팝업(`PuzzleWorkWaitView`)은 더 이상 쓰지 않는다.
- **기한:** `CanSpendStationTurn`이 기한을 넘기는 역 행동을 막는다. 버튼은 비활성화된다.
- **무료 행동:** 역 화면 열기, 기차 안 재배치, 화물칸 전환, 지도·경로 계획, 상환은 턴을 쓰지 않는다.

## 시간 진행

- 시간이 흐르는 경로는 `AdvanceTurnsFor` 하나다. 이동, 휴식, 아침 대기, 시설 진입, 작업대 작업이 모두 이 경로를 쓴다.
- 진행 루프(`PrepareTimeAdvance`)는 다음 사건 경계까지 턴 단위로 건너뛴다. 경계에서 같은 시각 순서로 처리한다:
  1. 시너지 정산
  2. 신선도·만료
  3. 배설
  4. 조합
  5. 섭취
  6. 성장
  7. 출산
- 유통기한이 있는 화물이 기차에 있으면 한 턴씩 진행한다.
- 시너지 정산은 `activationIntervalTurns`(2)마다, 하루 4회 한다(12·18·00·06시).
  - 횟수는 `floor(도착 턴/2) − floor(현재 턴/2)`이다(`IntervalCountAfter`).
  - 구매·배치·도착은 주기를 초기화하지 않는다.
- 신선도는 정수 턴이다. 품목마다 `(소모 턴, 누적 %)`를 둔다.
  - 매 턴 보존 효과를 반영한 소모율(%)을 누적하고, 100이 찰 때마다 1턴을 소모한다.
  - 냉장 50%면 2턴마다 1턴이 준다.
  - 신선도 % = 남은 턴 ÷ 유통기한 턴이다.
- 동물·조합 수치(턴):

  | 항목 | 값 |
  |---|---|
  | 번식 `breedingTurns` | 8 |
  | 완료 전 공간 대기 `completionHoldTurns` | 1 |
  | 곡물 섭취 주기 `feedIntervalTurns` | 1 |
  | 섭취 시 번식 단축 | 4 |
  | 섭취 시 성장 단축 | 8 |
  | 배설 `wasteIntervalTurns` | 16 |
  | 성장 `growthTurns` | 8 |
  | 성장 공간 재확인 `growthBlockedTurns` | 1 |
  | 조합 `requiredTurns` | 4 |

  - 배설 주기는 경과 턴이 16의 배수가 되는 경계에 맞춘다.
  - 공간이 없으면 다음 턴(1턴 뒤)에 다시 확인한다.
- 이동 확정 전에 기한, 자금, 모든 화물칸 가치와 보유 시간의 범위를 확인한다.
- 정산·가치·보유 시간을 먼저 확정하고 부산물을 생성한 뒤 `GameEvents.TimeAdvanced`를 발행한다.
  - 페이로드는 `previousTurns`·`elapsedTurns`·`DeltaTurns`다.
- 의뢰도 턴을 쓴다.
  - 최단 이동은 노선 턴 합이다.
  - 기한 = 최단 턴 × `deadlinePercent` 올림 + `deadlineExtraTurns`.
  - 보상 = 기본 + `rewardPerCellTurn` × 칸 × 최단 턴.
  - 지역 불이익 기간은 `durationTurns`이다.

## UI와 이벤트

- 시간 표기 형식:
  - 기간·남은 시간은 `Presentation.PuzzleMapTime`의 "N턴"이다.
  - 시계는 `PuzzleTime`, 소문·의뢰 기록 시각은 `GameTimestamp`("D일 N턴")이다.
  - 도착 시각은 "N턴(HH:00)"으로 표시하며 `HourOfTurn`을 쓴다.
- 이동 견적·확인창·경로 계획은 같은 노선 턴을 표시한다.
  - 지도 라벨은 현재 역과 직접 연결된 노선에만 붙는다.
  - 확인창에는 도착 턴과 밤 여부를 보인다.
- 턴을 쓰는 역 버튼은 "시장 · 1턴"처럼 턴 수를 붙인다(`StationTurnCost`). 화면 제목에는 붙이지 않는다.
- 정산 게이지는 2턴 주기 눈금을 그리고, 낮·밤 막대는 하루 8턴에서 밤 2턴을 칠한다.
- 분석 로그는 schemaVersion 7부터 턴 필드를 쓴다([PLAY_LOG](PLAY_LOG.md)). 세션 ID·실제 시간 시계는 `TelemetryLog` 계약을 유지한다.

## 확인 범위

- 컴파일 오류 0, 테이블 검증 통과, 기초데이터 계약 재생성까지 확인했다.
- 플레이, 입력 실험, 화면 캡처, SmokeCheck는 수행하지 않았다.
- 경제 수치(가격·운임 단가·보상)는 바꾸지 않았다. 턴제에서의 밸런스는 검증 전이다.
