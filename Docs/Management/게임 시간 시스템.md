# 게임 시간 시스템

게임 시계는 **실시간에 비례해** 흐르고, **턴은 이동 횟수**다. 규칙·의도는 [게임 기획서](<../게임 기획서.md>) 3·6·7·8장이 원본이다. 3시간 턴제 전환 경위는 [3시간 턴제 전환 계획](<../3시간 턴제 전환 계획.md>)에 남아 있고, 그 문서의 턴 규칙은 이 문서가 대체한다.

## 원본과 소유권

- 시뮬레이션 단위는 **1게임시간**(정수)이다. `PuzzleTimeManager`(`Assets/Scripts/Runtime/Core`)가 `ElapsedHours`를 보관한다.
  - `HourFraction`(0~1)은 다음 정시까지 흐른 비율이다. 시계 분 표시·낮밤 막대·이동 진행 막대에만 쓴다.
  - 상수: `HOURS_PER_DAY` 24, `MINUTES_PER_HOUR` 60.
- 시간 배율의 원본은 기초데이터 `rules.time.gameHoursPerRealMinute`(6)이다. 게임 6시간 = 실제 1분, 즉 게임 1시간 = 실제 10초다(`PuzzleInventoryService.RealSecondsPerGameHour`).
- 이동 중에는 시계를 기초데이터 `rules.time.travelTimeScale`(24)배로 가속한다. 거리 1(3시간) 구간은 실제 1.25초, 거리 7(21시간)은 8.75초다.
- `PuzzleTimeTableData.json`이 나머지 시간 설정의 원본이다.
  - `daylightHours` 18: 낮 시작(06:00)부터 이만큼이 낮이고 나머지 6시간(00:00~06:00)은 밤이다.
  - `startHour` 6: 게임 시작 시각이자 날짜 변경·재입고 시각이다.
  - `restHours` 3: 휴식이 건너뛰는 시간이다.
  - `hoursPerDistance` 3: 노선 거리 1당 이동 시간이다.
- 노선 거리는 `PuzzleRouteTableData.routes[].distance`가 원본이다.
  - 이동 시간 = 거리 × `hoursPerDistance`(`PuzzleTimeManager.TravelHours`).
  - 운임의 거리 항 = 거리 × `costPerDistance`.
  - `points`는 그리기 전용이다. Map Editor의 "노선 거리 자동 계산"은 선 길이 ÷ `pixelsPerDistance`(100)를 반올림한 값(최소 1)을 넣는다.
- 기한은 `PuzzleTradeTableData.deadlineHours`(336, 14일)다. 정확히 기한 시각의 상환은 허용한다.
- 턴은 `PuzzleInventoryService.CityMoveCount`다. 이동 한 번(통과 구간 포함)마다 1 늘고 기한·가치 계산에는 쓰지 않는다.

## 실시간 시계

- `PuzzleInventoryPresenter.Update`가 매 프레임 `session.AdvanceRealTime(Time.deltaTime, 끌기 중)`을 부른다.
  - 일시정지 메뉴는 `timeScale`을 0으로 두므로 시계가 멈춘다.
  - 마지막 정시 이후 흐른 시간은 세션의 `clockCarryHours`(double)에 자르지 않고 누적한다. `HourFraction`은 표시용 사본이다.
  - 화물을 끄는 동안은 정시 확정을 미루고, 놓은 뒤 누적분을 이어서 처리한다.
  - 프레임이 크게 끊겨도 한 번에 최대 24시간만 처리한다.
- 정시를 넘을 때마다 `AdvanceClockHour`가 1시간짜리 진행(`PrepareTimeAdvance` → `CommitTimeAdvance`)을 확정하고 `GameEvents.TimeAdvanced`를 발행한다.
  - 시계 자체의 진행은 분석 행동으로 기록하지 않는다. 휴식·아침 대기만 행동으로 남는다.
  - 분이 바뀌면 시계 표시만 다시 그린다.
- 진행 처리 순서(1시간마다): 시너지 정산 → 신선도·만료 → 배설 → 조합 → 섭취 → 성장 → 출산 → 작업장 완료 → 의뢰 실패 판정.

## 날짜와 낮·밤

- `Day = 경과 시간 / 24`, `HourOfDay = 경과 시간 % 24`(둘 다 0부터)이다. 시각은 `startHour + HourOfDay`다.
- 화면 시계는 `D일 HH:MM · 낮/밤 · N턴`(`Presentation.PuzzleTime`)이다. 소문·의뢰 기록 시각은 `D일 HH:00`(`GameTimestamp`)이다.
- 매일 06:00에 날짜가 바뀌고 모든 시장을 재입고한다(`DaylightOpeningsThrough`).
- 밤(00:00~06:00)에는 시장에 들어갈 수 없다. 이미 들어가 있으면 나올 때까지 거래할 수 있다.
- 아침 대기(`WaitForDaylight`)는 06:00까지 한 번에 진행한다.

## 이동

- 출발: `DepartLeg(도시, 통과 여부, 경로 구간 여부)`.
  - 운임을 차감하고 `Journey`(`PuzzleJourney`)를 만든다. 실패하면 아무것도 바꾸지 않는다.
  - 시설 입장·작업장 열림을 닫고 `GameEvents.JourneyChanged`를 발행한다.
  - 판매해 시장 보드에 남겨 둔 의뢰 화물은 출발과 함께 실패 판정 대상이 된다.
- 이동 중: 시계가 `travelTimeScale`배로 흐르고 1시간마다 `Journey.ElapsedHours`가 는다.
  - 출발 시점의 정시 사이 비율(`StartCarryHours`)을 기록해, 진행률과 도착은 출발 후 흐른 시간(`JourneyTraveledHours`)으로 잰다. 도착은 정시가 아니어도 된다.
  - 도착 시각을 넘는 몫은 도착 뒤 평소 속도로 흘린다.
  - `CurrentCityId`는 출발 역이지만 `IsTraveling`이면 역 시설·작업장·거래·휴식·다른 이동을 막는다.
  - 진행 비율은 `JourneyProgress`다. 지도 이동 창이 이 값으로 막대를 채운다.
- 도착: `CompleteJourney`.
  - 도시를 바꾸고 턴(`CityMoveCount`)을 1 늘린다.
  - 정차면 방문 기록·`CityArrived`·의뢰 완료를 처리하고, 통과면 `IsPassingThrough`만 켠다.
  - 경로 계획의 구간 전진·완료·이탈 판정도 여기서 한다.
- 출발한 이동은 취소할 수 없다. 지도 창이 이동을 더 따라가지 못하면(`AbortTravel`) 진행 중 통과 구간을 정차로 바꾼다(`StopJourneyAtDestination`).
- 경제 분석처럼 실시간을 기다리지 않는 호출자는 `Travel`·`TravelLeg`를 쓴다. 출발 뒤 남은 시간을 한 번에 진행하고 도착한다(`FinishJourneyNow`).

## 역 행동

- 시장·술집·화차 시설 진입(`TryEnterMarket`·`TryEnterTavern`·`TryEnterWagonFacility`)은 시간을 쓰지 않는다.
  - 들어간 시설은 `EnteredFacility`로 남는다. 다른 시설 진입, 휴식·작업장 화면 선택(`LeaveFacility`), 출발 때 사라진다.
  - 시장 거래 판정(`EvaluateDrop`)은 `CanTradeInMarket`(시장에 들어가 있고 이동 중이 아님)을 요구한다.
- 휴식은 `restHours`(3시간)를 건너뛴다. `CanRest`가 이동 중·기한 초과를 막는다.
- 작업장은 아래 절을 따른다. 맡길 때도 시간을 쓰지 않는다.
- 기차 안 재배치, 화물칸 전환, 지도·경로 계획, 상환도 시간을 쓰지 않는다.

## 작업장

- 원본은 세 곳이다.
  - `TrainventoryWorkTableData.works[]`(WorksData): `id`·`displayName`·`description`·`inputPieceId`·`workHours`·`outputPieceId`·`outputCount`·`cost`.
  - `TrainventoryWorkshopTableData.workshops[]`: `id`·`type`(Butchery·Refining·Modification)·`title`·`description`·`board`·`workIds`·`costPercent`·`feePerHour`·`extraCost`.
  - `PuzzleTableData.cities[].workshopIds`: 역이 가진 작업장.
- 화물 하나의 수수료 = 올림(`cost` × `costPercent` / 100) + `workHours` × `feePerHour` + `extraCost`(`TableManager.WorkFee`).
  - 맡길 때 보드 전체의 합을 낸다. 함께 맡긴 화물은 가장 긴 `workHours`가 지나면 모두 나온다(`PuzzleInventoryService.Workshops.cs`).
- 도축·정제: 작업이 등록된 화물만 받는다. 입력을 없애고 산출물을 예약해 완료 때 보드에 놓는다.
- 개조: 작업장의 작업 하나를 모드로 골라 보드 전체에 적용한다. 결과는 같은 모양·같은 기본 가치의 정의 교체다.
  - 결과 품목을 다시 맡기면 `AlreadyModified`, 다른 작업의 입력이면 `NoConversion`, 등록되지 않은 화물이면 `InvalidItem`으로 막는다.
- 완료는 시계 진행 때 판정하고 수령은 같은 역 작업장에서 한다. 수령은 무료다. 작업 대기 팝업은 쓰지 않는다.
- 검증(`GameTableRules.ValidateWorkshops`):
  - 참조 무결성과 작업장 안의 입력 화물 중복을 본다.
  - 같은 역에 같은 종류의 작업장이 둘이면 오류다.
  - 개조는 1:1, 같은 모양, 같은 기본 가치, 태그 유지여야 한다. 개조 결과 품목은 시장 재고 후보가 될 수 없다.
  - 산출물이 빈 작업 보드에 들어가는지 확인한다.
  - 예전 개조 범위 검사(`exemptFromModification`)는 더 이상 검사에 쓰지 않는다. 필드만 남아 있다.

## 시간 규칙 수치(게임 시간)

| 항목 | 값 |
|---|---|
| 시너지 정산 `activationIntervalHours` | 6 (하루 4회: 12·18·00·06시) |
| 번식 `breedingHours` | 24 |
| 완료 전 공간 대기 `completionHoldHours` | 3 |
| 곡물 섭취 주기 `feedIntervalHours` | 3 |
| 섭취 시 번식 단축 | 12 |
| 섭취 시 성장 단축 | 24 |
| 배설 `wasteIntervalHours` | 48 |
| 성장 `growthHours` | 24 |
| 성장 공간 재확인 `growthBlockedHours` | 3 |
| 조합 `requiredHours` | 12 |
| 작업 `workHours` | 3 (도축·정제·개조 모두) |
| 유통기한 `shelfLifeHours` | 품목별 72·168·336 |

- 정산 횟수는 `floor(도착 시간/6) − floor(현재 시간/6)`이다(`IntervalCountAfter`). 구매·배치·도착은 주기를 초기화하지 않는다.
- 신선도는 정수 시간이다. 품목마다 `(소모 시간, 누적 %)`를 두고 매시간 보존 효과를 반영한 소모율을 누적해 100이 찰 때마다 1시간을 소모한다. 냉장 50%면 2시간마다 1시간 준다.
- 배설 주기는 경과 시간이 48의 배수가 되는 경계에 맞춘다. 공간이 없으면 3시간 뒤에 다시 확인한다.
- 의뢰:
  - 목적지 후보와 보상은 최단 노선 거리 합을 쓴다(`minTravelDistance`·`maxTravelDistance`·`rewardPerCellDistance`).
  - 기한(시간) = 최단 거리 × `hoursPerDistance` × `deadlinePercent`(올림) + `deadlineExtraHours`.
  - 지역 불이익 기간은 `durationHours`다.

## UI와 이벤트

- 기간·남은 시간은 `Presentation.PuzzleMapTime`의 "N시간"이다. 지도 노선 라벨, 이동 견적, 의뢰, 유통기한 표시가 같은 표기를 쓴다.
- 이동 확인창은 이동 시간과 도착 시각(`HH:00`)·밤 여부를 보이고, 경로 계획 요약은 총 이동 시간과 도착 시각을 보인다.
- 역 버튼에는 턴·시간 비용을 붙이지 않는다. 휴식 버튼만 "3시간"을 보인다.
- 정산 게이지와 낮·밤 막대는 하루 24시간 기준이며 `HourFraction`으로 부드럽게 움직인다.
- `GameEvents.JourneyChanged`: 출발·도착·중단 때 발행한다. 역 행동 Presenter와 인벤토리 Presenter가 구독해 시설·시장 상태를 다시 그린다.
- 분석 로그는 schemaVersion 8부터 시간 필드(`elapsedHours`·`requestedHours`·`deadlineHours`·`totalHours`)를 쓴다([PLAY_LOG](PLAY_LOG.md)).

## 확인 범위

- 확인한 것: 컴파일 오류 0, 테이블 검증 오류 0, 기초데이터 계약 재생성.
- 하지 않은 것: 플레이, 입력 실험, 화면 캡처, SmokeCheck, 경제 분석 재실행.
- 경제 수치(가격·운임 단가·보상·작업 비용)는 바꾸지 않았다. 다만 개조 비용은 확정 1회당에서 화물 하나당으로 바뀌었다.
- 실시간 배율에서의 밸런스와 체감(이동 대기 길이, 밤 1분)은 검증 전이다.
