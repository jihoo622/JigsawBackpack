# 게임 시간 시스템

## 원본과 소유권

- `PuzzleTimeTableData.json`은 K·시작 시각·일출 시각·일출/야간 길이·일반 휴식 분수의 단일 원본이다. K=28픽셀/시간은 플레이 검증 전 잠정치다.
- `PuzzleRouteTableData.routes[].points`는 고정 지도 좌표의 폴라인 x,y 쌍이다. 왕복은 같은 점의 역순이며 요금용 `distance`·화면 줌과 독립적이다.
- `PuzzleInventoryService.Time`의 `PuzzleTimeManager` 하나가 경과 분을 보관한다. `ElapsedMinutes`가 원본이며 `ElapsedHours`는 소수 시간 조회값이다. `OwnedMinutes`가 물품 보유 시간의 원본이다.
- `PuzzleTradeTableData.deadlineHours`는 기한 설정이다. 시계 생성 시 분으로 변환하고 정확히 기한과 같은 시각의 상환은 허용한다.

## 계산과 날짜

- `소요 분 = ceil(폴라인 구간 길이 합 / pixelsPerHour × 60)`이다. 가중치 변환·코드 기본 소요 시간은 제거했다.
- 시작은 06:00이며 일출은 06:00~24:00, 야간은 00:00~06:00이다. HUD 날짜는 자정에 바뀌고 기한은 시작부터의 경과 분으로 비교한다.
- 이동 확정 전에 시간·자금·모든 화물칸 가치·기존 물품 보유 시간의 범위를 확인한다.
- 실제 가치에는 `(시너지 계산값−기본 가치) × 소요 분 / 60`을 누적한다. 호버 예측도 같은 계산 순서를 사용한다.
- 경과 분과 보유 시간을 확정하고 날짜 변경 부산물을 생성한 뒤 `GameEvents.TimeAdvanced`를 발행한다. 새로 생성한 부산물의 보유 시간은 0이다.

## 시장과 대기

- 야간에는 시장 구매·판매·시장 내 재배치를 모델의 `EvaluateDrop`에서 거부한다. UI도 시장의 `CanvasGroup` 입력을 끄고 흐리게 표시한다.
- 기차 안 재배치·화물칸 선택·역 이동은 야간에도 허용한다.
- 우측 역 메뉴의 휴식 화면에서 `restMinutes`(현재 60분)만큼 시간을 보내거나 야간에 다음 06:00까지 대기한다. 시계·보유 시간과 기한 판정을 진행하며 이동 횟수·요금·이동 시너지 가치·시장 재고를 바꾸지 않는다.

## UI와 이벤트

- 지도 시간 라벨·이동 견적·확인창·호버는 동일한 계산 소요 분을 표시한다. 확인창에는 도착 시각과 야간 시장 휴업 여부도 표시한다.
- HUD의 예측 목적지 버튼은 직접 연결된 도시를 ID 순서로 선택하고 마지막에는 미선택으로 돌아간다. 지도에서 이동할 역을 누를 때도 목적지를 기록하며 도시 도착 후 초기화한다. 미선택 시 미래 가치만 숨긴다.
- `TimeAdvanceInfo`는 `session`·`previousMinutes`·`elapsedMinutes`·`DeltaMinutes`를 제공한다. `DeltaHours`는 소수 시간 조회값이다.
- `TravelPreviewChanged`는 세션 로컬 예측 목적지 변경을 UI에 알린다. 정적 이벤트는 기존 SubsystemRegistration 경로에서 초기화한다.
- 분석 세션 ID·실제 시간 시계는 `TelemetryLog`의 계약을 유지한다. 게임 시간 이벤트를 별도 분석 파일로 중복 기록하지 않는다.

## 재적용과 확인 범위

- `Tools/MyJG/Apply Time Planning`은 표 캐시를 갱신하고 지도 시간 라벨·시장 입력 그룹·Game 씬의 대기/예측 버튼을 연결한다.
- 일반 표 갱신은 `Tools/MyJG/Tables/Reload Tables`를 사용한다. 플레이 중에는 재적용하지 않는다.
- 플레이·입력 실험·화면 캡처는 수행하지 않았다. K·시간 비례 가치 증가·야간 동선과 경제 밸런스는 잠정이다.
