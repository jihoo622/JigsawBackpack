# 개발 과제와 확인 항목

게임 규칙과 기획 미정 사항은 [게임 기획서](<../게임 기획서.md>)를 따른다. 이 문서는 개발 기반의 남은 제약과 사용자 확인 범위만 관리한다. 기획의 임시값을 여기에서 별도 규칙으로 다시 정의하지 않는다.

## 기반 구조

- Preload → Title → Game 진입 흐름의 플레이 확인: 빌드와 에디터(Play From Preload 켬·끔, 씬 직행 도구)에서 Preload를 한 번만 거치는지, 분석 로그 session_start·scene_change 순서, Title 시작·종료, 테이블 오류 시 Preload에서 멈추는지.
- 분석 원본과 테이블은 LogKit Data 전송에 연결했다. 서버의 Telemetry/TelemetryRules 추출·조각 복원·대시보드 처리는 외부 작업이다. 도착·시간·경제·상환은 puzzle_action 변화분과 run_end에 통합하며 같은 사건을 별도 분석 이벤트로 중복 기록하지 않는다.
- 씬 사이 게임 상태 인계와 공용 페이드 씬 로더는 없다. 영구 저장·재개 범위는 기획 결정 후 구현한다.
- 외부 dope-grid는 현재 구현의 의존성이 아니다. 로컬 격자 모델과 사전 배치 View를 사용하며 이전 패키지 검토는 [과거 작업 계획](<Archive/기차 인벤토리 게임 구현 작업 계획.md>)에 보존한다.
- 외부 데이터의 노드 30개·노선 43개(표시 104조각)·시간 라벨·색 그룹을 프리팹에 저장했다. 커밋 전 ProjectValidation에서 테이블은 정상이며 기존 빌드 씬 불일치가 남아 있다. 실제 지도 화면 확인은 사용자 확인 대상이다. 경위는 [MAP](MAP.md) §4.
- 자동 에디터 설정이 열린 씬을 저장할 수 있다. 원격 씬 변경을 반영할 때 메모리의 씬이 이전 참조를 다시 저장하지 않도록 파일과 에디터 상태를 맞춘다.

## 남은 사용자 확인

아래는 플레이 확인 대상이며 수행 완료를 뜻하지 않는다. 테스트·플레이·검증용 입력·캡처는 사용자 요청 시에만 진행한다.

- 렌즈 방문 도시: 현재 도시와 직결되지 않은 과거 방문 도시가 모두 표시되고 미방문·통과만 한 도시는 제외되는지 확인한다. 선택 화물의 적재 칸을 반영한 알려진 최단 경로/예약 경로의 운임·턴, 현재 도시의 0원·0턴, 경로 미확인 시 운임·턴 생략, 여러 도시 스크롤과 기존 소문 탭·지도 핀도 함께 확인한다.

- 행선지 렌즈 소문 도시: 선택 화물과 품목 ID·태그가 맞는 실제 소문이 먼 마을·미계획 목적지·이미 방문한 마을에서도 표시되는지 확인한다. 무관한 소문은 빠지고, 관련 기록이 없으면 기존 빈 상태가 표시되어야 한다. 화물 변경·소문 추가·시간 경과·오래됨 표시·여러 기록 스크롤과 현재/방문 도시 탭도 함께 확인한다.

- 이동 운임의 잔액 표시: 단일 이동·반복 이동·자동 경로의 각 구간에서 보유 자금이 실제 누적 차감된 잔액으로 갱신되는지, 이동 패널이나 지도를 닫기 전에도 반영되는지 확인한다. 확인 취소·이동 실패 시에는 운임이 차감되지 않아야 한다. 개편·구형 UI와 이동 직후 거래·기간 종료 결산도 같은 잔액을 표시해야 한다.

- 좌측 기차·화물칸 바와 우측 역 메뉴·시장·술집·휴식의 여백, 뒤로 가기, 시장 진입 후 드래그·즉시 거래, 술집 첫 소식 재사용과 도착 후 초기화, 휴식 시 시간·기한·야간 상태 갱신.
- 우측 소문 로그의 접기/펼치기·기록 날짜/시각/출처 순서·마지막 기록 스크롤, 접은 상태의 새 기록 유지, 지도 위 휠의 본문 스크롤과 패널 밖 조작.
- 술집 소문 우선순위와 방문 배지: 희귀 후보가 남으면 특산·행동 소문이 나오지 않는지, 모든 희귀 대상이 이미 알려지거나 방문되면 2그룹(특산·행동)이 선택되는지, 희귀가 애초에 없는 경우와 2그룹 한 종류만 있는 경우·후보가 전혀 없는 경우, 같은 마을의 다른 정보 중복 차단, 실제 방문 직후 `?` 배지 소멸과 통과만 한 역의 배지 유지, 수첩·역 요약의 과거 기록 유지를 확인한다.
- 기초데이터 변경 후 표 캐시 갱신과 표시·색·줌·툴팁 반영. 제작 치수 변경은 제작 메뉴로 씬·프리팹에 다시 적용한다.
- 기초데이터의 남은 표시 매핑·원본 프리팹 스타일·술집 정책은 [후보 목록](BASIC_DATA_CANDIDATES.md)을 따른다. 공통 게임 UI 배치·화면 기준·주요 버튼 테마는 `ui.layout.*`로 관리한다.
- 지하철 노선도에서 30개 역의 이름·생산 5개 지역·수도권의 6색 노선과 회색 일반 길·연결역 링·시간 숫자가 구분되고, 실제 인접 목적지만 이동되는지.
- 이동 1턴·노선 거리 운임과 가치 누적·보유 시간·견적·표시가 일치하는지. 이동 연출 뒤 도착 때 턴이 1 오르는지. 역 시설 진입이 시간을 쓰지 않는지, 휴식이 고른 턴(1~4)만큼 진행되는지, 작업장 확정이 1턴을 쓰고 바로 수령 가능한지.
- 06:00 시작, 00:00~06:00 밤의 시장 진입 차단과 아침 대기 경계, 밤 도착 견적이 맞는지. 밤 직전에 들어간 시장이 밤이 되어도 그 방문 동안 거래되는지. 시장에 들어가지 않으면 모델에서도 거래·시장 재배치를 막고 기차 조작은 허용하는지. 일시정지 메뉴에서 시계가 멈추고, 화물을 끄는 동안 정시 처리가 미뤄졌다가 놓은 뒤 이어지는지.
- 턴제(1턴 = 6시간, 하루 4턴)·모든 이동 1턴·목표 잔액 1,500(14일 결산)·금융마을 출발·화차 120~450·시작 자금 200과 매 턴 시너지 정산의 밸런스와 체감은 플레이 확인이 필요하다. 장거리 직통의 시간 비용이 사라졌다. 경제 수치는 바꾸지 않았다(6시간 미만 규칙만 1턴으로 올림).
- 시뮬레이션의 승리 경로가 헤일하임↔카르포트 왕복 하나에 집중된다. 플레이어가 이 왕복을 찾는지, 노르노바·헤일포드 등 다른 출발에서도 길이 있는지 확인이 필요하다.
- 6시간 주기 직전·정각·직후, 여러 주기 경과, 이동 중·휴식, 구매·재배치·도착 후 주기 유지와 예측 정산 횟수·실제 가치가 일치하는지.
- 동물 시너지의 여러 자정 일괄 진행과 순차 진행, 객차별·동물별 배설, 같은 쌍 재결합과 시간 경과 후 초기화, 만석에서 완료 직전 대기 후 공간 확보 시 3시간 뒤 재시도, 출산·배설의 부분 생성 없음, 미리보기와 실제 정산의 일치를 확인한다. 공간이 없는 송아지가 21시간에서 대기해도 이동·휴식이 진행되고 자리 확보 후 3시간 뒤 성체가 되는지, 냉장 50%가 2시간마다 1시간 소모하는지도 함께 확인한다.
- 기차 툴팁의 번식·성장 진행도가 실제 경과와 일치하고 짝이 없는 소는 0으로 보이는지, 시장·도축·개조 보드에는 진행도가 없는지, 공간 부족 때 빨간 표시와 아이콘이 뜨고 가치 알림과 독립으로 읽히는지, 이동·휴식 후 열린 툴팁과 아이콘이 갱신되는지 확인한다.
- 인접 조합: 재료별 결과와 가격(물고기 50·소고기 62·고기 포장 46)이 맞고 절인 결과가 다시 절여지지 않는지, 소금과 식품이 한 번에 한 쌍에만 묶이는지, 시간 경과 전 분리·재접촉은 진행도를 유지하고 떨어진 채로 시간이 흐르면 초기화되는지, 만료와 같은 시각에는 부패한 식품이 결과로 바뀌지 않는지, 긴 이동과 미리보기가 같은 12시간 경계를 쓰는지, 입력 양쪽에 같은 설명·진행도가 뜨고 소금의 냉장 보존 효과와 설명이 그대로인지 확인한다.
- 냉장 화살표가 접촉한 냉장원→음식 방향으로만 뜨고 분리·재배치·신선도 만료 후 사라지는지, 한 쌍이 여러 칸에서 접해도 화살표 하나가 있는지, 세 번째 냉장원은 소모율이 이미 0이라 표시되지 않는지, 드래그 중에는 양쪽 화살표가 숨는지, 시장·도축·개조 보드에는 없는지, 가치 화살표와 겹쳐도 방향과 레인이 구분되는지 확인한다.
- 줌 시 이름·마커·시간·선 굵기가 과도하게 커지지 않고, 라벨 우선순위와 겹침 회피가 읽기 편한지.
- 역 클릭 시 확인·취소가 표시되고 취소·Esc 시 도시·자금·시간이 유지되는지. 확인 후 기차 이동·진행률·도착 표시가 보이고, 중복 클릭과 지도 조작을 차단하며 이동을 한 번만 확정하는지. 확인 후 조건 변경·패널 닫힘·씬 재진입 때 연출과 입력이 정상 정리되는지.
- 자금 부족·연결 없음·계산 범위 초과 시 마을·시간·화물·시장·자금이 보존되는지.
- 시간을 쓰지 않는 거래 중에는 시장 재고가 보존되고, 이동·휴식·작업으로 턴이 지나면 모든 시장이 재입고되는지.
- 복수 태그의 흔함 우선순위, 수도권 물가, 구매·판매 반올림과 음수 가치 등 경계 상황이 의도와 맞는지.
- Ctrl+클릭의 빈자리·회전 탐색과 자금·공간 부족 처리, 지도·완료 패널의 입력 차단이 맞는지.
- 수도권 툴팁과 실제 결제 일치, 판매 후 재구매의 실제 가치 기준, 처분 화물 소멸, 기본/실제 가치·현재/가능 효과 구분과 미방문 물가 숨김.
- 클리어 비용 경계와 기한 초과 패배 결과 패널, 완료 후 추가 조작 차단, 재시작·종료와 도메인 리로드 해제 상태의 재진입이 맞는지.
- LogKit 수신 서버·빌드 환경변수와 실제 분석 값이 맞는지. 파일 형식·세션 계약 검증만으로 게임 사건의 값까지 확인한 것으로 취급하지 않는다.

데이터 계약은 [TABLES](TABLES.md), 로그 운영은 [TELEMETRY](TELEMETRY.md), 이벤트 필드는 [PLAY_LOG](PLAY_LOG.md)를 참고한다.

- 피벗 후 확인: 14일이 끝나는 행동 직후 자동 결산·결과 패널이 뜨는지(목표 미만 패배), 노선 밝기(달린 노선 밝게·안 달린 노선 짙은 회색)·외곽선 두께, 역마다 다른 화차가 진열·구매·보드 모양대로 붙는지, 의뢰 숙련 태그·경험치 표시와 지급, 전장의 안개(고지도 층의 농도·반지름, 들른 역 이웃만 보임·핵심 도시/소문/의뢰 역 위치만·의뢰 최단 경로 노선 표시와 경유역 숨김·모르는 길 경로 계획 거부·검색 제한) 화면 확인.
- 화차 고유 효과(유물)와 경제 시뮬레이터 전략(결산 잔액 극대화) 재설계가 남았다.

### 통합 수첩의 소문·의뢰 표시

[현재 구현 범위](CURRENT_STATE.md#통합-수첩의-소문의뢰-표시)에 대한 미확인 항목이다. Unity 컴파일·테스트·플레이·입력·캡처는 수행하지 않았으며, 아래 시나리오는 사용자가 확인하거나 검증을 별도로 요청할 때 진행한다.

- [ ] 새 게임의 소문·의뢰 탭에 기존 빈 상태가 표시되고 프리팹 예시 기록이나 수락하지 않은 게시판 제안이 나타나지 않는다.
- [ ] 술집에서 소문을 들은 뒤 실제 들은 시각·마을·내용이 표시된다. 다른 소문을 추가로 듣거나 대상 마을을 방문한 뒤에도 이전 기록이 남는다.
- [ ] 소문을 확인한 출처 마을에서는 창 재열기·재방문·시간 경과·구형/개편 UI 전환 뒤에도 버튼이 비활성이고 같은 결과가 표시된다. 소식 없음도 한 번으로 처리하며, 아직 확인하지 않은 마을과 새 게임에서는 다시 확인할 수 있다. 반복 조작으로 수첩 기록이 중복 추가되지 않는다.
- [ ] 의뢰 수락 후 화물·목적지·기한·보상이 표시되고 시간 경과와 완료·실패 상태가 반영되며 끝난 의뢰도 이력에 남는다.
- [ ] 텍스트 탭 사이 전환, 지도·상성표를 거친 복귀, 창을 닫은 동안 기록이 생긴 뒤 재열기에서 본문과 최신 기록이 표시된다.
- [ ] 퀵 툴바의 마지막 탭 재열기, 역 상단 요약, 엔티티 링크가 같은 수첩의 해당 탭으로 연결된다. 이미 열린 창도 앞으로 올라오며 구형 수첩이 함께 열리지 않는다.
