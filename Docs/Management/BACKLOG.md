# 개발 과제와 확인 항목

게임 규칙과 기획 미정 사항은 [게임 기획서](<../게임 기획서.md>)를 따른다. 이 문서는 개발 기반의 남은 제약과 사용자 확인 범위만 관리한다. 기획의 임시값을 여기에서 별도 규칙으로 다시 정의하지 않는다.

## 기반 구조

- 빌드 활성 씬은 Game 하나지만 `FlowTableData`에는 Preload·Title·Game 경로가 남아 있다. ProjectValidation이 Preload·Title의 빌드 목록 누락을 보고하며 두 씬의 진입·전환 흐름도 미연결이다.
- 분석 원본과 테이블은 LogKit Data 전송에 연결했다. 서버의 Telemetry/TelemetryRules 추출·조각 복원·대시보드 처리는 외부 작업이다. 도착·시간·경제·상환은 puzzle_action 변화분과 run_end에 통합하며 같은 사건을 별도 분석 이벤트로 중복 기록하지 않는다.
- 씬 사이 게임 상태 인계와 공용 페이드 씬 로더는 없다. 영구 저장·재개 범위는 기획 결정 후 구현한다.
- 외부 dope-grid는 현재 구현의 의존성이 아니다. 로컬 격자 모델과 사전 배치 View를 사용하며 이전 패키지 검토는 [과거 작업 계획](<Archive/기차 인벤토리 게임 구현 작업 계획.md>)에 보존한다.
- 외부 데이터의 노드 30개·노선 43개(표시 104조각)·시간 라벨·색 그룹을 프리팹에 저장했다. 커밋 전 ProjectValidation에서 테이블은 정상이며 기존 빌드 씬 불일치가 남아 있다. 실제 지도 화면 확인은 사용자 확인 대상이다. 경위는 [MAP](MAP.md) §4.
- 자동 에디터 설정이 열린 씬을 저장할 수 있다. 원격 씬 변경을 반영할 때 메모리의 씬이 이전 참조를 다시 저장하지 않도록 파일과 에디터 상태를 맞춘다.

## 남은 사용자 확인

아래는 플레이 확인 대상이며 수행 완료를 뜻하지 않는다. 테스트·플레이·검증용 입력·캡처는 사용자 요청 시에만 진행한다.

- 좌측 기차·화물칸 바와 우측 역 메뉴·시장·술집·휴식의 여백, 뒤로 가기, 시장 진입 후 드래그·즉시 거래, 술집 첫 소식 재사용과 도착 후 초기화, 휴식 시 시간·기한·야간 상태 갱신.
- 우측 소문 로그의 접기/펼치기·기록 날짜/시각/출처 순서·마지막 기록 스크롤, 접은 상태의 새 기록 유지, 지도 위 휠의 본문 스크롤과 패널 밖 조작.
- 기초데이터 변경 후 표 캐시 갱신과 표시·색·줌·툴팁 반영. 제작 치수 변경은 제작 메뉴로 씬·프리팹에 다시 적용한다.
- 기초데이터의 남은 표시 순위·매핑·원본 프리팹 스타일·부산물/술집 정책은 [후보 목록](BASIC_DATA_CANDIDATES.md)을 따른다. 공통 게임 UI 배치·화면 기준·주요 버튼 테마는 `ui.layout.*`로 옮겼으며 전체 직렬화 스타일이 이미 테이블화된 것으로 취급하지 않는다.
- 지하철 노선도에서 30개 역의 이름·생산 5개 지역·수도권의 6색 노선과 회색 일반 길·연결역 링·시간 숫자가 구분되고, 실제 인접 목적지만 이동되는지.
- 폴라인 길이/K의 분 단위 소요 시간과 가치 누적·보유 시간·견적·표시가 일치하는지. 요금용 거리·적재 단가는 시간과 분리해 확인한다.
- 06:00 시작, 00:00~06:00 야간의 시장 차단과 아침 대기 경계, 야간 도착 견적이 맞는지. 시장 거래·시장 재배치는 모델에서도 막고 기차 조작은 허용하는지.
- K=28·상환액 1,500·시작 자금 200·14일 기한과 6시간 주기 시너지 정산의 밸런스는 플레이 확인이 필요하다.
- 6시간 직전·정각·직후, 여러 주기 경과, 이동+휴식 분할, 구매·재배치·도착 후 주기 유지와 예측 정산 횟수·실제 가치가 일치하는지.
- 줌 시 이름·마커·시간·선 굵기가 과도하게 커지지 않고, 라벨 우선순위와 겹침 회피가 읽기 편한지.
- 역 클릭 시 확인·취소가 표시되고 취소·Esc 시 도시·자금·시간이 유지되는지. 확인 후 기차 이동·진행률·도착 표시가 보이고, 중복 클릭과 지도 조작을 차단하며 이동을 한 번만 확정하는지. 확인 후 조건 변경·패널 닫힘·씬 재진입 때 연출과 입력이 정상 정리되는지.
- 자금 부족·연결 없음·계산 범위 초과 시 마을·시간·화물·시장·자금이 보존되는지.
- 출발 시장만 재생성되고 도착 시장과 기차의 인스턴스·배치·회전·실제 가치가 유지되는지.
- 복수 태그의 흔함 우선순위, 수도권 물가, 구매·판매 반올림과 음수 가치 등 경계 상황이 의도와 맞는지.
- Ctrl+클릭의 빈자리·회전 탐색과 자금·공간 부족 처리, 지도·완료 패널의 입력 차단이 맞는지.
- 수도권 툴팁과 실제 결제 일치, 판매 후 재구매의 기본가 기준, 기본/실제 가치·현재/가능 효과 구분과 미방문 물가 숨김.
- 클리어 비용 경계와 기한 초과 패배 결과 패널, 완료 후 추가 조작 차단, 재시작·종료와 도메인 리로드 해제 상태의 재진입이 맞는지.
- LogKit 수신 서버·빌드 환경변수와 실제 분석 값이 맞는지. 파일 형식·세션 계약 검증만으로 게임 사건의 값까지 확인한 것으로 취급하지 않는다.

데이터 계약은 [TABLES](TABLES.md), 로그 운영은 [TELEMETRY](TELEMETRY.md), 이벤트 필드는 [PLAY_LOG](PLAY_LOG.md)를 참고한다.
