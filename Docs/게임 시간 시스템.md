# 게임 시간 시스템 연결 계약

`PuzzleInventoryService.Time`이 세션별 `PuzzleTimeManager`를 소유한다. 시간은 정수 시간(hour)으로만 저장·계산한다. 현실 시간과 TelemetryLog.GameTime은 별개다. 시작은 Day 0의 0시이며 거래·지도 열람·일시정지 중에는 자동 진행하지 않는다.

## 노선 담당

`PuzzleRouteData.travelTimeWeight`에 1 이상의 정수를 설정한다. 시간 가중치와 비용용 distance는 별개다. 가중치 1 = 8시간, 3 = 24시간, 5 = 40시간, 6 = 48시간이다. 상한은 6으로 제한하지 않는다. 테마 경계는 시간 관리자가 판단하지 않는다.

기존 노선 JSON에서 생략하면 임시로 1을 사용한다. 아직 거리별 밸런스를 배정하지 않았으며 도시·상품 배치는 변경하지 않았다. 예:

```json
{ "fromCityId": "city.a", "toCityId": "city.j", "cost": 6, "distance": 4, "highSpeed": false, "travelTimeWeight": 5 }
```

기존 `Travel(toCityId)`는 성공한 이동마다 자동으로 시간을 한 번 진행한다. 실패한 이동은 시간이 흐르지 않는다. 목적지·시장·자금을 먼저 확정하고, 경과 시간·기한 패배를 처리한 뒤 `TimeAdvanced`, `CityArrived` 순으로 발행한다. 기존 화물 인접 시너지는 이동당 한 번 적용하는 기존 규칙을 유지한다.

새 이동 시스템이 기존 Travel을 사용하지 않는다면 이동 확정 후 `session.AdvanceTravelTime(weight)`를 한 번 호출한다. 기존 Travel 뒤에 추가 호출하면 시간이 중복되므로 호출하지 않는다. 대기·작업 등은 `session.AdvanceHours(hours)`로 진행한다. 종료된 세션이나 초기화 전에는 시간을 진행하지 않는다. 0시간은 이벤트 없는 무변화, 음수·오버플로는 예외로 차단한다.

## 물건 담당

`GameEvents.TimeAdvanced`를 OnEnable에서 구독하고 OnDisable에서 해제한다. `info.session`으로 해당 세션의 이벤트인지 확인한다. `info.previousHours`, `info.elapsedHours`, `info.DeltaHours`는 모두 정수 시간이다. 시간당 손상·부패 규칙은 물건 시스템이 소유한다. 이벤트를 직접 발행해도 시계는 진행하지 않으므로 행동 시스템은 세션의 시간 진행 API를 사용해야 한다.

```csharp
void OnTimeAdvanced(GameEvents.TimeAdvanceInfo _info)
{
    if (_info.session != session)
    {
        return;
    }
    // 물건 담당: _info.DeltaHours만큼 상태 갱신
}
```

## 조회·상환

- `Time.ElapsedHours`, `Day`, `Hour`: 누적 시간, 경과 일수, 당일 시각(0~23).
- `Time.RemainingHours`, `HasDeadline`: 남은 시간. 무기한이면 long.MaxValue이므로 HasDeadline을 먼저 확인한다.
- `PuzzleTimeManager.TravelHours(weight)`: 가중치를 소요 시간으로 변환.
- `Time.ArrivalAt(durationHours)`: 현재 기준 예상 도착 누적 시간. 시계를 변경하지 않는다.
- `Time.CanArriveBeforeDeadline(durationHours)`: 기한 내 도착 가능 여부. 기한 초과 이동 자체를 차단하지 않는다.

`PuzzleTradeTableData.json`의 `deadlineHours`는 336(14일), 0이면 무기한이다. `debtCityId`는 현재 빈 문자열로 상환 장소를 제한하지 않는다. 도시 ID를 지정하면 그 도시에서만 상환 가능하다. `gameClearCost`는 기존 상환 금액이다.

기한 336시간에 상환하는 것은 허용하고 337시간부터는 자금·도시와 무관하게 패배한다. 상환 버튼은 자금·도시·기한을 함께 확인하고 조기 상환은 즉시 승리한다. 도착만으로 자동 납부하지 않는다. 무기한은 시간 제한만 해제하며 별도 무한 모드 승패 규칙은 아직 없다. 기존 이동 횟수 기반 빚 일정은 계속 비활성이다.

## UI

메인 UI의 `City Navigation/Game Time`은 Day 0 · 00:00 형식으로 경과 일수와 당일 시각을 표시한다. 가중치 1 이동 1회·2회는 Day 0, 3회는 Day 1이다. 지도 호버는 노선의 실제 소요 시간을 표시한다. 날짜 표기로 바꿀 때는 `Presentation.PuzzleTime`을 교체하면 된다.
