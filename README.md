# JigsawBackpack

Unity 6.3 LTS(6000.3.22f1) URP 기반의 기차 화물 거래 게임. 작업 규칙은 [AGENTS.md](AGENTS.md), 문서 진입점은 [Docs/README.md](Docs/README.md)다.

게임 기획서는 [노션](https://app.notion.com/p/41400f902d2281849db4c5e61b7f5ac3)과 로컬을 함께 관리한다. 작업 시작 시 노션 변경을 로컬로 가져오고, 여기서 기획을 바꾸면 노션에도 반영한다. 현재 연결은 404이며 로컬의 잠정 규칙·UI 정합성 변경이 미반영 상태다. [동기화 규칙](Docs/Management/NOTION_SYNC.md)과 마지막 공통 기준을 먼저 확인한다.

## 현재 상태 요약

상세 구현 현황과 기획 대비 차이는 [현재 구현 상태](Docs/Management/CURRENT_STATE.md)를 본다.

- 기본요금은 모든 노선 6이다. Map Editor의 공통 설정에서 표시 선 길이 비례 요금 거리를 정수로 일괄 계산할 수 있다. 환산 기준은 노선 테이블의 fareDistancePixelsPerUnit(초기 100)이다.
- Game 씬에서 바로 진입한다. 상단 정보·좌측 기차/화물칸·우측 역 행동·하단 상태 안내로 배치했다. 우측에서 시장(7×6)·술집 소식·휴식·다른 역 이동을 선택한다. `ui.layout.*`와 `Tools/MyJG/Apply UI Overhaul`이 공통 배치 원본이다([UI 배치](Docs/Management/UI_LAYOUT.md)).
- seed 20265146의 지리·이름·고정 좌표를 사용한다. 원본 43개 왕복 철도에 카르포트↔포르베르 공업 연결을 추가해 총 44개다. 생산 마을 21개·수도권 5개·일반 마을 4개이며 금융마을을 상환 장소로 제한한다. 시작은 `city.industry.ironworks`(에른아 공업역)이고, 금융마을까지 최단 이동 합은 K=28 잠정치로 39시간 53분이다.
- 지도 프리팹에도 외부 데이터의 역 30개·철도 44개·시간 라벨을 저장했다. `Tools/MyJG/Apply Rail Map Layout (seed 20265146)`으로 다시 적용할 수 있다([MAP](Docs/Management/MAP.md) §4).
- `Tools/MyJG/Map Editor`의 내부 지도 캔버스에서 역·노선·지형을 보고 선택/드래그·확대/축소하며 편집한다. 이름·지역·시장 설정·요금·거리·표시/시간 경유점은 오른쪽 속성과 연결되고 테이블·레이아웃·프리팹에 함께 저장한다([사용법](Docs/Management/MAP.md)). 기존 `Edit Rail Routes`는 표시 경유점 전용이다. 지도 지명은 지역 우선순위·핵심 역 가중치로 축소 시 표시 대상을 줄이고 확대 시 일반 역명을 추가한다.
- 지도에 지형 배경·휠 확대/축소·드래그 이동·전체 보기/현재 위치 버튼을 연결했다. 현재 역은 금색 배지·링으로 강조한다. UI 여백과 연결 재적용은 `Tools/MyJG/Apply Map Presentation`이다.
- 지도 지명은 직전 배치 방향을 우선 유지하고 원래 역까지 안내선으로 연결한다. 이름·배지·실제 역 테두리·안내선 간 충돌을 피하며, 빈 공간이 없으면 겹쳐 강제 표시하지 않는다. 축소 시 역의 입력 영역도 실제 표식으로 제한한다. 시간 표시는 현재 역의 직결 노선으로 한정하며 85% 미만에서 숨긴다. 변경 후 플레이 확인은 수행하지 않았다.
- 역 클릭은 확인·취소 창을 거친다. 확인 시 기차 이동 연출 완료 후 이동을 확정하고, 도착 표시 후 지도를 닫는다. 이동 연출 시간은 거래 테이블, UI 재적용은 `Tools/MyJG/Apply Map Travel UI`다. 플레이 확인은 아직 수행하지 않았다.
- 이동 비용은 기본요금 + 거리 요금 + 전체 기차 적재 요금이다. 이동 중 지난 6시간 경계마다 각 화물칸의 시너지 변화량을 실제 가치에 누적하고 출발 시장만 새 인스턴스로 재생성한다.
- 시장 재고는 마을 특산 3개·지역 특산 1개·랜덤 2개이며 수도권은 집산·수입품을 사용한다. 시너지와 거래는 복수 태그를 공유하고 흔함을 귀함보다 우선한다. 구매는 기본 가치·도시 배율, 판매는 누적 실제 가치·도시 배율에 지역 물가를 곱한다. 귀함 150/120, 수도권 물가 125%다. 클리어 비용 지불로 승리하고 완료 패널에서 재시작·종료한다. 옛 이동 횟수 기반 빚 일정은 제거했다. 14일 기한·조기 상환 코드를 유지하고, `debtCityId`를 금융마을으로 정해 그 도시에서만 상환할 수 있다.
- 시간은 고정 폴라인 길이 ÷ K(잠정 28픽셀/시간)를 분 단위로 올림한다. `PuzzleTimeTableData`가 이동/시각 설정의 원본이다. 시너지는 `PuzzleSynergyTableData.activationIntervalHours`의 6시간마다 정산하고 이동·휴식·아침 대기에 공통 적용한다. 06:00 시작, 야간 00:00~06:00에는 시장을 차단하며 아침 대기 버튼을 제공한다. 하단 예측 선택 UI는 제거했으며, 호버 미래 가치는 지도에서 선택한 목적지를 사용한다. `Tools/MyJG/Apply Time Planning`으로 표 캐시·지도 시간·HUD 연결을 갱신한다.
- 화물 정의에 기본 가치를 통합하고 시장 재고는 7개 프로필을 공유한다. 기초데이터 필수 키 계약 생성 메뉴를 제공한다.
- 거래 견적은 모델/툴팁이 공유한다. 툴팁은 기본·실제 가치와 현재 적용 효과·일반 효과·가능 가치 시너지를 나눠 표시한다. 정산 주기는 가치 시너지에 표시한다. 기차 합계는 누적 실제 가치를 사용한다. 패배도 결과 패널을 열며 사과는 일반 재고에 포함된다. 툴팁 행 제작은 `Tools/MyJG/Apply Tooltip Trade Details`다.
- 술집 소문은 우측 접이식 로그에 게임 날짜·시각 - 들은 마을 - 내용 순으로 쌓인다. 지도는 닫았다 열어도 확대 배율·이동 위치를 유지한다. 로그는 지도와 역 화면이 공유하고 새 기록은 마지막으로 스크롤한다. 소문 대상인 미방문 마을은 지도에 `?`를 붙이고 호버에 미확인 소문을 표시한다. 제작 메뉴는 `Tools/MyJG/Apply Rumor Log Panel`이다.
- 수치·재고·노선은 `Assets/Resources/Tables/*.json`이 원본이다. 공통 표시·UI 조정값은 **기초데이터**(`BasicDataTableData`)에 모았다([편집 계약](Docs/Management/BASIC_DATA.md)). 표기·색은 `Presentation`, 상태는 씬 로컬 `PuzzleInventoryService`, UI는 사전 배치한 View와 Presenter가 담당한다.
- 다르폴에서 3×3 도축대를 이용할 수 있다. 대상 화물과 작업 시간은 `PuzzleCityActionTableData`가 정하고, 도축대와 버튼은 Game 씬에 연결했다.
- 도축은 무료이고 냉장 개조는 선택 모드 확인당 150원이다. 표 비용은 작업대 확인 버튼에 표시하고, 잔액이 부족하면 작업대에 사유를 표시하고 확인을 막는다.
- 에른아에서 기계 프레임을 냉장 프레임으로 개조한다. 냉장 프레임은 같은 객차에서 상하좌우로 맞닿은 음식의 유통기한 소모율을 개당 50% 낮춘다. 합계가 100% 이상이면 소모가 멈춘다. 신선도 %는 음식별 경과 6시간마다 반영하고, 유통기한이 끝나면 식품 폐기물로 바뀐다. 기차 객차에서는 냉장이 실제로 적용된 관계만 냉장원에서 음식으로 향하는 녹색 화살표로 보인다.
- 송아지는 2×1, 기본 가치 40원이다. 시작 객차에는 없으며 번식으로만 얻는다. 시장 재고에서 제외되며 애기 태그가 있는 동안 도축할 수 없다. 기존 소와 같은 배설물 규칙을 따르며, 48시간 후 같은 객차에서 성체가 된다. 성체 자리가 없으면 성장만 마지막 1시간 직전에서 대기하고 이동·휴식은 막히지 않으며, 자리 확보 후 1시간이 더 지나면 성체가 된다.
- 동물은 주기마다 자기 객차의 빈자리에 똥을 만든다. 똥은 인접 화물에 −50%, 동물은 인접 `Cargo`에 −10%를 적용한다. 같은 객차에서 상하좌우로 맞닿은 성체 소 한 쌍은 48시간 후 송아지 1마리를 낳는다. 시간 경과 전 재결합은 진행도를 보존한다. 산출물이 안 들어가면 그 동물·쌍만 완료 1시간 직전에서 대기하고 부분 생성은 하지 않는다.
- 기차와 시장의 동물 툴팁은 테이블에서 읽은 객차 번식·성장·배설 조건을 표시한다. 기차 툴팁은 그 설명 아래에 현재의 진행도와 공간 부족 여부를 덧붙이고, 시장·도축·개조 보드에는 진행도를 표시하지 않는다.

## 중요한 제약

- 분석 로그는 schemaVersion 3다. 원본 행과 적용 테이블을 모두 LogKit Data로 전송하고 로컬 `Telemetry`에도 보관한다. 집계는 외부에서 수행한다. 서버 추출·테이블 조각 복원은 [로그 계약](Docs/Management/PLAY_LOG.md)을 따른다.

- `FlowTableData`에는 Preload·Title·Game이 있지만 빌드는 Game만 활성이다. ProjectValidation의 Preload·Title 빌드 목록 누락이 남아 있고 진입·전환 흐름도 미연결이다.
- 테스트·플레이·입력 실험·캡처는 사용자 요청 시에만 실행한다. 임시 지역 맵·시간 소비·거래 경계·클리어 흐름의 남은 사용자 확인은 BACKLOG를 본다.
- 번식·배설 진행과 공간 부족 대기는 현재 판의 씬 로컬 상태에서만 보관한다. 툴팁 진행도와 공간 부족 알림은 그 상태를 그대로 읽으며, 시간 진행은 객차·상태 사본에서 흘러 미리보기가 원본을 바꾸지 않는다. 배설·성장·출산의 플레이 확인은 [BACKLOG](Docs/Management/BACKLOG.md)에 남겼다.
- 컴파일과 씬 변경은 Unity CLI를 사용한다. 자동 에디터 설정이 열린 씬을 재저장할 수 있으므로 원격 씬을 병합한 후 메모리의 씬과 파일의 참조가 일치하는지 주의한다.
- asmdef·namespace 없이 새 Input System, `PanelBase`, `GameEvents`, 정적 상태 초기화 규약을 따른다. Enter Play Mode는 도메인 리로드 해제, Active Input Handling은 Both다.
- LogKit 패키지는 v0.7.0이다. 콘솔 자동 수집과 분석 Data 전송을 함께 사용한다. 빌드 환경변수·로컬 우회 설정은 TELEMETRY를 본다. 서버 주소·키는 저장소에 넣지 않는다.
